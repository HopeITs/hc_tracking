# قصة المستخدم · Public Relations (موظف جمع التمويل)

> **المصطلحات عند فريق الـ PR:** الـ Proposal هو «المشروع»، وله ممول أساسي واحد وتقرير ختامي واحد.
> أما «المشروع» عند باقي المؤسسة فهو **برنامج × محافظة**.
> العلامة ⏳ تعني جزءاً مخططاً في Wave 3 ولم يُنفَّذ بعد.

## من أنا وماذا أريد
أنا موظف جمع التمويل. أكتب طلبات التمويل وأتابعها حتى يوافق الممول أو يرفض، ثم أتابع التنفيذ حتى التقرير الختامي.

## أين أبدأ
1. أسجّل الدخول بحساب HR، فتفتح الـ **Desk**: لوحة Tasks، ولوحة To-do، والإشعارات.
2. من الـ Sidebar أفتح **Funding & Finance → Proposals**، ثم أضغط **New proposal**.

## السيناريو خطوة بخطوة

### 1. إنشاء الـ Proposal
أملأ النموذج بهذا الترتيب:

| الحقل | ملاحظات |
|---|---|
| الاسم | اسم المشروع كما سيُقدَّم للممول. |
| الرقم الداخلي | يُولَّد تلقائياً عند الحفظ بصيغة `HC-YYYY-NNN`. |
| **الممول (Donor)** | هو دائماً **الممول الأساسي**. إذا لم يكن في القائمة أضغط «إضافة ممول»، فيصبح «طلب ممول معلّق». **لا يُحفظ الـ Proposal** حتى يوافق عليه المدير العام. |
| ⏳ هل يوجد ممول وسيط؟ | نعم / لا. عند «نعم» أختار الممول الوسيط. |
| **صفوف المواقع (Locations)** | صف لكل محافظة + برنامج: المحافظة (إلزامية)، والبرنامج، ومسؤول التقرير، والمراكز. حتى الاعتماد كلها اختيارية ما عدا المحافظة. أعلّم «جديد» إذا كان البرنامج أو المركز غير موجود بعد. |
| الـ Concept note | نص أو ملف. |
| التواريخ المخططة | البداية والنهاية. |
| مرحلة البداية | **Concept note**، أو **Proposal draft** مع كتابة سبب تخطي الـ Concept note. |
| الملاحظات | آخر النموذج. |

### 2. مرحلة الـ Concept note
- `concept note` → **إرسال للمراجعة**. الشروط: صف موقع واحد على الأقل، وممول، وتواريخ مخططة.
- أختار المراجعين: مدير المتابعة والتقييم، والمالية، ومدير جمع التمويل، والمدير العام. تصلهم مهمة مراجعة.
- إذا أُعيدت لي بسبب، أعدّل وأرسل من جديد.
- بعد الموافقة الداخلية: `concept note submitted`، أي أُرسلت للممول.
- **قبِل الممول:** أنقلها إلى `proposal draft`. **رفض:** أنقلها إلى `rejected` مع سبب (10 أحرف على الأقل) وتاريخ.

### 3. مرحلة الـ Proposal
- أكمل الخطة: الـ Logframe مع الـ MEAL، والـ Targets، والـ Milestones، ومهام الأقسام (Media، Finance).
- المالية تُدخل **الميزانية والعملة**، وعدد المستفيدين المستهدف لكل موقع.
- `proposal draft` → `proposal review` → `submitted`.
- بعد الإرسال للممول أسجّل **Negotiation notes** إن وُجدت (نص وملف): أي تغيير طلبه الممول.
- أقدر أضع الطلب **On hold** مع تاريخ تذكير إذا تأخر رد الممول.
- إذا طلب الممول إعادة التقديم أرجعه إلى `proposal draft`.

### 4. بعد موافقة الممول
- **الاعتماد يعمله مدير المشاريع وجمع التمويل** (PR Manager)، وليس أنا. ⏳ اليوم يقدر GM وFinancial أيضاً.
- قبل الاعتماد يجب أن يكون كل صف موقع كاملاً: برنامج، ومسؤول، ومركز أو «جديد». ولا يبقى طلب برنامج معلّقاً.
- عند الاعتماد ينشئ النظام المشاريع (برنامج × محافظة) تلقائياً ويربطها.

### 5. أثناء التنفيذ
- أتابع الـ **Funding agreement** والدفعات مع المالية.
- **التمديد:** نفس الـ Proposal، ونفس الرقم، ونفس المشروع. يسجّله الـ PR Manager.
- **الإغلاق:** أرفع التقرير الختامي، ويقبله الـ PR Manager، فيصبح الـ Proposal `completed`.

## الإشعارات التي تصلني
- تغيّر حالة الـ Proposal، ورأي كل مراجع.
- موافقة المدير العام على الممول الجديد أو رفضه.
- تذكير «On hold» عند موعده.
- المهام المسندة لي.

## ما لا أستطيعه
- اعتماد الـ Proposal (`approved`).
- اعتماد ممول جديد.
- رؤية مبالغ لا تسمح بها صلاحياتي.
- تصحيح حالة نهائية (`rejected` أو `completed`).

## متى تنتهي مهمتي
عندما يصبح الـ Proposal `completed` بعد قبول التقرير الختامي، أو `rejected` مع السبب.
