# Handoff · T14 · MEAL alert: program without a logframe

Branch: `lifecycle-tasks-youssef` (one-branch rule) · Owner: Youssef · Date: 2026-10-19 · Status: done

## Definition
A program has **no framework** when no `results` row has `program_id = X` and `proposal_id IS NULL` (`Result::programFramework()`, contracts §11.2). A program with only proposal frameworks still has none.

## Delivered contracts (exactly as on the branch)
```php
final class App\Notifications\Alerts\LogframeGapAlert {
    public const Rule = 'logframe_missing';
    public const Stage = 'logframe';
    /** @param list<int> $programIds  @return int notifications sent */
    public function notify(array $programIds): int;
}

final class App\Jobs\CheckProgramLogframe implements ShouldQueue {
    /** @param list<int> $programIds */
    public function __construct(public array $programIds);
}

// App\Models\Program
/** @return list<int> ids of the programs this sync newly inserted */
public static function syncFromHr(): array;   // was void; still silent (withoutRecording, notifies nothing)
```
- **Ledger:** rule `logframe_missing`, subject `program:{id}`, stage `logframe`, one row per recipient. Each `notify()` first **releases** the ledger of every given program that now has a framework, so a later deletion alerts again.
- **Triggers:**
  1. `SyncProgramsFromHr` middleware → `CheckProgramLogframe::dispatch($newProgramIds)` (only ids `syncFromHr()` newly inserted). Seeders and commands that call `syncFromHr()` directly never notify.
  2. `SaveProject` → `CheckProgramLogframe::dispatch([$program_id])->afterCommit()` on create or program change. No project observer.
  3. `DataGapScanner` (daily, working days only) → `notify()` with the programs that hold an open project (`ProjectStatus::isOpen()`: draft, approved, active).
- **Recipients:** role `MEAL` + the `meal_manager` slot holder (`Slots::holderOf`, §9), filtered by `RecipientFilter` on module `results` (needs `results.view`). Nothing in `RecipientResolver`. Priority `important`, kind `alert`.
- **Payload:** one program → key `notifications.alerts.logframe_missing.single` (`:subject` = program name), subject `program:{id}`, link `results.index?program={id}&create=1`. Several → one `notifications.alerts.logframe_missing.grouped` (`:count`) per recipient, no subject, link `results.index`. No money, no project lists.
- **Deep link:** `pages/results/⚡index.blade.php` `mount()` opens the create modal with `resultProgramId` = the program and `resultType` = `impact` only when `create` is exactly `1`, `program` is an existing id and `Gate::allows('results.create')`. Anything else is ignored. Read once (not `#[Url]`), so a refresh after closing does not reopen it.
- **Catalog:** `program.logframe_missing` was already in `EventCatalog` (results, digest, oversight all, direct `scanner`); verified by test, not changed.
- **Lang:** `notifications.alerts.logframe_missing.{single,grouped}` in `en` + `ar`. The notification presenter uses `__()` (not `trans_choice`), so `grouped` has no plural ranges: "Programs without a program framework yet: :count".

## Deviations from contracts.md / the prompt
- **Re-arm timing (Q2, approved by Youssef 2026-10-19):** the ledger is released by the next check (`notify()` / daily scan), not by `SaveResult`. A framework created and deleted between two checks does not re-alert until the next scan. Keeps T12's `SaveResult` untouched.
- **New programs from HR alert even with no project yet (Q1, approved by Youssef 2026-10-19).** The daily rule requires an open project.
- **SaveProject hook** is a 3-line `if` + dispatch (not literally one line). **Dev 1 to review.**
