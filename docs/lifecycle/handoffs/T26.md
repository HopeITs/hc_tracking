## Delivered contracts (exactly as on the branch)

**The UI checklist** lives in `docs/lifecycle/prompts/T26.md` under "UI checklist". Copy it into every UI task's PR description.

**Guards** in `tests/Feature/LocalizationTest.php`:
```php
/** @return list<string> paths relative to resources/views; entries ending in "/" expand to every *.blade.php below */
function localizedViewFiles(): array;
function physicalDirectionClasses(string $source): array;   // whole-token ml- mr- pl- pr- left-N right-N text-left/right rounded-l/r* border-l/r*
function literalUiText(string $source): array;              // text nodes + literal label/placeholder/title/aria-label/heading/description/alt
function literalUiTextAllowlist(): array;                   // ['OP1.2', 'https://', 'email@example.com']
```
Tests added: `listed views use logical direction classes only`, `listed views contain no literal UI text`, `arabic plural strings use the explicit ranges`.
- The list names every top-level view folder (`components/ pages/ layouts/ mail/ partials/ errors/ notifications/`), so a new Blade file is checked from its first commit. Vendor-published `flux/` and `vendor/` are left out.
- A centred `left-1/2` paired with `-translate-x-1/2` is allowed (symmetric).
- `components/ui/gantt.blade.php` is the one reviewed direction exemption: its header comment says the timeline stays in left-to-right pixel space.
- Echoes become `§`, directives with arguments and comments are stripped before scanning, so Blade logic is never read as text.
- To allow a value, add it to `literalUiTextAllowlist()` with a reason in the PR.

**Arabic render tests**: `tests/Feature/ArabicPageRenderTest.php` (dataset `translated pages`: route, role, title key, label key). Each row runs an Arabic test (`<html lang="ar" dir="rtl"`, Arabic title, one Arabic label) and an English twin. A new page adds one row.
