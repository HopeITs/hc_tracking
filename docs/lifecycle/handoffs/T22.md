```php
/** @return array{id: string, encrypter: Encrypter} @throws FileStorageNotConfigured */ public static function current(): array;
```

```php
public const FileTables = ['media', 'report_files', 'task_attachments'];   // register new file tables here
public static function save(Media|ReportFile|TaskAttachment $file, ?UploadedFile $upload, string $directory, string $typedName, array $attributes, array $uploadAttributes = [], string $label = 'file'): void; // signature unchanged, now encrypts
```

`save()` stores at `{directory}/{Str::random(40)}.{type}`, sets `encryption_key_id`, keeps `size` = original bytes, forgets a replaced file after the save, and deletes the Livewire temporary upload and its `.json` sidecar (best effort).

**Exceptions** (`app/Exceptions`): `FileStorageNotConfigured extends ValidationException` (field `newFile`, `errors.file_storage_not_configured`); `UnreadableStoredFile extends RuntimeException` with `forKey(?string)`, `forRow(string $table, int $id)`, `report()` (logs `table`, `id`, `key_id` only) and `render()` (view `errors.file-unreadable`, status 500). The seven controllers catch it and call `forRow()` so the log names the row.

**`FileType::mimeType(): string`**. **Models** `Media`, `ReportFile`, `TaskAttachment`: `encryption_key_id` in `#[Fillable]`/`@property`/`$attributes` (null), `isEncrypted(): bool`.

**Schema**: `encryption_key_id` varchar(20) NULL after `size` on the three tables (`2026_10_14_095945_add_encryption_key_id_to_file_tables`). `down()` throws while any row has a key id.

**Commands**
- `security:reencrypt --files {--dry-run}` (now `Isolatable` + `ConfirmableTrait`): re-keys every file whose key id is not the current id. Per file: lock the row, re-check `path` and key id, write the re-encrypted copy to a new sibling path, read it back and compare sha256, update `path` + `encryption_key_id`, then delete the old file after commit. A file that cannot be read is reported by id and left alone; exit FAILURE. Without `--files` the command is unchanged.
- `files:encrypt-existing {--dry-run} {--chunk=100}` (`Isolatable` + `ConfirmableTrait`, "Run with --dry-run first."): encrypts every plaintext row (key id NULL) on the `local` disk. Per file: read the original, write the encrypted copy to a new sibling path, read it back and compare sha256, then one transaction locks the row, re-checks `path` and key id and sets `path` + `encryption_key_id`; the plaintext is deleted after commit (leftovers: `files:prune`). Skips and counts (table + id logged): missing file, reference-only row (`original_name` NULL), non-`local` disk. A row that changed while processing is left alone ("changed while running"; run again). A failure removes the new copy, keeps the original, lists the id and exits FAILURE. A missing or invalid key exits FAILURE before any read or write, also with `--dry-run`. Output per table: `N to encrypt|encrypted, N already encrypted, N missing on disk, N skipped`. Resumable: rows with a key id are never selected again.
- `files:decrypt {table} {--id=} {--to=}` (`Isolatable`): writes one decrypted file to a NEW path outside `Storage::disk('local')` root, `storage/app` and `public/`; never overwrites; prints only the destination and a reminder to delete it.

**Lang** `errors.file_unreadable`, `errors.file_storage_not_configured` (en + ar).
