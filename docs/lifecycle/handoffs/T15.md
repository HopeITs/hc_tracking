### `App\Support\MealCoverage` (contracts §12.3)
```php
final class MealCoverage
{
    public static function responsibleFor(Project $project): ?int;          // HR employee id
    /** @return list<int> */ public static function projectsCoveredBy(int $employeeId): array;   // project ids, sorted

    // Helpers, not in §12.3 (safe to use, not frozen):
    public static function cityIdOf(Project $project): ?int;              // center's city, else projects.city_id
    public static function officerOfCity(int $cityId): ?int;              // the stored officer, active or not
    public static function mealManagerEmployeeId(): ?int;                 // MEAL Manager slot holder (see Deviations 1)
    /** @param list<int> $employeeIds @return list<int> */ public static function activeEmployeeIds(array $employeeIds): array;
}
```
- **The return value is an HR employee id, not a user id.** Map it with `app(EmployeeRecipients::class)->usersFor([$id])`. An employee with no account maps to nobody.
- **`responsibleFor()` fallback chain.** Each step is skipped if the employee is inactive in HR (`employees.is_active`):
  1. the project's own officer;
  2. the officer of the project's governorate (the center's city via `Project::center()`, else `projects.city_id`);
  3. the MEAL Manager slot holder;
  4. `null`, in which case the caller uses the MEAL role holders.
- **Cost of `responsibleFor()`:** 1 query on `meal_coverages` and 1 HR query on `employees`, plus the cached `HrCenter`, `EmployeeProfile` and settings lookups.
- **`projectsCoveredBy($employeeId)`:**
  - It returns the projects assigned to the employee directly, plus every project whose governorate the employee covers. Projects whose own officer is someone else are excluded.
  - It does **not** filter out inactive officers.

### Writer and policy
- **Action:** `App\Actions\Cities\AssignMealCoverage::handle(MealCoverageScope $scope, int $targetId, int $employeeId): MealCoverageAssignment`. It is the only writer.
  - **Authorization:** `Gate::authorize('manage', MealCoverageAssignment::class)`.
  - **Employee check:** a closure rule (`HrEmployee::query()->whereKey()->where('is_active', true)->exists()`). On failure it raises `ValidationException` on `mealEmployeeId` with "Choose an active employee."
  - **City check:** `HrCity` must exist (it may be inactive); else "City not found." on `mealTargetId`.
  - **Project check:** the project must exist ("Project not found."), then `Gate::authorize('view', $project)`.
  - **Write:**
    - Runs in `DB::transaction` and reads the existing row with `lockForUpdate`.
    - Same employee: no write, no activity, no notification.
    - Different employee: Eloquent `update`, which also sets `assigned_by`.
    - A create that hits the unique index (`UniqueConstraintViolationException`) re-reads the row under lock and updates it.
- **Policy:** `App\Policies\MealCoverageAssignmentPolicy::manage(User $user): bool`. True only when the user has `meal-coverage.manage` **and** `employee_id === MealCoverage::mealManagerEmployeeId()`.
