### `App\Support\EmployeeProfile` (contracts §10)
```php
final class EmployeeProfile
{
    /**
     * @return array{employee_id: int, position_id: ?int, position_title_en: ?string, position_title_ar: ?string, job_level: ?string, grade: ?int,
     *               department_id: ?int, program_id: ?int, center_id: ?int, city_id: ?int, direct_manager_employee_id: ?int, is_active: bool}|null
     */
    public static function for(int $employeeId): ?array;
    /** @return list<int> */ public static function employeeIdsAtCenter(int $centerId): array;
    /** @return list<int> */ public static function employeeIdsInDepartment(int $departmentId): array;
    public static function managerOf(int $employeeId): ?int;
    public static function holderOfPosition(int $positionId): ?int;
}
```
- **Current position** comes from the active contract (`contracts.is_active = 1`). If an employee has several, the latest `start_date` wins (then the highest contract id), and `Log::warning('HR employee has several active contracts; …', ['employee_id' => …])` is written once per load.
- **`for()` returns null** for an employee with no active contract and for an id HR does not have.
- **Field rules:**
  - `job_level`: the current-locale name (Arabic, falling back to English).
  - `city_id`: the center's city when the position has a center, else `positions.city_id`.
  - `is_active`: `employees.is_active`.
  - `direct_manager_employee_id`: `holderOfPosition(positions.direct_manager_id)`, so it is null when that position is vacant.
- **Cost:** 2 HR queries per load.
  - `contracts ⋈ positions ⟕ job_levels ⟕ centers`, active contracts only, every column named.
  - `employees(is_active, id)`, the whole table, so asking about someone without a contract never counts as an unknown id.
- **Never read:** `contracts.salary`, `currency`, contract type, or `*`.
- **Caching:** kept per running app via `RemembersHrLookup`. It reloads after 60 s, or once when an id HR did not have at load time is asked for (a new hire). `holderOfPosition()` and `employeeIdsAt*()` read the cached map and never force a reload.
- `employeeIdsAtCenter()` / `employeeIdsInDepartment()` list everyone holding an active contract there, including employees inactive in HR. Filter on `for($id)['is_active']` if you need active people only.

### `App\Models\HrCenter` (`centers`, extends `HrModel`, read-only, `RemembersHrLookup`)
- `HrCenter::options(): Collection<int, HrCenter>` returns active centers sorted by current-locale name, then id.
- `HrCenter::remembered(int $id): ?HrCenter` returns any center, active or not, from the lookup; null when HR has none.
- `name` / `secondary_name` accessors (locale-aware); `city()` belongsTo `HrCity`; casts `city_id` int, `is_active` bool.
- The lookup reads `id, name_en, name_ar, city_id, is_active` only.

### `App\Models\HrJobLevel` (`job_levels`, read-only, `RemembersHrLookup`)
- `HrJobLevel::options(): Collection<int, HrJobLevel>`, ordered by `grade` then id; `name` accessor.

### `App\Models\HrPosition`
- New relations: `center()`, `jobLevel()`, `city()`, and `directManager()` (belongsTo `HrPosition` via `direct_manager_id`).

### `App\Models\Project`
- `center_id` is in `#[Fillable]` (`@property int|null $center_id`).
- `public function center(): ?HrCenter` resolves through `HrCenter::remembered()`, not a relation. Call it as a method; `$project->center` does not work.
- `public static function openProjectFor(int $centerId, int $programId, ?int $exceptId = null): ?Project`
  - Open means the `ProjectStatus::isOpen()` statuses (today draft, submitted, approved, active; T05 drops `submitted`).
  - It locks the `programs` row first (`lockForUpdate`), so **call it inside the transaction that writes the project**. Every create, restore, reopen or link for that program is then serialised.
  - Returns the lowest-id open project for the pair (`id, slug, name, status, center_id, program_id`).

### Project form (`ManagesProjectForm`, projects/index modal)
- **Center replaces City.** The form has no `cityId` property any more; setting it is refused by Livewire. `centerId` is `wire:model.live`.
- **When the center is required:**
  - Always on create.
  - On edit, only if the project already has a center (Q1).
  - It must exist and be active, except the edited project's own inactive center, which stays choosable and is labelled "Inactive center".
- **City:** the server writes `city_id` from the center. A project with no center keeps its city.
- **Default name:** «{Program} — {Center}», proposed once both are chosen on create. A name the person typed is never replaced.
- **Duplicate refusal:** create, or an edit that changes center or program of an open project, runs in `DB::transaction` → `Project::openProjectFor()` → save. On a hit it shows the `open_project_exists` error on `centerId` and writes nothing.
- **Unmapped-projects warning:** holders of `projects.delete` (General Manager, Managers) see "Projects without a center (N)" on projects/index. The list loads only when expanded.
- **Project page:** the header meta shows the center name, an "Inactive center" badge, or `#id · تعذّر تحميل بيانات HR` when HR can't be read.
- **Chip:** `x-ui.employee-chip` (non-compact) adds a position line. If HR can't be read it shows `#id · Could not load HR data`.
- **Pickers:** they render `detail` under the name and dim inactive people (`resources/js/form-fields.js`).

## Deviations from contracts.md / the prompt
None to `contracts.md`. Prompt-level choices, all approved in plan review (Q1–Q5, recommended answers):
1. **Center on edit (Q1):** optional while a project has no center, so the 36 legacy projects stay editable.
2. **Warning audience (Q2):** holders of `projects.delete`, not `administrator_roles`, which is Super Admin and dev-only (D-20a). The warning lists **every** project with `center_id` NULL, a superset of "cities without a center".
3. **Mapping conflicts (Q3):** two open projects that would share a (center, program) are reported and never applied.
4. **Matching (Q4):** strict. Positions with that program at an active center in the project's city; there is no single-center-in-city fallback. The no-center table shows the city's active centers as a hint.
5. **`currentDepartmentId()` (Q5):** now delegates to `EmployeeProfile`.
6. **Shared lang keys:** `hr_unavailable` and `no_active_position` live in `lang/*/common.php` (the chip is shared), not `projects.php`.
7. **Query budget:** the projects/index budget in `ProjectDirectoryTest` went from 18 to 21. The +1 is the unmapped-projects count; the +2 are EmployeeProfile's queries behind the owner chips.
8. **Lock target:** the lock is the `programs` row (no new table, no index), taken inside `openProjectFor()` itself.
