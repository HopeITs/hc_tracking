**Period math**
```php
App\Support\DonorReportPeriods::window(Proposal $proposal, ReportingPeriod $type, string $startMonth, ?string $endMonth): array{start: CarbonImmutable, end: CarbonImmutable}
```
- Start = the 1st of `startMonth` (`Y-m`).
- Fixed periods end after `addMonthsNoOverflow(n)->subDay()`. Custom ends at the end of `endMonth`.
- Both are clipped at `actual_date_end`.
- `ValidationException` `startMonth: donor_reports.period_outside_grant` when there are no actual dates, the start month is outside the grant, or a custom end is missing, before the start or after the grant.

**Aggregator**
```php
App\Support\DonorReportAggregator::aggregate(Proposal $proposal, CarbonImmutable $start, CarbonImmutable $end, bool $includeFinance): array   // instance method; resolve with app()
```
Throws `proposalId: donor_reports.self_funded` for an internal donor. Read-only, with a constant query count (same count for 2 × 2 and 10 × 12 centers × months, tested).

Snapshot shape (`schema_version` 1). `ComposeDonorReport::snapshot()` adds `generated_at`, `generated_by` and `period.type`:
```
schema_version: 1, generated_at: ISO-8601, generated_by: user id
period: {type, start: Y-m-d, end: Y-m-d, months: list<Y-m>}
header: {proposal_id, proposal_name, internal_number, donor_id, donor_name, agreement_id: ?int, contract_number: ?string (external_project_number), implementer (config app.name), goal: ?string (impact result)}
centers: list<{project_id, name (project name), center_id, beneficiaries: ?int (project_proposal.target_beneficiaries)}>
indicators / historical: list<{
    indicator_id, library_indicator_id, code, name, measure, unit, basis, is_cumulative, is_tracking_only,
    shared: bool (footnote "shared with another funding"),
    target: ?float, period: Figure, cumulative: Figure, achievement: ?float, excluded: int,
    centers: list<{plan_indicator_id, project_id, target, beneficiaries, period: Figure, cumulative: Figure, achievement, excluded, shared}>,
    disaggregation: null | {centers: list<{project_id, male, male_disabled, female, female_disabled, total}>, total: {…}}
}>
    Figure = {value: ?float, numerator: ?float, denominator: ?float}   (counts: numerator/denominator null)
    category = counts {value} | entered ratios {numerator, denominator, value}
activities: list<{result_id, statement, centers: list<{project_id, status (ActivityStatus value), execution_months: list<Y-m>}>}>
narratives: list<{project_id, month: Y-m, question, answer}>
files: list<{id, monthly_report_id, project_id, month, name, evidence_type_id, evidence_type_ar, evidence_type_en}>   (links to monthly_report_files, never copies)
completeness: {missing: list<{project_id, month, state: not_submitted|not_validated}>, missing_denominator: list<{plan_indicator_id, project_id}>, has_validated_data: bool}
finance (only when $includeFinance): list<{currency (amount_received_currency), received, net, net_missing: int, fees: list<{currency (fees_currency), amount}>}>
```

Rules as built:
- **Figures:** only approved mirrors (`reports.monthly_report_id` set) of the proposal's targets count.
- **Windows:** "period" = start month … end of the end month. "Cumulative" = grant start … end of the end month.
- **Counts:** sum. `is_cumulative` → the latest value.
- **Ratios:** `PlanIndicator::pooledRatio()` per center and across centers.
- **Achievement:** cumulative ÷ target × 100. Tracking-only → null.
- **Indicator target:** counts → Σ center targets; ratios → the shared target when every center has the same one, else null.

## Deviations from contracts.md / the prompt
All of these were approved by Dev 1 (Rit) in plan review on 2026-10-19, as Q1–Q9.
1. **Q1, contract addition (§13):** `pooledRatio()` gained the `numerator` / `denominator` keys, so the snapshot stores Σ numerator and Σ denominator without a second formula. **Dev 1 to log it in `CHANGELOG.md`.**
2. **Q2:** disaggregation over months follows the pooling rule per target. Counts sum (the latest month when cumulative). Entered ratios take the latest month. Centers then add up. Fixed-denominator indicators show counts (the `numerator` column) only.
3. **Q3:** `shared`-mode breakdowns are read at line level (`monthly_report_line_share_id` NULL), as T17A stores them; `split` reads share level.
4. **Q4:** "historical indicators" are targets with validated figures whose template line is `retired`, or whose indicator lost its library link. A delete is impossible once shares exist.
5. **Q5:** new key `agreement_required`.
6. **Q6:** the snapshot stores the **project** name + `center_id`, never HR center names; user ids only, no names (AGENT.md §5 HR rule). Slice 2 resolves the center name at render.
7. **Q7:** finance lines are per received currency; fees are listed per fee currency inside the line.
8. **Q8:** "execution months" = months in the period whose validated entry is started, ongoing, completed or conducted.
9. **Q9:** `header.implementer` = `config('app.name')`.
10. `DonorReportPolicy::regenerate` also requires `isComposed()`, because a hand-entered report has no period to compose. This tightens the policy.
11. The period of a regenerated report is not re-checked against the grant ("existing snapshots stay when the grant changes").
12. **TDD:** the aggregator was written before the first run of `DonorReportAggregatorTest`, so its red phase was not observed. `DonorReportBuilderTest` was seen red (missing `handle()`), then green.
