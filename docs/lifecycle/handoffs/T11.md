**Actions** (`app/Actions/IndicatorLibrary`, each `Gate::authorize`s; all refusals are `ValidationException`)
```php
SaveLibraryIndicator::handle(?int $libraryIndicatorId, array $input): LibraryIndicator
DeactivateLibraryIndicator::handle(int $libraryIndicatorId): LibraryIndicator
ReactivateLibraryIndicator::handle(int $libraryIndicatorId): LibraryIndicator
DeleteLibraryIndicator::handle(int $libraryIndicatorId): void
SaveLibraryIndicator::LevelRefPattern = '/^(G|CC|OC\d+|OP\d+(\.\d+)*|AC\d+(\.\d+)*)$/'
```
- `$input` = column names + `institutional` (bool; true → `program_id` null). `code`/`serial`/`is_active`/`is_legacy` in the input are ignored.
- Save validates in the action. Error keys: `name_ar`, `program_id`, `level_ref`, `follow_up_months`, `measure`; deactivate/reactivate/delete use `entry`.
- Save runs in one `DB::transaction` (3 attempts for deadlocks):
  - reloads with `lockForUpdate()`;
  - program/level change on an entry in use → `code_frozen`; on an unused entry → a new code;
  - measure change when a linked indicator has `plan_indicators` → `measure_locked`; otherwise every linked `indicators.measure` is updated in the same transaction;
  - percentage: `unit` cleared, `denominator_basis` = input or the collector's default; other measures: basis null; `follow_up_months` kept only for `follow-up`.
- Deactivate/Reactivate: lock, refuse a no-op with `stale`, `forceFill(is_active)`.
- Delete: lock; refused with `in_use` when any indicator references it; FK error 1451 is caught as the backstop → same message.

**Achievement** (`App\Models\PlanIndicator`): `measuresPercentage()` → `measuresLevel()` (private): percentage **or** average → latest approved value, pending always 0. `achievedValueSql()` / `pendingValueSql()` use `measure in ('percentage', 'average')`.

### Slice 3: seed command

```php
class App\Console\Commands\SeedIndicatorLibrary extends Command
protected $signature = 'meal:seed-indicator-library {--dry-run : List the proposed entries and codes without changing anything}';
```
- Reads once: every indicator with `library_indicator_id IS NULL` (by id), every result (`id`, `type`, `parent_id`, `program_id`), the legacy entries, HR programs. Writes in chunks of 50 groups, one `DB::transaction` each, inside `Activity::withoutRecording` (no `activities` rows).
- **Grouping:** name tidied (trim, one space) and folded with `ArabicText::normalize()`, plus `measure`. One legacy entry per group. A name used with two measures → one entry per measure and a `Conflict: "<name>" is used with more than one measure (numeric, percentage)` line.
- **Program** (developer, 2026-10-13): every use in one program → that program; several programs or none → institutional (`HC`).
- **Level** (developer, 2026-10-13), from the group's oldest indicator's result. `results` has no number column, so numbers are ranks by id:
  - impact → `G`;
  - outcome → `OC{n}`, n = rank among the program's outcomes;
  - output under an outcome → `OP{outcome n}.{rank under that outcome}`;
  - output under an output → parent's ref + `.{rank under that output}`;
  - output with no outcome/output parent → `OP{rank among those}`.
  - A parent in another program counts as no parent. Every ref is checked against `SaveLibraryIndicator::LevelRefPattern` (`LogicException` otherwise).
- **Entry fields:** `name_ar` = the name; `name_en` = the name too when it has no Arabic letters (`\p{Arabic}`), else null. English-only entries are listed "For MEAL review". `unit` from the oldest indicator (null for percentage); percentage → `denominator_basis = fixed` (`IndicatorCollector::ProjectTeam->defaultDenominatorBasis()`); `frequency` = the indicator's `Period` value as `CollectionFrequency`; `suggested_level` = the result type; `is_legacy = true`; everything else the column default. Code from `IndicatorCode::next()` inside the chunk transaction.
- **Linking:** `indicators.library_indicator_id` + `code` copy through a query-builder update guarded by `whereNull('library_indicator_id')`. `measure` already equals the entry's (it is part of the group key). `indicators.name` is not touched.
- **Re-runs** (developer, 2026-10-13): nothing unlinked → "Every indicator is already in the library." A later unlinked indicator joins the **legacy** entry with the same folded name (`name_ar` or `name_en`) and measure; never an entry MEAL made by hand. If MEAL has deactivated that entry, the indicator is still linked to it, with a warning: `002.OP1.1.1 "Number of people reached" is deactivated; 1 indicator(s) will still be linked to it. Reactivate it, or move them to another entry.` (developer, 2026-10-13).
- **Parent loops** (developer, 2026-10-13): before planning, results whose `parent_id`s lead back to themselves stop the run with `Results 12, 13 are each other's parents, so their level cannot be worked out. Fix their parents on the results page.` and exit 1, nothing written. The results page never builds a loop (parent exactly one level up); only data written around it could.
- **Order:** the full plan (table `Code · Measure · Name · Indicators`, conflicts, MEAL review list) is printed first in both modes. Then a program with a missing HR code, or a code HR gave to another program (D-10a), prints `HR program code 003 is used by more than one program: 3 Relief Programs, 4 Family to Family.` and exits 1 **before any write**, dry run included. A `ValidationException` from `IndicatorCode::next()` during the write (HR changed meanwhile) also exits 1; chunks already committed stay.
- Entries are written by the command, not through `SaveLibraryIndicator`: that action `Gate::authorize`s a signed-in user the console has none of (same as `permissions:sync`).
