## Delivered contracts (exactly as on the branch)

### Schema (§12.5)
- `sectors`: `id`, `name_ar` varchar(255), `name_en` varchar(255) null, `is_active` boolean default true, `sort_order` unsigned int default 0, timestamps. Index `sectors_active_order_index` (`is_active`, `sort_order`).
- `project_sector`: `id`, `project_id` FK `projects` cascadeOnDelete (`project_sector_project_id_foreign`), `sector_id` FK `sectors` **restrictOnDelete** (`project_sector_sector_id_foreign`), timestamps. Unique `project_sector_project_id_sector_id_unique`. No column on `projects`.

### Action (§12.5, signature exact)
```php
final class App\Actions\Projects\SyncProjectSectors
{
    /** @param list<int> $sectorIds  @throws ValidationException under the `sectorIds` key */
    public function handle(Project $project, array $sectorIds, bool $requireOne = false): void
}
```
- The one writer of `project_sector`. Distinct positive ids only. Anything else, a missing id, or an inactive sector the project doesn't already have refuses **the whole batch** (`sectors.unavailable`). With `$requireOne` and no ids it refuses with `sectors.choose_at_least_one`.
- One transaction: the project row is locked `FOR UPDATE`, the chosen sectors are read with a shared lock, then `sync()`.
- Records `project.sectors_changed` on the project only when something changed. Properties hold names only (`name_ar`): `added` / `removed` (joined text or `—`) and `added_sectors` / `removed_sectors` (lists). No ids, no amounts.

### Component (§12.5)
`<x-projects.sector-picker wire:model="sectorIds" />` (`resources/views/components/projects/sector-picker.blade.php`)
- Optional props: `label`, `help`, `required` (default `true`), `in-modal` (default `true`).
- Reads the bound array from the Livewire component.
- Offers `Sector::pickerOptions($chosenIds)`: active sectors plus chosen inactive ones, marked «غير فعّال» / "Inactive".
- Errors come from `$errors->first('sectorIds')`.

Also `<x-projects.sector-chips :sectors="$project->sectors" :empty="…" />`: read-only chips, runs no query.

- `App\Models\Sector`: `#[Fillable(['name_ar', 'name_en'])]`; `projects()` belongsToMany; `#[Scope] active()`, `#[Scope] ordered()` (qualified `sort_order`, `id`); `static pickerOptions(list<int> $chosenIds): Collection`; `localizedName()`.
- `App\Models\Project::sectors(): BelongsToMany<Sector>`.
- `App\Policies\SectorPolicy`: `viewAny` / `view` → `sectors.view`; `create` / `update` / `delete` → `sectors.manage` (§8).


### Project pages
- Form (`ManagesProjectForm`): `public array $sectorIds` (strings), loaded on edit, sent to `SaveProject`. The picker sits in the Placement section and is required on create.
- `SaveProject` `$data` gains `sectorIds?: list<int|string>`:
  - validated with the other fields (`required|array|min:1` on create);
  - then `SyncProjectSectors::handle($project, $sectorIds, requireOne: $existing === null)` runs inside the same transaction, after `save()`;
  - on edit, sectors change only when the key is sent.
- List: `#[Url] sector` filter, a `whereHas('sectors')` on the same connection, applied to every view. A sectors column appears in the table view, with sectors eager-loaded for that view only.

## Deviations from contracts.md / the prompt
1. **"Idempotent by a stable key."** §12.5 gives `sectors` no key column, so the defaults are matched by name instead (see `DefaultSectors`). **Dev 1:** add a nullable unique `sectors.key` to §12.5 if a real key is wanted.
2. **`SyncProjectSectors` authorization.** The prompt says `Gate::authorize('update', $project)`. Public Relations Manager holds `projects.create` but not `projects.update`, so that would block every PR Manager create. A project created in the same request (`wasRecentlyCreated`) therefore needs `create` on `Project`; every other call needs `update`. The signature is unchanged. Covered by "lets a Public Relations Manager … create one with its sectors". **Dev 1 to confirm.**
3. **`SaveProject` touched beyond the hook.** The prompt allows adding the component to T05's form "with Dev 1's review". Besides the hook call, `SaveProject` now also validates `sectorIds` together with the other fields on create, so a user sees every error at once. `SyncProjectSectors` still re-checks under the lock. **Dev 1 to review.**
4. **No activity on `Sector` itself.** The quality bar says every new model records activity, but §15 has no `sector.*` keys. The only contract event is `project.sectors_changed`, so `Sector` does not implement `TracksActivity`. **Dev 1:** add keys if the list changes should be logged.
5. **Seeder.** The plan said `CoreDataSeeder`. Projects are seeded later, so a dedicated `SectorSeeder` runs last instead.
6. **Collateral test updates** (needed because a new project now requires a sector):
   - a `newProjectSectorIds()` helper in `tests/Pest.php`, set after `openCreateModal` in `ProjectCenterTest`, `ProjectDirectoryTest`, `ProjectDraftLifecycleTest` and `Assignments/ProjectAssignmentTest`;
   - `NavigationTest` expects Sectors after Cities;
   - the `ProjectDirectoryTest` query budget is 21 → 22 (the filter's options);
   - `DatabaseSeederTest` covers `Sector` and `project_sector`.
