### Slice 2: generation, line builder, commands, `MonthlyReportPeriods`

**Generation** (system writers, no Gate)
```php
App\Support\MonthlyReportGenerator::generate(Project $project, CarbonImmutable $from, CarbonImmutable $to): array    // list<int> ids created; months of $from..$to
App\Support\MonthlyReportGenerator::missingMonths(Project $project, CarbonImmutable $from, CarbonImmutable $to): array // list<CarbonImmutable>, read-only
App\Support\MonthlyReportGenerator::monthsBetween(CarbonImmutable $from, CarbonImmutable $to): array                // static, list<CarbonImmutable> (first days)
App\Listeners\GenerateMonthlyReportsForProject   // queued (auto-discovered), tries 3, backoff [10,60,300], inline-safe
    ::handleProjectActivated(ProjectActivated)       // active projects only; startDate..endDate; one grouped monthly_reports.generated to the owner when anything was created
    ::handleProjectPeriodChanged(ProjectPeriodChanged) // newStart..newEnd, missing months only, no notification
```
- One transaction; locks the project row; reads existing periods once; one bulk `insertOrIgnore` (slug = `Str::slug(project slug-Y-m)`, the same as `MonthlyReport::slugSource()`); a month whose slug is already taken is saved through the model so `HasSlug` adds the suffix. No activity per month. Query count is constant in the number of months (tested).
- Never deletes or changes an existing report.

**Line builder** (internal; T17B never calls it directly)
```php
App\Support\MonthlyReportLineBuilder::build(MonthlyReport $report): array   // array{lines: int, shares: int} created; drafts only, else zeros
App\Support\MonthlyReportLineBuilder::templateLines(Project $project): Collection<int, ReportTemplateLine>   // confirmed, eager-loaded
App\Support\MonthlyReportLineBuilder::plannedLines(Collection $templateLines, CarbonImmutable $month, DonorAttribution $attribution): array
    // array<int library_indicator_id, array{entered_by: IndicatorCollector, fixed_denominator: ?int, shares: array<int plan_indicator_id, ?int>}>
App\Support\MonthlyReportLineBuilder::missingLineCount(Project $project, Collection $templateLines, CarbonImmutable $month, ?MonthlyReport $report): int  // dry runs
App\Support\MonthlyReportLineBuilder::attributionOf(Project $project): DonorAttribution  // load `program` first
```
- Lines of M = confirmed template lines with `isDueIn(M)` whose `PlanIndicator::coverableWindow()` covers M, grouped by library indicator; one share per target in both modes. `entered_by = meal` when any template line is. Share `fixed_denominator` = its template line's; line = Σ (`split`) or max (`shared`).
- Locks the report row; adds with `insertOrIgnore` on the unique indexes; never changes or removes a line or share. Constant query count (tested).
- Slice 3: `OpenMonthlyReport` and `RefreshMonthlyReportLines` authorise, then call `build()`.

**`PlanIndicator::coverableWindow(): ?array{0: CarbonImmutable, 1: CarbonImmutable}`** — moved from `ManagesReportForm` (which now delegates; no behaviour change): AnnualPlan → year bounds; Proposal → `actual_date_begin ?? planned_date_begin`, `actual_date_end ?? planned_date_end`; else null. Reads `source`.

Completeness and evidence are checked by slice 3's Submit, not here.

**Commands**
- `monthly-reports:prepare {--dry-run}`: for each active project whose first working day of the month (its own calendar) is today, builds the lines of the current month's draft. Prints `monthly_reports.console.prepare_row` per report; `--dry-run` writes nothing and prints `monthly_reports.console.dry_run`.
- `monthly-reports:backfill {--from=2026-10} {--dry-run}`: active projects with both dates; months from max(`--from`, start month) to the end month; builds the lines of started drafts. One row per project: `Project :project: :created months created, :skipped already there, :lines lines built.` Malformed `--from` → `monthly_reports.console.invalid_from`, exit 1.
- **T29 schedule entry** (`routes/console.php`): `Schedule::command('monthly-reports:prepare')->dailyAt('05:00')->withoutOverlapping()->onOneServer();`

**T27 go-live step**
1. `php artisan monthly-reports:backfill --from=2026-10 --dry-run` → one row per active project, then `Dry run: nothing was written.` Check `created` = months from Oct 2026 (or the start) to the end; `lines` > 0 only for projects with a confirmed template.
2. `php artisan monthly-reports:backfill --from=2026-10` → the same rows. A second run shows `0 months created, N already there, 0 lines built`.
- Dev DB dry run on 2026-10-16 (fake data, no confirmed templates yet): e.g. `Project 5: 3 months created, 0 already there, 0 lines built.` … `Project 31: 0 months created, 0 already there, 0 lines built.`, then `Dry run: nothing was written.`; `monthly_reports` stayed at 0 rows.
