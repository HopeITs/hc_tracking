How the numbers are made (so slice 2 and T28 can trust them)
- Rows: `plan_indicators` ⨝ `indicators` ⨝ `library_indicators` ⨝ `projects`, left-joined to `programs`, `proposals` (morph key `proposal`), `donors`, `annual_plans`, limited to targets whose proposal period (actual dates once both are set, else planned) or annual-plan year overlaps the window.
- Center view (no donor/proposal filter): one row per (project, library indicator); counts from `monthly_report_lines`; target = `DonorAttribution::combine()` of the row's targets (`shared` → highest, `split` → sum). Donor view (donor or proposal filter): one row per target; figures from the share mirrors in `reports`.
- Totals: counts Σ the validated cells' figures (latest when cumulative); percentage/average rows through `PlanIndicator::pooledRatioSql()` / `pooledExcludedCountSql()` over the row's targets (representative target in a `shared` center row, all in `split`, the single target in the donor view). Achieved % = total ÷ target × 100, null when the target is 0.

## Slice 2 (built)
**Row shape additions** (every row): `is_disaggregated`, `attribution` (`DonorAttribution`, null in a group), `is_group`, `centers_count`, `breakdown_kind` (`count`|`fixed`|`ratio`|null), `breakdown_raw` (summed figures, gender => Y-m => v/n/d/dv/dn/dd), `breakdown` (null, or `male|female|total` each `{cells[Y-m] ?float, total ?float, pwd{cells, total}}`).
- **Grouped (`view=grouped`)** (`GroupsMonthlyMatrix`): one row per library indicator, key `group-{library_id}`, `project_id`/`center` null, `centers_count`. Counts: target, cells and total are Σ of the (project, indicator) rows (a cumulative row already holds its latest value). Percentage/average groups: total and excluded count come from one `pooledRatioSql()` aggregate grouped by library entry over the union of the rows' `pooled_ids` (so a `shared` program still counts its one representative target); month cells are Σ numerator ÷ Σ denominator of that month's validated figures; the target is shown only when every row has the same target, otherwise null and so is achieved % (never an average). Cumulative groups show a "may count donors twice" note (D-25, flag only). A group's cell state is the strongest state of its rows.
- **Disaggregation** (`BuildsMatrixBreakdowns`): validated reports only, two flat reads. `shared` rows read the line-level breakdowns (`share_id` NULL), `split` rows Σ their share-level ones (the single share in the donor view). Counts use `value`/`disabled_value`; fixed-denominator percentages show the stored counts (`numerator`) only; entered ratios/averages are Σ numerator ÷ Σ denominator per month and over the window (never a sum of monthly percentages). Male, female and total each have an "of whom PwD" series; the PwD rows render and export only when `pwd` is on. Rows expand with an Alpine toggle (no round trip).
- **Activities tab** (`BuildsMatrixActivities`, computed `activityBoard`): `{months, outputs[{output_id, statement, activities[{key, activity_id, statement, kind, project_id, center, cells[Y-m => {kind: status|carried|planned|empty, status, weeks}]}]}], count}`. One row per activity x linked project of donor-approved proposals that overlap the window, under its output. A month shows the activity's own validated entry; else the planned weeks (a project's override rows replace the proposal calendar, as in `MonthlyReportActivities`); else the last validated status carried forward (muted, italic). Pending reports never show. Filters: proposal, donor, center, city, pillar, year, mine (the indicator filter is hidden on this tab). Five flat reads. Not paginated.
- **Shared filter helper:** `applyMatrixFilters()` in `BuildsMonthlyMatrix` now holds the proposal/donor/center/city/pillar/mine filters for the matrix and the Activities tab.
- **Export:** the matrix CSV gains a **Breakdown** column after Measure (the other columns keep their order, shifted by one); breakdown sub-rows follow their indicator, "of whom PwD" rows only with `pwd`. Grouped mode exports group rows (center = "N centers"). On the Activities tab `exportCsv()` writes `monthly-matrix-activities-YYYY-MM-DD.csv` (output, activity, center, type, 12 months). The permission, the 10/min limiter key and the no-money rule are shared.
- **Lang:** `reports.matrix.*` gains `tab_*`, `view_*`, `show_pwd`, `of_whom_pwd`, `sex.*`, `breakdown`, `centers_count`, `cumulative_group_note`, `fixed_counts_note`, `output`, `activity*`, `planned*`, `carried`, `no_status`, `no_target`, `no_activities*`, `activities_legend` (EN and AR).
- **Files:** traits `GroupsMonthlyMatrix`, `BuildsMatrixBreakdowns`, `BuildsMatrixActivities`; partials `_monthly-matrix-breakdown`, `_monthly-matrix-activities`.
- **Tour hooks added:** `data-matrix-modes`, `data-matrix-expand`, `data-matrix-activities`.

## Deviations from contracts.md / the prompt
- **No totals row** across the table, in any mode: rows are different indicators, so a column total would add unrelated figures. In grouped mode the group row is itself the total.
- **No expandable split rows** (quality-bar mention, not in the slice 2 build order): the donor filter already shows each share. Follow-up. Disaggregation rows are expandable.
- Annual-plan (org-wide) targets are included in the center view (plan Q1, recommended). In the donor view they drop out because a donor/proposal filter requires a proposal source.
- Pagination: 100 rows per page (in memory); the export holds every filtered row.
