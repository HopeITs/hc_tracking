How the numbers are made (so slice 2 and T28 can trust them)
- Rows: `plan_indicators` ⨝ `indicators` ⨝ `library_indicators` ⨝ `projects`, left-joined to `programs`, `proposals` (morph key `proposal`), `donors`, `annual_plans`, limited to targets whose proposal period (actual dates once both are set, else planned) or annual-plan year overlaps the window.
- Center view (no donor/proposal filter): one row per (project, library indicator); counts from `monthly_report_lines`; target = `DonorAttribution::combine()` of the row's targets (`shared` → highest, `split` → sum). Donor view (donor or proposal filter): one row per target; figures from the share mirrors in `reports`.
- Totals: counts Σ the validated cells' figures (latest when cumulative); percentage/average rows through `PlanIndicator::pooledRatioSql()` / `pooledExcludedCountSql()` over the row's targets (representative target in a `shared` center row, all in `split`, the single target in the donor view). Achieved % = total ÷ target × 100, null when the target is 0.

## Deviations from contracts.md / the prompt
- **No totals row** across the table. Rows are different indicators, so a column total would add unrelated figures; it only makes sense in slice 2's grouped mode.
- **No expandable split/disaggregation rows** (slice 2).
- Annual-plan (org-wide) targets are included in the center view (plan Q1, recommended). In the donor view they drop out because a donor/proposal filter requires a proposal source.
- Pagination: 100 rows per page (in memory); the export holds every filtered row.
