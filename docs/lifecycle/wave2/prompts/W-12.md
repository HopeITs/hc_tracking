Creation is a queued, idempotent listener on `ProposalStatusChanged`.

## Slice 1 · rules
- Seeder `StageTaskTemplatesSeeder` (idempotent upsert on the unique key) with the four starting rows; a data migration calls it so production gets them. Department ids come from a config map `config/stage-templates.php` keyed by a stable slug the seeder resolves against HR once (log and skip a department that is missing).
- Listener `CreateStageTasksOnStatusChanged` (queued, `shouldQueue` only when templates exist for `$to`, idempotent through `stage_template_id` + proposal, never calls Phase 1 actions). Tasks are created with `source` = the proposal, `department_id`, `kind`, title in the actor's locale fallback en, due = effective date of the move + offset, no assignee (D-33).
- `creates = final_report_milestone` → calls `SaveProposalMilestone`'s final-report path (do not duplicate it) and the manual "Add final report" button is **removed** from the page (keep the action class; the admin page is the only way to change the rule).
- A re-entry into the same status (e.g. draft → review → draft → review) does not duplicate open tasks; a closed template task may be re-created only if the template says so (`repeat_on_reentry` bool default 0 — add it to the table above).
