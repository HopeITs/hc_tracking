## [contract] · authorised by D-61
- `§7`, **W-09:** `risk_library` (`id`, `title_en`, `title_ar`, `category` varchar(40) null, `default_likelihood`, `default_severity` (same scale as `risks`), `is_active` bool default 1, `sort_order`, timestamps; unique `title_en`); `risks.library_risk_id` FK `risk_library` null restrictOnDelete; `risks.result_id` FK `results` null cascadeOnDelete; `risks.proposal_id` FK `proposals` null cascadeOnDelete; `risks.project_id` becomes nullable; index `(proposal_id, result_id)`. Rule: a new risk row has `library_risk_id`, `proposal_id` and `result_id`; `name`/`impact` are copied from the library at pick time so the proposal keeps its wording if the library changes.
- `§8`: permission `risk-library.manage`, holders `MEAL`, `General Manager`; `risks.create/update/delete` keep their holders and now mean "on a proposal's logframe".
- `§6`: `AttachLibraryRisk::handle(Proposal $proposal, int $resultId, int $libraryRiskId, array $overrides): Risk` (`@param array{likelihood?: int, severity?: int, solution?: string}`; result loaded through `$proposal->results()->whereKey($resultId)->firstOrFail()`), `DetachRisk::handle(Proposal $proposal, int $riskId): void`.
- `§15.2`: `proposal.risk_attached`, `proposal.risk_detached` (digest, names only).

## Slice 1 · rules
- Admin page `/admin/risk-library` (sidebar under Admin for `risk-library.manage`): CRUD, activate/deactivate (a library risk referenced by any `risks` row cannot be deleted), reorder, seeded from the list (idempotent, data migration too).
- `AttachLibraryRisk`: active library rows only; one library risk per result (unique in the action under the proposal lock, message "Already on this result"); activity after commit.
- `RiskPolicy`: `create`/`update`/`delete` now take the proposal (`ProposalPolicy::update` holders); BOLA on `resultId` and `riskId`.

## Slice 2 · rules
- Logframe: every outcome/output node gets a "Risks & assumptions" drawer (`x-ui.logframe-node` prop; count badge on the node) listing attached risks with likelihood/severity badges and a picker (`x-ui.multi-select-popover` over active library rows grouped by category); no free-text form anywhere.
- Proposal page: the heat map (moved partial, same component) in the Logframe tab footer, reading the proposal's risks.
- Removals: `risks.index` leaves `Destinations` and the sidebar; the route stays one release with a one-line notice linking to the proposal logframe; `_show-risks-tab` removed from the project page and its `TABS` entry; "Add Result" wording stays as T32 left it ("Start from library / program framework").
- Lang in `risks.php` both languages; `enums.php` for categories if you add an enum (TitleCase, lower-case values).
