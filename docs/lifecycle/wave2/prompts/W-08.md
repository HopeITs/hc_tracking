ClickUp: https://app.clickup.com/t/123jdbarcz4

## Goal
An `active` proposal can be **extended** (D-60): a new end date, a reason and an optional amendment file. The original `actual_date_end` is kept and the page shows "Extended to …" beside it. Every linked approved/active project whose end is earlier widens to the new date through the existing period path, so new monthly reports are generated. One status note of kind `extension` records it.

## Rules
- Transaction: lock the proposal, guard `expectedStatus = active`, write the columns, one note (`kind = extension`, context = reason, `effective_date` = today), file through `SecureUpload`, then for each linked project (locked in ascending id order) call `ProjectPeriods::widen()` with `end = new_date_end` and the project's current begin. Events after commit only.
- A second extension replaces `extended_date_end` (must be later than the current effective end) and appends another note; history lives in the notes.
- Page: "Extend" action in the proposal actions (active only, `proposals.update`); modal with date, reason (min 10), file; vitals show "Ends {actual} · Extended to {extended}" with the amendment file linked.
- `DeadlineCatalog`'s proposal-end items, `DonorReportPeriods` and `AgreementMoney` period readers switch to `effectiveDateEnd()` (search every `actual_date_end` read; list them in the plan).

Messages (`lang/{en,ar}/proposals.php`): "Only an active proposal can be extended." / «لا يمكن التمديد إلا لمقترح فعّال»; "The new end date must be after {date}." / «يجب أن يكون تاريخ النهاية الجديد بعد {date}».
