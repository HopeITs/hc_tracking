# W-06 · "On hold" becomes a flag on Submitted · Dev 1 · L (3–5 days) · 2 slices

ClickUp: https://app.clickup.com/t/123jdbarcz1

## Goal
`on hold` stops being a status (D-58). A proposal that is `submitted` (or `concept note submitted`) can be **put on hold** and **taken off hold** without moving; the label reads "Submitted (On hold)"; the reminder keeps working from `status_remind_on`. The transitions table loses every hold row; existing `on hold` rows migrate back to their pre-hold status with the flag set. The Status pickers, board columns, pipeline charts and the lifecycle stepper (W-25) follow.
- **Slice 1 (Dev 1):** contract, schema, enum deprecation, actions, transitions table, data migration, scanner, guard tests.
- **Slice 2 (Dev 2):** UI: status modals, board/register columns, pipeline chart, badges; W-25's stepper lands here too.

## Slice 1 · rules
- Data migration: `on hold` rows → pre-hold status (from the notes; `submitted` when none can be derived, logged) with `on_hold_since = date of the hold note`; `status_remind_on` kept. Print before/after counts; `down()` is a no-op that prints "manual"; guard tests allow the migration file by name.
- `ProposalTransitions`: remove the pre-hold branch and `onHoldTargets()`; `requirements()` loses the `$preHold` parameter (every caller updated); the moves from `submitted` and `concept note submitted` clear the flag inside `TransitionProposal`'s transaction.
- `ApproveProposal` accepts a proposal on hold (it is `submitted`) and clears the flag.
- `OnHoldReminderScanner` reads `on_hold_since IS NOT NULL AND status_remind_on <= today`.
- `ProposalStatus::label()` for a flagged row: the UI composes "Submitted (On hold)" through one helper `Proposal::statusLabel()`; stored values never change. `StatusTone` for the flagged state = `warn`.
- Pipeline and register counts group hold inside their status with a sub-count.

- `_show-lifecycle.blade.php` stepper draws the merged line (W-25 is folded into this slice; close its ClickUp task with this PR).
