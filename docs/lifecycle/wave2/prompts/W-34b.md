# W-34b · Tracking-owned programs · Dev 1 · L · 2 slices

ClickUp: https://app.clickup.com/t/123jdbarcyu · Spec: `docs/lifecycle/wave2/W-34.md` §0 and §9. Ruling: **D-68** (5 Nov 2026, `wave2/README.md`).

## Goal
`programs` stops being a mirror of `hchr_programs` and becomes a table of ours. Today the row holds only an id, a strategy link, a manager and a donor-attribution setting; the name, code, slug and active flag are read live out of HR, the row itself is inserted by `Program::syncFromHr()` under HR's id, and the `hr` connection is read-only — so Tracking cannot create a program at all, and there is no `programs.create` permission.

D-68 settles the question this task was blocked on: **"for now, regardless of HR"** — Tracking becomes the owner and the writer and issues the id, HR's table is left alone and stops being a source, and HR reads from the unified store later. Nothing outside this repo has to change.

- **Slice 1 (Dev 1):** the data flip. Local columns, a one-time import from HR, `Program` reads itself, `syncFromHr()` loses its insert, every call site off `HrProgram`.
- **Slice 2 (Dev 1):** creating one. `programs.create`, `SaveProgram` + policy, the fields in the existing program modal, an inactive badge and filter, activity events.

## Rules · slice 1
- Migration adds `name_en`, `name_ar`, `code`, `slug`, `is_active` exactly as `contracts.md` §7 W-34b. Every column pre-checked before the DDL (MySQL does not roll back DDL); working `down()`; utf8mb4_unicode_ci. **The migration must not read the `hr` connection** — the test suite builds the HR SQLite schema per test, so a migration touching `hr` is unrunnable.
- `php artisan programs:import-from-hr {--dry-run} {--apply} {--force}`. `--dry-run` (the default) writes nothing and **is also the drift report**: HR programs with no local row, local programs HR does not have, and rows whose name, code or slug differ. `--apply` fills the empty columns from HR, inserts a local row for any HR program we lack, raises `AUTO_INCREMENT` to `max(id) + 1000` (`W-34.md` §9: new Tracking ids clear of the HR range), and prints counts. Idempotent. A `name_en` someone has already edited locally is never overwritten without `--force`. **Slugs are carried over from HR** so existing `programs/{slug}` URLs keep working.
- `Program`: `name_en`, `name_ar`, `code`, `is_active` become real attributes; `name` stays an accessor and returns the Arabic or English name by locale, falling back to `name_en` (HR has one name, so `name_ar` starts empty). `HasSlug` replaces the slug accessor, `getRouteKeyName()` and the custom `resolveRouteBinding()`, with `slugSource()` = `name_en`. `whereNameLike()` and `orderByName()` become ordinary SQL — the `FIELD(...)` ordering and the HR id pre-read go. New statics `namesById()`, `nameOf()`, `codeOf()`, `idsMatchingName()`, `idsOrderedByName()` mirror the old HR API so each call site changes by class name only, memoized per request, **no HR query**.
- `syncFromHr()` keeps only the manager mirror (an employee id, so HR-owned) and loses the insert and its "new ids" return. `SyncProgramsFromHr` middleware keeps running for that.
- The logframe-gap job moves with it: `CheckProgramLogframe` was dispatched from the sync's new ids, so it moves to a `created` hook on `ProgramObserver` — it then works in slice 1 and for programs created in slice 2.
- `ProgramFactory` stops inserting into the `hr` connection and writes `name_en`, `code` and `slug` locally; `newModel()`'s `Arr::except('name')` goes.
- Call sites off `HrProgram`: `ListsLibraryEntries` (×4), `FiltersProjectDirectory`, `ManagesProjectForm`, `ManagesProposalForm`, `IndicatorCode`, `ImportProgramFramework`, `MapProjectCenters` (the `namesById()` call only), `SeedIndicatorLibrary`, `DemoDeliverySeeder`, `components/proposals/{_logframe-copy-modal,⚡targets}.blade.php`. **Staying on HR deliberately:** `HrPosition::program()`, `ImportStrategyPillars`, `MapProjectCenters`' HR mapping table, and the new import command — they match *against* HR data by design.

Under D-68 the program is simply created here. Retire the table, the `program_request.opened|linked` catalog keys, the `hr_liaison` slot and the admin page once slice 2 lands — its own item, with its own `[contract]` text.
- `center_requests` (W-34c, Dev 1's 4 Nov ruling) is unaffected: HR still owns centers.
