## [contract] · authorised by D-64
- `§12.2`: `TaskKind::Report = 'report'`. `tasks.reportable_type` varchar(255) null, `tasks.reportable_id` unsigned big int null, index `(reportable_type, reportable_id)`; morph map key `donor_report` (later `monthly_report`). At most **one open** (status ≠ done) report task per reportable, enforced in the action under the report's lock.
- `§6`: `SyncReportTask::handle(DonorReport $report): ?Task` — creates the task for the current responsible when none is open, reassigns the open one when the responsible changed, completes it when the report is submitted. Called by the assignment and submission actions inside their transactions. `Gate` is the caller's (the report action already authorised).
- `§15.2`: reuse `task.assigned` / `task.completed`; no new key.

## Rules
- Task fields: `kind = report`, `source` = the report's proposal (so proposal pages list it), title "Donor report: {donor} · {period}" built from the report at creation (titles are not updated later), due = the report's due date (null allowed), assignee = the responsible employee, created_by = actor.
- Reassignment moves the single assignee; submission sets `status = done`, `completed_date = today`; reopening a report (if T19 allows) reopens the task.
- Tasks panel / register / task page: a row with `kind = report` shows a "Report" chip and its title links to the report page (through `SubjectLinks`); the usual status moves apply, but marking the task done by hand does **not** submit the report (one direction only; say so in a helper line on the task page).
- `TaskKind::Report` is excluded from the department-task delivery trail (media) and from the Finance-only filter; add the case to every `match` on `TaskKind` (exhaustive, no default).
