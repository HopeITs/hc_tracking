## Goal
When the employee named as responsible on a proposal location row, or the owner of an open project, is no longer active in HR, the proposal owner and the Public Relations Manager get one notification asking them to reassign, with a "Reassign" quick action that opens the row (D-62). Once per employee per subject; silent again after reassignment.

## Rules
- New `ResponsibleInactiveScanner implements Scanner`: reads the inactive employee ids **once** from HR (in-memory set), then selects location rows of live proposals (`ProposalStatus` not rejected/completed) and open projects whose responsible/owner is in the set. No `whereHas` across connections.
- Ledger stage = the employee id, so a reassignment to another inactive person raises again and a reassignment to an active one goes quiet.
- Notification text names the proposal/project and the person; no money.
- Quick action "Reassign" / «إعادة التعيين»: `QuickActions` entry visible to `proposals.update` (or `projects.update`) holders; link = proposal page `?tab=locations&row=<id>` (W-34a's chapter must accept the anchor; if it does not yet, add the `row` query handling there in this task, scoped to scrolling and highlighting).
- Register the key in `EventCatalog` with module `proposals`, priority `now`, type `scanner`.
