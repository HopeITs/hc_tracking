## Delivered contracts
- `TaskKind::Report = 'report'` (label `enums.task_kind.report`: «Report» / «تقرير»). `TaskKind::department()` / `departmentValues()` list the kinds a person may pick: everything except `Report`. `SaveDepartmentTask`, the plan modal and the department-tasks filter use them, so a report task can never be created or filtered as a department task.
- `tasks.reportable_type` varchar(255) null, `tasks.reportable_id` unsigned bigint null, index `tasks_reportable_index` (migration `2026_11_04_121857_add_reportable_to_tasks_table`; throws if a column exists; `down()` drops index and columns). Both are in `Task`'s `#[Fillable]`. `Task::reportable(): MorphTo`, `Task::isReportTask(): bool`, `Task::reportUrl(): ?string` (through `SubjectLinks::routeFor`).
- **Morph map:** `donor_report` already exists. A monthly-report task would use `monthly_report` (also mapped); add its case to `SubjectLinks` only if it is not there (it is) and pass `reportable_type = 'monthly_report'`.
- `App\Actions\Tasks\SyncReportTask::handle(DonorReport $report): ?Task` (no Gate; run inside the caller's transaction, locks the report row):
  - submitted → completes the open task (`done`, `completed_date` today, progress 100); returns null when there is none;
  - not submitted, no responsible → returns the existing task or null;
  - not submitted, no task → creates one: `kind = report`, `source` = the report's proposal, `reportable` = the report, title `donor_reports.report_task_title` ("Donor report: {donor} · {period}", built once, never updated), `due_date` = `due_on`, `created_by = Auth::id()` (throws `LogicException` when nobody is signed in), one `TaskAssignee` for the responsible;
  - not submitted, task closed → reopens it (`todo`, no completed date);
  - responsible changed → deletes the other `TaskAssignee` rows and adds the new one (so `task.unassigned` / `task.assigned` fire);
  - a newer version (same agreement, type and period, higher `version`) deletes the open task of older unsubmitted versions.
  - `SyncReportTask::forget(DonorReport $report): void` deletes the report's tasks.
- Callers: `SaveDonorReportSnapshot::insertNextVersion()` (after the insert, so compose and regenerate), `MarkDonorReportSubmitted` (after `submitted_on` is written), `DeleteDonorReport` (`forget`, before the delete).
- UI: Tasks panel, Tasks register (list row, list card, board card) and the task page show an `x-ui.enum-badge` «Report» chip (`data-test="report-task-chip"`); the title links to `donor-reports.show` when the task is a report task; the task page adds an "Open the report" link and the helper line (`tasks.report_task_helper`, `data-test="report-task-helper"`): marking the task done does not submit the report. The proposal Plan tab lists report tasks in its "Other" group (`ManagesProposalPlan::planGroups`).
- Lang: `donor_reports.report_task_title`, `tasks.open_report`, `tasks.report_task_helper`, `enums.task_kind.report` (en + ar). No new notification key: `task.assigned` / `task.completed` are reused.
- Task selects that feed the register and the task page now include `kind`, `reportable_type`, `reportable_id` (`FiltersTaskDirectory::filteredTasksQuery`, `pages/tasks/⚡show`).

## Deviations from contracts.md / the prompt
- **Reopen and change of responsible have no caller yet** (nothing edits `responsible_employee_id`; T19 has no reopen). `SyncReportTask` handles both and `ReportTaskTest` calls it directly. Any future edit/reopen action must call it inside its transaction.
- **Closed-by-hand task:** a later sync of an unsubmitted report reopens the task (the report still owes delivery). Sync only runs on create/submit/delete today.
- `DeleteDonorReport` also removes the report's task (not in the prompt; otherwise the task would point at nothing).
- Superseded versions: a regenerated report takes over the open task of the older version (Q2 of the plan).
- Board card shows the chip but its title link also goes to the report (the card still has the edit drawer button).
