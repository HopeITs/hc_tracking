### `x-ui.panel` (`components/ui/panel.blade.php`)
`@props(['title' => null, 'subtitle' => null, 'count' => null, 'as' => 'section', 'clip' => true])`
- Root `<{as} data-panel class="rounded-panel border border-panel-border bg-white shadow-card dark:bg-surface-1 dark:shadow-raised [overflow-hidden when clip]">`.
- `as`: `section` (default), `aside`, `article`, `div`, `ol`, `ul`. Anything else falls back to `section`. Converted roots keep their original element.
- `clip` (default `true`) adds `overflow-hidden`. Pass `:clip="false"` when a child is `sticky`, or when the old markup did not clip. Roles and users forms both have a sticky "Save" bar.
- The title-row and footer dividers use `border-panel-border`.

### `x-ui.section` (new, `components/ui/section.blade.php`)
`@props(['title' => null, 'description' => null, 'padded' => true, 'level' => 2, 'key' => null])`, slot `actions`.
- `<section data-section="{key}" aria-labelledby="section-{key}-heading" class="min-w-0">`. Both attributes appear only when `key` is set (and a title for `aria-labelledby`).
- `<header class="… border-b border-panel-border pb-2">` holds:
  - `<h2|h3 class="type-label text-secondary-medium dark:text-ink-muted">`: `level` 3 → `h3`, anything else → `h2`; uppercase and tracked, reset under Arabic by `.type-label`;
  - an optional description `<p>`;
  - the actions slot, at the end.
- Then `<div data-section-body class="min-w-0 [pt-4 when padded]">`.
- No border, shadow or radius on the root. The header renders only when there is a title or actions.

### Fixed during the browser check: the risks page scrolled sideways at 375px (existed before W-29)
- **Cause:** `components/ui/chart.blade.php` rendered its screen-reader data as `<table class="sr-only">`. A table ignores `width: 1px` and `overflow`, so its layout box stayed about 475px wide. Nothing around it is positioned, so it escaped the panel's `overflow-hidden` and widened the page to 499px (en) and 487px (ar).
- **Fix:** the table now sits inside `<div class="sr-only">`. A div honours the 1px box, so the chart stays contained wherever it is used, not only inside a clipping panel. Screen readers still get every row.
- **Test:** `UiComponentsTest` › "the chart keeps its screen-reader table inside a one-pixel box so it never widens the page". It was red first, then green; `UiComponentsTest` + `RiskRegisterTest` pass 104/104.
- **Browser:** risks at 375px is 375px wide in en and ar; the table keeps 16 rows inside a 1px box.
