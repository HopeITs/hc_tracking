## Delivered contracts (exactly as on the branch)

### The HR path used
`contracts` (`is_active = 1`, latest `start_date`) → `positions.job_level_id` → `job_levels.name_en` / `name_ar` / `grade`.

`EmployeeProfile::load()` already joins `positions` and `job_levels` and keeps `job_level_en`,
`job_level_ar` and `grade` in the remembered lookup, so **the rule adds no HR query** and nothing
is stored locally. There is no `whereHas` across connections.

### The config key
```php
// config/access-control.php
'department_manager_job_level' => 'Department Manager – Grade 5',   // en dash, as D-65 writes it
```
Unrelated to `task_department_scope_bypass_roles` / `task_department_scoped_roles` in the same
file, which decide what a user sees **at all** (`TaskVisibilityScope`) and are untouched.

### The one definition
```php
// app/Support/EmployeeProfile.php   (contracts.md §10)
public static function isDepartmentManager(int $employeeId): bool;
```
- Reads the remembered lookup entry; `false` when the employee holds no active contract **or** is
  inactive in HR.
- Compares against `config('access-control.department_manager_job_level')` on a **normalised**
  string: every dash variant (`‐ ‑ ‒ – — ― −`) becomes `-` with no space around it, runs of
  whitespace collapse to one space, then trim + `mb_strtolower`.
- Tries **`job_level_en` and `job_level_ar`**, so the answer never depends on the interface
  language. **Trap for the next reader:** `EmployeeProfile::for()['job_level']` is localised (it
  returns the Arabic name in Arabic) and must never be used for this check.
- No `grade` check: the configured name already carries "Grade 5", and D-65 names one level.

Verified against these inputs (normalised config = `department manager-grade 5`):

| Stored name | Counts |
|---|---|
| `Department Manager – Grade 5` (en dash) | ✔ |
| `Department Manager - Grade 5` (ASCII hyphen) | ✔ |
| `Department Manager — Grade 5` (em dash) | ✔ |
| `Department Manager‑Grade 5` (non-breaking hyphen, no spaces) | ✔ |
| `department manager -  Grade  5 ` (case + spacing) | ✔ |
| `Senior Officer – Grade 4`, `Department Manager – Grade 4`, `Department Manager`, `` | ✘ |

### Delegations
```php
// app/Models/User.php
public function canSeeDepartmentTasks(): bool;
// isAdministrator() || (employee_id !== null && EmployeeProfile::isDepartmentManager(employee_id))
// Memoized per user instance with once(), beside departmentEmployeeIds()/departmentUserIds().

// app/Policies/TaskPolicy.php
public function viewDepartmentQueue(User $user): bool;   // tasks.view AND canSeeDepartmentTasks()
```
- Super Admin keeps everything through `access-control.administrator_roles`.
- `Managers` / General Manager get the scope **only** when their HR job level matches (D-65 is
  explicit). Their `task_department_scope_bypass_roles` membership does **not** grant it.

### Where it is enforced
| Surface | Before | Now |
|---|---|---|
| `department-tasks.index` route | `->can('tasks.view')` | `->can('viewDepartmentQueue', Task::class)` → 403 |
| Side-nav item (`Destinations::all()`) | `$can('tasks.view')` | `fn (User $user) => $user->can('viewDepartmentQueue', Task::class)` → **hidden**, not disabled |
| Tasks panel `department` option | always rendered | `@if ($this->hasDepartment)` |
| `deliverables` desk panel (`Panels.php:704`) | `$can('tasks.view')` | `fn (User $user) => $user->can('viewDepartmentQueue', Task::class)` → not offered |
| Tasks panel scope read | `$this->scope` | `$this->activeScope` |

### The panel's single definition (`components/desk/panels/⚡tasks.blade.php`)
```php
#[Computed] public function activeScope(): string;    // 'department' only for a manager; 'team' unchanged; else 'mine'
#[Computed] public function hasDepartment(): bool;    // auth()->user()?->canSeeDepartmentTasks() === true
```
**Why a computed and not just `updatedScope()`:** `IsDeskPanel::applyFilters()` assigns the filter
properties **directly** (`app/Livewire/Concerns/Desk/IsDeskPanel.php:107`), so it never runs
`updatedScope()` — that is exactly how `TaskWorkflowTest` reaches `scope = 'department'`. Guarding
only `updatedScope()` would have left that path open. `base()` (the only reader, feeding `rows()`)
and the view both go through `activeScope`, and `updatedScope()` now normalises the property
through the same computed instead of its own `in_array` list.

`TeamScope` and the `team` scope are untouched: a teamless user asking for `team` still gets the
existing empty result rather than being bounced to `mine`.

### No lang change
`desk.scope_department` already exists in `lang/{en,ar}/desk.php:141`. Nothing new is
user-visible, so `LocalizationTest` is unaffected and no Arabic copy was needed.

   `isDepartmentManager(): bool`. Every other `EmployeeProfile` method is static and takes an
   employee id; a no-arg version has no employee to read. **Dev 1 to confirm.**

   (`is_active !== true` → false). The prompt does not say; this follows T30's "none → null /
   inactive". **Dev 1 to confirm.**
5. **The level name is matched against `name_en` *or* `name_ar`.** The prompt names one config

   `department-tasks.index` with a user who is now refused. See Tests.

   touches `composer.json` / `composer.lock` — global `use-github-api false` (every GitHub zipball
