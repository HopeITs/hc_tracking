### One definition of which fields each section holds
A single `$sectionFields` map at the top of the modal, in render order:
```php
$sectionFields = [
    __('proposals.section_identity')      => ['previousProposalId', 'name', 'internalProjectNumber'],
    __('proposals.section_donor')         => ['donorId'],
    __('proposals.section_locations')     => ['projectIds', 'beneficiaries', 'beneficiariesReason', ...per-row 'beneficiaries.{id}'],
    __('proposals.section_planned_dates') => ['plannedDateBegin', 'plannedDateEnd'],
    __('proposals.section_budget')        => ['requestedBudget', 'requestedCurrency'],
    __('proposals.section_start')         => ['startingStage', 'skipReason'],
    __('proposals.section_notes')         => ['notes'],
];
```
Every `x-ui.form-section` takes its `:fields` from this map, and the error banner names the failing sections from the same map (`$failingSections`, rendered as `data-form-error-sections` with `proposals.form_error_summary_sections`). The two cannot disagree. **Anyone adding a field to this form adds it to the map**, or its section's dot will not turn red and the banner will not name it.
