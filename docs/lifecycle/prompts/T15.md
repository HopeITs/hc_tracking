## Rules
- One officer per city; one per project; assigning a different employee replaces the row. Re-assigning the same employee is a no-op (no write, no activity, no notification).
- **Writes:** `meal-coverage.manage` AND the actor is the MEAL Manager slot holder (`Slots::holderOf('meal_manager') === user's employee_id`); otherwise 403. Policy `MealCoverageAssignmentPolicy`.
- `employeeId` must be an **active** HR employee, checked server-side with a closure rule (`HrEmployee::query()->whereKey($id)->where('is_active', true)->exists()`; no cross-connection `exists:`). `cityId` must exist in HR cities. `projectId` is loaded through `Project::query()->whereKey()` with the user's visibility. `assigned_by` comes from `auth()->id()`.
- `responsibleFor()` skips inactive employees at each step. `projectsCoveredBy()` per §12.3.
- A city inactive in HR can still be assigned, with a warning. An employee who left HR: the row stays, the page shows "Responsible inactive".
- **Audit:** `TracksActivity` + `RecordsActivity`, `activityEmployeeFields()` = `['employee_id']`, events per §12.3. Register them in T21's `EventCatalog` (MEAL + GM, digest). Notifications name people only.
- **Concurrency:** one transaction, `lockForUpdate` on the existing row. A create race hits the unique index → catch `UniqueConstraintViolationException`, re-read, update (or "changed by someone else, reload").
- Writes go through Eloquent (never a query-builder upsert). No FK to HR; never write HR.
- **Module:** reuse the `cities` notification module (gated by `cities.view`) with a `ModuleRecipients` subclass naming the new, previous and governorate officers. If a new module key is unavoidable, ask first (it needs `module_icons` and `notifications:banners`, checked by `DesktopAppTest`).

UI (Cities page, `/admin/cities`):
- a "MEAL officer" field per city (grid and map detail);
- a **Project officers** section: search a project → pick any active MEAL employee; each project shows «موروث من المحافظة» / "Inherited from the governorate" or its officer;
- an assign/change modal via `wire:model`;
- warnings «المسؤول غير فعّال» / "Responsible inactive" and «المدينة غير فعّالة في HR» / "City inactive in HR", using `text-status-*` + an icon;
- coverages loaded in one query + employees in one HR query (`select([...HrEmployee::NameColumns, 'is_active'])->whereKey($ids)`). No per-card queries.

Messages (`lang/{en,ar}/cities.php`): "Choose an active employee." / «اختر موظفًا فعّالًا»; "City not found." / «المدينة غير موجودة». Event sentences in `notifications.events.meal_coverage.*` (with `_you` variants).
