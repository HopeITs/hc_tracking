## Rules
**Data model (what a cell and a total are)**
- Months come from `monthly_reports.period`, never from `created_at` or `submit_date`.
- **Center view** (no donor or proposal filter): one row per (`project_id`, `library_indicator_id`), read from `monthly_report_lines`. Target = `split`: Σ the row's targets; `shared`: the highest. The source column lists the covering proposals and donors as plain text.
- **Donor view** (a donor or proposal filter is set): one row per target (`plan_indicator`), read from that target's share mirrors in `reports`. `split` shows only that donor's share; `shared` shows the full value.
- Totals across donors always come from lines, never from mirrors. `split` 6 + 4 → center 10, donor 1 sees 6. `shared` 30 for two donors → center 30, not 60.
- Cell states, each with an icon or text, not colour alone:
  - **approved** (monthly report `validated`, normal, counted);
  - **pending** (`submitted`, shown, never counted);
  - **not submitted** (`draft`, no report, or a started month without a row);
  - **upcoming** (month not started);
  - **—** (the report exists but the indicator is not due that month, per the T33 template).
- Total: counts = Σ validated values in the window; `is_cumulative` = the latest validated value. Percentage and average rows show the pooled level through `pooledRatioSql()`/`pooledRatio()` for the row's targets (`shared`: one representative target, highest target then lowest id; `split`: all). Achieved % = total ÷ target × 100, "—" when the target is 0. Never add up the visible cells or write the formula inline in the page.
- Ratio lines without a numerator/denominator are excluded and counted beside the figure: «(n غير قابلة للتجميع)» / "(n not poolable)". Fixed-denominator percentage rows show count and percentage per month (D-25).
- The total covers the displayed 12-month window. No "includes other periods" marker (it belonged to the old model).
- No separate "periodic indicators" section: periodic MEAL indicators are template lines that appear in the months they are due.
- No money anywhere: no budget, agreement, tranche or currency.

**Month window and filters**
- With exactly one proposal filtered, the 12 columns start at its start month (`actual_date_begin` ?? `planned_date_begin`) and the year filter becomes grant year 1, 2, … (longer than 12 months picks the window). Otherwise January–December of the selected calendar year. Headings show month and year (`translatedFormat(__('formats.month_year'))`); a November start runs November → October.
- `#[Url]` filters: proposal, donor, center (project), city, indicator (library), pillar, year, "my projects" (`MealCoverage::projectsCoveredBy()`, **not** cities, D-12a), `view` (`rows`|`grouped`), `tab` (`matrix`|`activities`), `pwd` (boolean).
- Pillar: resolve pillar → program ids via the cached program lookup, then `whereIn projects.program_id`. City = `projects.city_id` against the cached HR city options. Never a cross-connection join.
- Ids are integers present in their table (`Rule::exists`), otherwise reset to "all". `year` 2020..next year, or a grant year between 1 and the proposal's length. Pass the **resolved** value to `x-ui.header-filter-select :value` and assert the label.
- "My projects" without `employee_id` or coverage: empty result with a hint, no error. A deactivated library indicator stays listed. Center label = HR center + city (T30), else the project name.

**Authorization and security**
- Route `->can('reports.view')`. `exportCsv()` calls `Gate::authorize('reports.view')` itself. Department roles see every indicator (no task scoping).
- Donor and proposal names are plain text. Link to `donors.show` only with `donors.view`, `proposals.show` with `proposals.view`, `projects.show` with `projects.view`. Pass model instances to `route()` (slugs bind, raw ids 404).
- Export: same query method, filters and visibility as the screen; all filtered rows, streamed with a generator through `CsvExport::download()`; no money column; filename `monthly-matrix-YYYY-MM-DD.csv`. Rate limit **10 per minute per user** with `RateLimiter::attempt('monthly-matrix-export:'.$userId, 10, …)` inside the action (a refusal shows a toast and writes nothing).
- Data helpers stay `protected` (`BrowserCallableMethodsTest`). Write nothing; cache nothing across requests.

**Queries (flat count, independent of row count)**
1. Rows: `plan_indicators` ⨝ `indicators` ⨝ `library_indicators` ⨝ `projects`, left-joined to `proposals` (morph key `'proposal'`) and `donors`.
2. Cells: one aggregate over `monthly_reports` ⨝ `monthly_report_lines` (center view) or the share mirrors in `reports` (donor view), limited to the window and filtered rows, grouped by row, `period`, status.
3. Cached filter options. No lazy relations. Load once, filter and page in memory.

**UI**
- `x-ui.page-header` with a row-count badge; filters via `x-ui.header-filter-select` / `-multiselect`; export button (`arrow-down-tray`) in the actions slot.
- Columns: code, name (EN), name (AR), center, source, measure, target, 12 months, total, achieved %. The table scrolls inside the panel, sticky identity columns, `table-fixed`, `tabular-nums`; numbers/codes `dir="ltr"`, names `dir="auto"`; `status-*` tokens, a legend with text. Empty result: `x-ui.empty-state` naming the filters with a clear action. stable `data-<name>` tour hooks (see `config/tour.php`) `data-matrix-table`, `data-matrix-filters`, `data-matrix-export` (T26).

**Navigation**
- Declare `Route::livewire('reports/monthly-matrix', …)->name('reports.monthly-matrix')` **before** `reports/{report}`.
- Sidebar item in the Monitoring & Evaluation group under `@can('reports.view')`. Narrow the Reports item's `:current` to `routeIs('reports.index', 'reports.show')` so exactly one item is current.

Messages (`lang/{en,ar}/reports.php`, `matrix`): empty state ("No indicators match these filters" / «لا توجد مؤشرات مطابقة لهذه المرشحات»), my-projects hint ("You have no assigned projects" / «لا توجد مشاريع مسندة إليك»), export throttled ("Too many exports. Try again in a minute." / «عمليات تصدير كثيرة. حاول بعد دقيقة»), upcoming / pending / not submitted labels.
