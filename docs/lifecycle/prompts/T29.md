## Rules
- **Secrets:** never `cat .env` or `config:show` a key; never paste one. Check production `.env` **by name** while Dev 1 reads: `APP_ENV=production`, `APP_DEBUG=false`, `APP_URL` https, `SESSION_EXPIRE_ON_CLOSE=true`, `REVERB_ALLOWED_ORIGINS` not `*`, `AUTH_TWO_FACTOR_ENFORCED` and `TRUSTED_PROXIES` unchanged, non-root DB user, mail set, `FILE_ENCRYPTION_KEY` + `FILE_ENCRYPTION_KEY_ID` present.
- **Keys:** Dev 1 generates `FILE_ENCRYPTION_KEY` on the server before the first encrypted write, **once** (a second key after encryption = data loss); two off-server copies, verified by a second person without displaying it. Never `key:generate` (breaks `users.two_factor_*`, `accounts` banking columns, sessions); APP_KEY rotation = `security:reencrypt` with `APP_PREVIOUS_KEYS`.
- **No deploy** without a restore-verified backup, the key in two off-server places, and Go. Keep backups and key copies until monitoring ends and management signs off.
- Never `RolesAndPermissionsSeeder`, `db:seed`, `migrate:fresh`, `migrate --graceful`, `key:generate`; never skip `--dry-run`.
- Placeholders only (`<app-path>`, `<backup-dir>`, `<release-tag>`, `<deployer-email>`). Each step: command, owner, expected output, rehearsal duration, "on failure → rollback step N"; total window at the top; `- [ ]` items.
- Quote the decryption-failure log message and flags **from the code** (`app/Support/StoredFiles.php`, `app/Console/Commands/`); never guess. `pail` is gone after `--no-dev`: use `tail`.
- **Phased release:** full code, every migration and command, but only the ready modules' permissions (grant later in **Admin > Users**, no second deploy). Document both variants and the smoke tests each skips.
- Acceptance: system works; 0 critical errors in 48 h; T27's POST check on `encryption_key_id IS NULL` = 0 except reported missing.

## Edge cases
- **HR unreachable:** migrations unaffected; login fails (`SyncProgramsFromHr` reports) → postpone login smoke tests; stay down or announce the delay.
- **`files:encrypt-existing` stops:** re-run (idempotent); systematic failure = trigger; past the window → T27's decision; keep clear of the 03:00 `files:prune`.
- Users mid-session see the 503 page, then a stale Livewire snapshot asks for a refresh.
- First scans after `up` may send many alerts (monthly report due, department tasks, donor-report owners, logframe missing, project start/end, templates to confirm, the backfill's grouped `monthly_reports.generated`); the ledger stops duplicates; warn MEAL and managers.
- Mail fails: in-app still arrives; retries depend on topology. Scheduled tasks skip during `down` (no `evenInMaintenanceMode`).
