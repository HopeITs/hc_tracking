> New prompt: the plan had no prompt for T33. It's on the critical path: confirming the template is what makes a project `active` (D-04b, D-39).

## Goal
MEAL decides, per project, which library indicators the center manager reports each month, with target, schedule, who enters it, and required evidence.
- On donor approval the template is **pre-filled as pending** from the proposal's targets.
- When MEAL **confirms** it, the project becomes `active` through Team A's `ActivateProject`, which triggers monthly report generation (T17).
- Later proposals on an active project add pending lines that MEAL confirms. Nothing is retroactive.

## Rules
- **Team boundary:** this task never writes `projects.status` or `proposals.status` itself. Activation goes **only** through `ActivateProject`, called inside `ConfirmReportTemplate`'s transaction. Add `ConfirmReportTemplate` to nothing: the guard allowlist names `ActivateProject`, not you.
- **Library only:** a line needs a library-linked target. Unlinked legacy targets show «اربطه بالمكتبة أولًا» / "Link it to the library first" and can't be confirmed.
- **Pre-fill** per §12.4 on `ProposalStatusChanged(to: approved)`. It's queued and idempotent (unique template per project, unique line per target). It also runs for an `active` project receiving a new approved proposal: its lines arrive `pending` and wait for MEAL (D-41).
- **Defaults per line:**
  - `schedule = library_default`;
  - `entered_by` = the library `collected_by`;
  - `fixed_denominator` = the target's `project_proposal.target_beneficiaries` when the library `denominator_basis = fixed` (warn when missing);
  - required evidence types = none (MEAL picks);
  - `effective_from`/`to` = the months of the proposal's actual dates.
- **A line whose library frequency is per-season / baseline-endline / one-time** can't be confirmed with `library_default`: MEAL must pick `selected_months` or `once_after_months` («اختر أشهر القياس لهذا المؤشر» / "Choose the measurement months for this indicator").
- **Confirm:**
  - selected pending lines → `confirmed` (`confirmed_at`/`by`); ≥ 1 confirmed line overall, else «أكّد سطرًا واحدًا على الأقل قبل تفعيل المشروع» / "Confirm at least one line before activating the project.";
  - template → `confirmed`; project `approved` → `ActivateProject`; project `active` → notify the manager with the new lines' proposal and month range (`report_template.lines_added`);
  - all in one transaction, after a `lockForUpdate` on the template and project.
- **Edits after confirmation:** schedule, evidence and `entered_by` changes save immediately and apply to **draft** monthly reports only (T17 Refresh Lines). Retire = `effective_to` = the current month. A confirmed line is never deleted.
- **Questions:** on template creation the active bank questions are copied (`monthly` + `quarter_end`); MEAL edits text/order and adds or deactivates per project. Reports keep the question text at answer time (T17).
- **Authorization:**
  - template writes: `report-templates.manage` AND (`MealCoverage::responsibleFor($project)` = the user's employee **or** `Slots::holderOf('meal_manager')`) → policy `ReportTemplatePolicy`;
  - evidence types / questions: `evidence-types.manage` / `narrative-questions.manage`;
  - line ids are loaded via `$template->lines()->whereKey()` (BOLA); a foreign id rejects the batch;
  - project managers and owners see the template read-only on the project page;
  - no money.
- **Notifications** (after commit; register the keys in T21's catalog): `report_template.pending` (the responsible officer + MEAL Manager slot), `report_template.confirmed` (owner, program manager; MEAL + GM oversight), `report_template.lines_added` (owner).
- **Org-wide (D-44):** `annual-plans:ensure-2026 {--dry-run}` creates a 2026 annual plan per program when missing (2026 only, idempotent). MEAL enters yearly per-center targets for `HC.*` entries there (existing annual-plan target UI); pre-fill also creates pending lines for the project's `annual_plan` targets of `HC.*` entries.
- **Launch (D-45):** `report-templates:prefill-active {--dry-run}` creates pending templates/lines for projects already `active` (they stay active; no activation call). It prints created/skipped per project and lists (ids only) the `fixed`-basis lines missing `fixed_denominator` (a NULL `project_proposal.target_beneficiaries`, D-25); T27 checks that list is empty or accepted before go. T27 runs it.

Messages (`lang/{en,ar}/report_templates.php`): the three above, plus "This template was changed by someone else. Reload." / «عُدّل هذا القالب من مستخدم آخر، أعد التحميل».
