## Rules
- Seed the six starting sectors (D-47): Health / الصحة · Food security & livelihoods / الأمن الغذائي وسبل العيش · WASH / المياه والصرف الصحي والنظافة · Shelter & NFIs / المأوى والمواد غير الغذائية · Protection / الحماية · Education / التعليم. Idempotent by a stable key; a data migration too, so production gets them.
- **Managed** by `sectors.manage` (MEAL, GM) at `/admin/sectors` (`admin.sectors.index`), viewable with `sectors.view`. `name_ar` required, `name_en` optional, `sort_order`.
- **A used sector** (any `project_sector` row) can't be deleted, only deactivated. A deactivated sector stays on existing projects with an «غير فعّال» / "Inactive" badge and isn't offered for new selection.
- `SyncProjectSectors`:
  - `Gate::authorize('update', $project)`;
  - ids must be **active** sectors (an inactive one already linked may stay);
  - ≥ 1 is required when called for a new project (`$requireOne` flag passed by T05);
  - records `project.sectors_changed` with names only.
- `<x-projects.sector-picker wire:model="sectorIds">`: a multi-select of active sectors (via `x-ui.multi-select-popover`), with linked inactive ones shown with the badge. **Do not edit the project form**: T05 includes the component. If T05 merged first, add the component to its form in the same PR, with Dev 1's review.
- **Display:** sector chips on `projects/⚡show`; a sectors column + `x-ui.header-filter-select` filter on `projects/⚡index` (loaded once, filtered in memory, flat query count).
- No money; no notifications beyond the activity entry (register `project.sectors_changed` in T21's catalog as digest).

Messages (`lang/{en,ar}/sectors.php`): "Choose at least one sector." / «اختر قطاعًا واحدًا على الأقل»; "This sector is in use. Deactivate it instead." / «هذا القطاع مستعمل، أوقفه بدل حذفه».
