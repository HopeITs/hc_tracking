# T17A · Monthly report backend: generation, template lines, workflow, pooling · B1 · days 7–11 (contract frozen at CP3, day 9) · 4 slices

## Goal
One `draft` monthly report per project per month, generated when the project becomes `active`. Its **lines come from the project's confirmed T33 template** (D-38). The center manager fills and submits it. The responsible MEAL officer validates or returns it, and never edits the manager's figures. A validated report reopens only through a request decided per D-09a. Figures reach `reports` as **mirrors**, so `PlanIndicator::achievedValue()` stays the one achievement definition. T17B builds the pages; T18, T19 and T21 read validated mirrors and `pooledRatioSql()`.
- **Slice 1 (day 7):** schema, enums, models, factories, `MonthlyReportPolicy`.
- **Slice 2 (day 8):** generation listener, line builder, `monthly-reports:prepare` / `backfill`, `MonthlyReportPeriods`.
- **Slice 3 (day 9, CP3):** line/share/breakdown save, submit / validate / return / reopen, mirrors, `pooledRatioSql()`; writes `handoffs/T17A.md`.
- **Slice 4 (days 10–11):** activities this month, answers, typed evidence files, alerts, catalog keys.

## Rules
- **Schema** exactly per §13; user FKs `restrictOnDelete`. No narrative columns on `monthly_reports`: narrative is `monthly_report_answers` (D-43a). `reports.value` nullable (docblock: `down()` fails once NULL rows exist). New enums: `MonthlyReportStatus` (`mirrorStatus(): ReportStatus`, `isEditable()`), `ReopenRequestStatus`, `Gender`, `ActivityStatus` (`allowedFor(ActivityKind)`, `isFinal()`). Morph key `monthly_report`; `MonthlyReport` has `HasSlug` (project slug + `Y-m`) and `TracksActivity`.
- **Lines of M** per §13, grouped by library indicator, one share per covering target in **both** modes. Target window = proposal actual dates, or the annual-plan year for `HC.*` targets: extract `ManagesReportForm::coverableWindow()` into one place on `PlanIndicator`, used by both. A line is `meal` when any of its template lines is; line `fixed_denominator` = Σ shares (`split`) or the highest (`shared`) (§13.1 item 1). A month with no line still exists (D-05: activities and answers).
- **Line builder** (internal; name it in the handoff) is used by `prepare`, `OpenMonthlyReport` (prepares any started month) and `RefreshMonthlyReportLines` (draft only; adds lines/shares, removes none).
- **Mirrors** per §13, plus: `planned_date` = last day of M, `period_start`/`period_end` = month bounds; created with the first write to the share's figures (`user_id` = the actor), and Submit creates any missing; `submit_date` = today on submit, NULL on return/grant. Set `planIndicator.indicator` before saving (strict mode). Mirror writes run under `Activity::withoutRecording`: one transition, one activity.
- **Entry** per §13 Entry and D-50: the server computes every value and total; `shared` → entered once, copied to every share; `split` → per share. Shares load via `$line->shares()->whereKey()`, breakdowns via `$line->breakdowns()`; any foreign id rejects the batch.
- **Every move:** `expectedStatus`, one transaction, `lockForUpdate()`, re-authorize on the locked row; stale → no write.
- **Submit:** not before `WorkingCalendar::lastWorkingDayOnOrBefore(end of M)`; the **nearest earlier month with lines** must be `submitted`/`validated` (D-08); manager lines complete (`meal` lines exempt); required evidence present; no partial submit.
- **MEAL lines (D-48a):** filled or marked Not measured by the validator while `submitted`; they block Validate. The manager editing one → 403.
- **Validate** → mirrors `approved`, `project_activity_statuses` written. **Return** (reason ≥ 10) → draft, `returned_*`; no activity status. **Reopen**: request by the preparer side (reason ≥ 10, one pending); grant → draft (figures leave achievement, activity statuses restored); deny needs a note. **Mark seen** (`reports.mark-seen`) stamps `seen_by_meal_at` once. **Delete**: a never-submitted draft without requests; its files leave disk after commit. Requests are never deleted.
- **Generation:** on `UniqueConstraintViolationException` return the existing row. A month not started is never due or overdue.
- **Who:**
  - preparer side = `reports.create`/`update` AND (`in_array($project->id, $user->ownedProjectIds(), true)` OR a `SupervisionMap::supervisorsOf()` hit when T23 is merged). An owner whose HR position is at another center gets a warning (`MonthlyReportPeriods::ownerCenterMismatch()`), never a refusal;
  - validator = `reports.approve` AND (employee = `MealCoverage::responsibleFor()`, or the MEAL Manager slot holder, or any MEAL role holder **only when** `responsibleFor()` is null) AND not `prepared_by`/`submitted_by`. **GM never validates.**
  - decider (D-09a) = `reports.reopen` AND (the active MEAL Manager slot holder, else active PR Manager holders), never the requester or preparer. Neither → pending + GM notified. Super Admin is never the tested path (D-20a).
- **Generic Reports:** `ReportPolicy::update/submit/approve/returnToDraft/delete`, `SaveReportFile`, `DeleteReportFile` refuse mirrors (`monthly_report_id` not null).
- **Pooling** per §13: `pooledRatioSql()` + `pooledRatio()` over approved `reports` rows in the window. After CP3 sign-off, propose a `record-rule` on `resultsindicatorstargetsreports.md`: pool only through it.
- **Activities (D-51)** per §13; return planned weeks (D-49b) and the carry-over start month. On Validate, store each row's previous state in the `monthly_report.validated` activity properties; a grant restores it.
- **Answers:** active template questions, `monthly` every month, `quarter_end` in Mar/Jun/Sep/Dec (§13.1 item 3); text copied at answer time; optional on submit.
- **Evidence (D-42):** `StoredFiles`, `SecureUpload`, 5 MB, `FileType`, an active evidence type; Submit needs the union of the line's required types; Completed/Conducted need a file on the entry. Draft only (validator on `meal` lines while submitted).
- **Commands** per §13 (`prepare` in `routes/console.php`; `backfill` prints created/skipped per project).
- **Notifications** after commit via `ActivityRecorder`, never per line, no amounts. Module `monthly-reports` (`modules`, `view_permissions` => `reports.view`, `module_icons`), `MonthlyReportRecipients`, `events.monthly_report.*`. Submit → `responsibleFor()` + slot (else MEAL role holders, via `EmployeeRecipients::usersFor()`); validate/return → preparer + submitter; request → deciders (else GM, key `monthly_report.reopen_escalated`); decision → requester. Catalog keys (§13, §15.2) in `EventCatalog` with MEAL + GM oversight; no T21 yet → list them in the handoff for Dev 3.

## Do not
Build lines from targets or library frequency directly. Compute achievement or pooling anywhere else. Let MEAL change manager figures, or the manager change `meal` lines. Allow partial submit or mixed mirror states. Trust ids, statuses, the preparer or `plan_indicator_id` from the request. Let GM validate. Notify inside the transaction or once per line. Delete a submitted report or a reopen request. Use bare `startOfWeek()` or literal day counts.
