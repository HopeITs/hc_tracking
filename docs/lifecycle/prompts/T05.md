# T05 · Project as a dateless draft; project statuses v2 · Dev 1 · days 7–8

## Goal
The project side of `contracts.md §3` becomes true and tamper-proof:
- A new project is a `draft` with no dates (inputs not rendered, dates refused).
- `draft → approved → active` happens **only** automatically (T08 / T33); `approved` is a live project status again, and the duplicated `submitted` disappears.
- `active → closed` goes through `CloseProject`.
- Restore follows D-27.
- One open project per (center, program) is enforced everywhere.

## Rules
- Close: `ProjectPolicy::update` (projects.update holder, owner or program manager), only from `active`; `Gate::authorize` inside, `lockForUpdate`, state re-check.
- After activation, dates may be edited by `ProjectPolicy::update` with the existing "exceeds grant period" warning. The owner-rejection lock (ASG-03) is unchanged.
- Drafts produce no date-based alerts (`DeadlineCatalog` skips NULL dates); `DataGapScanner` stays on `active`. A draft and an approved project count as open in **Executive Summary**.
- Existing drafts with dates (none locally): report the ids, don't null them; list them for T27.
- A tampered `cityId`, `startDate`/`endDate` on a draft, or `projectStatus` (`approved`/`active`) fails server-side; hiding an input is not protection. The saved city is always the centre's.
- Two users close the same project, or close while an archive runs: lock the row and refuse unless it is still `active`; the second call writes nothing.
- Draft with dated milestones (early planning) is allowed: the **Plan** tab shows `plan_after_approval` and still lists the milestones (the Gantt tolerates NULL project dates).
- `approved` shows the «ممول، بانتظار نموذج التقرير» / "Funded, awaiting report template" badge (`x-ui.enum-badge`) in lists, filters, lenses, counts, charts and the lifecycle bar, and is never selectable.
- Status changes are logged by `RecordsActivity` (`project.status_changed`); do not bypass Eloquent for user-facing writes.
