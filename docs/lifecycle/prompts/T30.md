## Scope
**In:**
- `App\Models\HrCenter`, `HrJobLevel` (extend `HrModel`; explicit columns; `options()` via `RemembersHrLookup`). `HrPosition` relations `center()`, `jobLevel()`, `city()`, `directManager()`.
- `App\Support\EmployeeProfile` with **exactly** the §10 API (`for`, `employeeIdsAtCenter`, `employeeIdsInDepartment`, `managerOf`, `holderOfPosition`). It's cached per running app (refreshed after 60 s or on an unknown id) and uses 1–2 HR queries.
- Migration `add_center_id_to_projects_table`: unsigned big int, nullable, indexed, **no FK**. `down()` drops the index then the column.
- `Project`: `center_id` in `#[Fillable]`, `center()` resolved through the lookup, `Project::openProjectFor(int $centerId, int $programId, ?int $exceptId = null): ?Project` (open = draft/approved/active; until T05 lands, use the statuses `ProjectStatus::isOpen()` returns).
- Project create form: a required **Center** picker (active centers, current-locale label) replaces the free city choice. `city_id` is written by the server from the center. The default name is «{Program} — {Center}» (editable). A second open project for the same (center, program) is refused under a lock.
- Command `hr:map-project-centers` (`--dry-run` default, `--apply`, `--force`): proposes a center per project by matching (`city_id`, `program_id`) against `positions.center_id`. It prints matched / ambiguous / no-center tables plus a **duplicated `programs.code`** table (D-10a) and the presence/codes of Wells, Alternative Energy, PSS & Case Management, Parenting (D-35a). It's idempotent and never overwrites without `--force`.
- `x-ui.employee-chip` and the employee picker show position, job level, department and center.
- Lang keys in `lang/{en,ar}/projects.php`.

**Out:** writes to HR; `center_id` NOT NULL (later); project status/dates (T05); renewal (T10); MEAL coverage (T15); supervision (T23).

## Rules
- No `save()`/`delete()` on HR models. Copy no HR name, title or center name into tracking tables.
- Current position = the active contract; several active → latest `start_date` + logged warning; none → `null` and shown as inactive in new pickers.
- **Never select** `contracts.salary`, `currency`, contract type or `*`; every HR query lists its columns. Resolve ids on `hr` first, then `whereIn` on tracking tables. No cross-connection `whereHas`.
- Project city = center city, always. An inactive center already linked may stay (badge "Inactive center"), but it can't be chosen for a new project.
- HR unavailable: show the id with «تعذّر تحميل بيانات HR»; pages don't break.
- Projects in cities without a center keep `center_id = NULL`, with an admin-visible warning listing them.
- Messages: `centerId` required/exists/active «اختر المركز» / "Choose the center."; duplicate «للمركز مشروع مفتوح لهذا البرنامج: {name}. أضِف مقترحًا جديدًا عليه بدل إنشاء مشروع» / "This center already has an open project for this program: {name}. Add a new proposal to it instead."
