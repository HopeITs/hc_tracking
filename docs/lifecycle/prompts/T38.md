# T38 · Back link on nested pages · Team B · Phase A (meeting 23 Oct) · 0.5 day · 1 slice

## Goal
Every detail page (project, proposal, donor, agreement, monthly report, donor report, indicator, milestone, …) shows one **Back** control that returns to its parent in the hierarchy, not `history.back()`: from a project to the projects list, from a monthly report to its project (or the monthly reports list), from a proposal tab to the proposal. It is the first breadcrumb step made explicit, with an arrow that flips in RTL.

## Scope
**In:** a `back` slot/prop on `x-ui.detail-header`: when `breadcrumbs` has ≥ 2 entries, the header renders a link to the **last crumb that has a url** (label "Back to {label}", `wire:navigate`, `flux:icon.arrow-left` with `rtl:-scale-x-100`), above the breadcrumbs on mobile and inline with them on desktop; an explicit `:back="['label' => …, 'url' => …]"` prop overrides it; pages without breadcrumbs get them (parent list route). `data-back-link` hook.
**Out:** browser history navigation, a global header back button, changes to page content or tabs.

## Rules
- One implementation in `detail-header`; no page renders its own back link.
- The target is **deterministic** (the hierarchy), never the referrer. A proposal tab deep link (`?tab=plan`) goes back to the proposal, then to the proposals list.
- Labels from `lang/{en,ar}/ui.php` (`ui.back_to`), placeholder-safe for Arabic.
- Logical classes; the icon flips in RTL; touch target ≥ 44 px on mobile.
