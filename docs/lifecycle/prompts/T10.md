# T10 · Renewal = new proposal on the same project; duplicate detection; history · B3 · days 7–8

## Goal
A renewal never creates a project (D-30): it's a **new proposal on the same project**.
- **Start from Previous Proposal** clones last year's proposal into a fresh `concept note`, linked via `proposals.previous_proposal_id`, with last year's achievement shown beside targets as a reference only.
- Creating a project for a (center, program) that already has an open one is refused, with **Add a proposal to it**; similar names in other centers only warn.
- The Proposal page shows the previous ← current → next chain; the Project page shows the **Funding history**.

There is **no** `projects.previous_project_id` and **no** `CreateRenewalProject`.

## Rules
- **Never copied:** status (always `concept note`, first note by `SaveProposal`), actual dates, files, agreement, reports, reviewers, deliveries (`delivered_*`, delivery files), monthly reports, transfers, targets as commitments.
- **Copied:**
  - donor, linked projects, notes, planned duration (as editable planned dates), `target_beneficiaries` per project (editable);
  - the framework and its indicators via `CopyResultTree` (fills `copied_from_id`, remaps parents, never copies targets/reports) — **no second tree-copy routine**;
  - milestones and department tasks with planned dates only and statuses reset, with `copied_from_id`;
  - `previous_proposal_id` → the source.
- A linked project whose HR center is inactive → skipped and named. An inactive library indicator → skipped and named.
- If the previous proposal's project is closed and its (center, program) now has another open project, link the **open** project instead and say so in the result message.
- **Last year's achievement** = the previous proposal's targets matched by library indicator + project, read through `achievedValue()`/`percentAchieved()`. Expose `PlanIndicator::previousYearReference(PlanIndicator $target): ?array{value: ?float, percent: ?float}` for T13.
- The clone needs a new unique `internal_project_number` (existing rules); it never saves silently. It goes through `SaveProposal`, so `proposal.created` fires once (its activity properties carry `renewed_from` = the source id).
- **Authorization:**
  - `Gate::authorize('create', Proposal::class)`; the previous proposal must pass `Gate::allows('view', $previous)` (reloaded); projects are read from its relation, not the request;
  - copying the framework needs `results.create`, the plan needs `milestones.create`/`tasks.create` (or `proposals.update`); without them that part is skipped, with a message.
- **Similar Projects** and **Funding history** show names, center, program, donor name and status only.
- **Idempotency:** a double click returns the existing draft (key = `previous_proposal_id` + the same user's `concept note` clone within 2 minutes). Without a creator column, use `Cache::lock` keyed by user + source. Two different users → two drafts; the second sees "a renewal draft already exists: {number}".
- One transaction for the whole clone; any failure rolls everything back. HR data is read through `HrCenter`/`EmployeeProfile` with one batched lookup; never copied; no cross-connection `whereHas`.
