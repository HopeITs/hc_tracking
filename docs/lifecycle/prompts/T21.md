## Rules (both slices)
- **Oversight** = MEAL (role `MEAL` holders + the project's officer `MealCoverage::responsibleFor($project)` mapped through `EmployeeRecipients::usersFor()`, D-12a) and Management (role `General Manager` + roles added in settings). The officer is added only when a project is known; otherwise MEAL role holders only. **Super Admin never enters oversight**, not by role and not by a setting (D-20a).
- **Modes** (`OversightMode`): `all` = MEAL + management; `management_only` = management only (`transfer.*`); `none`. Department-task events: only `department_task.overdue` is `all`, the rest `none`.
- **Importance** (`EventImportance`): `immediate` = sent now; `digest` = direct recipients get it now, oversight recipients get it in the next daily oversight summary.
- **One notification per person**: direct + oversight collapse to one (direct wins). The actor never hears about their own action (`RecipientFilter`).
- **Oversight never bypasses the module view permission**, never widens a module's watcher roles, and is a separate layer in `OversightRecipients`. Oversight users are non-direct, so mutes apply; **direct** recipients of `critical` keys are never muted.
- **Money:** no amounts, budgets or currencies in any payload, in-app text or email (the monthly digest has none for anyone).
- **Ledger:** keys include the event, the subject and the date or month; in-app and mail use separate rules so each channel is idempotent alone.
- **Working days only** (`WorkingCalendar`; per-project days D-22 via `WorkingCalendar::forProject()`, which **this task delivers in slice 2a**, §9; project-bound scanners use it, the rest the global calendar): an event dated on a non-working day goes out the next working day; scanners catch up every date since the previous working day.
- **Settings overrides** (`NotificationSettings` key `event_overrides`: `array<string, array{enabled?: bool, importance?: string, oversight_roles?: list<string>}>`): a disabled event sends nothing but stays in the catalog; an unknown key or a deleted role is ignored safely and the settings page warns. The page writes only overrides; defaults live in `config/notifications.php`.
- **Keys are stable strings.** Never rename after CP0 without both teams and a `contracts.md` change.
- Recipients come from roles, slots, module maps, HR links and settings, never from names.
