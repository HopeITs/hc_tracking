## Rules
- **Start:** every new proposal starts at `concept note` (first note = `__('proposals.proposal_recorded_note')`). A `proposal draft` start requires a skip reason (min 10): create at `concept note`, then call `TransitionProposal` (`→ proposal draft`, reason) **in the same transaction**. That gives two notes. No form writes status.
- **Donor:** one, required. Editable only while `concept note` / `concept note review` and no agreement exists; locked after that (the composite FK is the backstop). Never mass-assigned.
- **Linkable projects:** `draft`, `approved`, `active` or `closed`; not owner-rejected; visible to the user; never `archived`. Linking a `closed` project calls `ReopenProjectAsDraft` (lock the project → `openProjectFor` must find none → `draft`, dates cleared; history stays in Activity Log) in the same transaction.
- **Beneficiaries (D-25):** per linked project, `target_beneficiaries` (integer ≥ 1; nullable at `concept note`; required from `proposal review` by T04's gate). After `approved`, only `proposals.update` holders change it, with a logged reason and event `proposal.beneficiaries_changed` (MEAL notified). Sent reports are not recalculated.
- **Unlink:** refused for the last linked project, or when that project has targets of this proposal that already have reports. Targets without reports → list them and ask to confirm; after unlinking they remain, flagged inconsistent (existing behaviour).
- **Edit Proposal** does not change links; links are managed from the proposal page's projects panel. Actual dates are not in the form (T08 sets them).
- **Linking from the project page** needs `proposals.update` (same actions), like the proposal page.
- **Money:** budget fields are rendered and saved only for holders of `funding-agreements.view`/`transfers.view`/`accounts.view`, decided from the acting user. Otherwise a submitted budget is ignored and the existing value kept. No amount in toasts, activities or notifications.
- **Authorization:** create `proposals.create`; edit/link/unlink `proposals.update`, through `ProposalPolicy` + `Gate::authorize` in each action. Submitted project ids are validated against the same server query (`Rule::exists` + status + owner-rejected conditions). Unlink loads through `$proposal->projects()->whereKey($id)`.
- **Activity:** `proposal.project_linked` / `proposal.project_unlinked` recorded explicitly (`recordActivity`, pivot writes fire no model events), names only.
- "Unfunded" on the projects page stays measured by the proposal link (`doesntHave('proposals')`).

Concurrency: keep the internal-number `UniqueConstraintViolationException` handling (around `SaveProposal`; a second save surfaces the field error, not a 500). `UnlinkProposalProject` locks the proposal and recounts. Two proposals linking the same closed project → lock the project and the center's open projects; the second one finds it `draft` and just links, or is refused. A `proposals.create` holder without `proposals.update` choosing `proposal draft` → the whole save is refused, nothing half-created.
