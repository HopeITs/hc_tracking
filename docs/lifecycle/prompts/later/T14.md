## Goal
When a program has no **program-level** framework and work is attached to it, MEAL gets one clickable, de-duplicated alert. It links to `/results?program={id}&create=1`, which opens the create form for that program.

## Rules
- "No framework" = no `results` row with `program_id = X` and `proposal_id IS NULL`. A program with only proposal frameworks still has none.
- **Triggers (one notifier `App\Notifications\Alerts\LogframeGapAlert::notify(list<int> $programIds): int`):**
  1. `SyncProgramsFromHr` dispatches the check for the ids `syncFromHr()` newly inserted (`syncFromHr()` returns them and stays silent; seeders never notify);
  2. `SaveProject` (T05) dispatches `CheckProgramLogframe` `->afterCommit()` on create or program change. **No new `ProjectObserver`**; Dev 1 reviews the one-line hook;
  3. a daily rule in `DataGapScanner`: programs with open projects and no program framework, skipping non-working days.
- **Ledger:** rule `logframe_missing`, subject `program:{id}`, stage `logframe`. One alert per detection; `AlertLedger::release()` when the framework appears, so a later deletion re-alerts. Overlapping runs are safe (`claim()` is atomic).
- **Recipients:** MEAL role users + the MEAL Manager slot holder; only `results.view` holders (payload module `results`, so `RecipientFilter` applies). No recipient logic in `RecipientResolver`. Priority Important. Ten programs in one sync → one grouped notification per recipient with the count, linking to `results.index`.
- **Catalog:** `program.logframe_missing` in `EventCatalog` (digest for MEAL + GM).
- **Deep link:** `program` must be an existing id and `create` must equal `1`; the modal opens only when `Gate::allows('results.create')`; anything else is ignored.
- Messages: `notifications.alerts.logframe_missing.single` / `.grouped` in `en` + `ar`. No money, no project lists.
