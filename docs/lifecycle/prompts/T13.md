## Rules
- Keep the tab key `targets` (deep links use it); relabel it **Indicators & Targets**.
- **Attach:**
  - the library entry is active and belongs to a program of the proposal's projects, or is institutional («هذا المؤشر لا يتبع برنامج هذا المقترح» / "This indicator doesn't belong to this proposal's program");
  - the result is in this proposal's framework, at a compatible level (= `suggested_level` when set);
  - this creates an `indicators` instance (name from the library, `code` copied, `measure` mirrored, `frequency` mapped `CollectionFrequency → Period`: monthly/quarterly/semi-annual/annual map 1:1, others fall back to the column default);
  - the same entry twice under one result → "already attached" (unique `(result_id, name)`), not a 500.
- **Picker:** grouped by program (separate headings for a two-program proposal), sorted by usage in that program's projects, searchable in AR/EN (`Like::contains`). It shows `collected_by`, `frequency`, measure and unit beside each entry. **Add to Program Library** creates an entry via T11's `SaveLibraryIndicator` (MEAL) and gets the next code.
- **Library link:** an instance without `library_indicator_id` (legacy) can never enter a monthly report template (T33). Show «غير مرتبط بالمكتبة» / "Not linked to the library" on such rows, with a link for MEAL to fix it.
- **Donor commitment:** each proposal target (`plan_indicators` row) is that donor's commitment. T33 reads it as a suggestion and never overwrites `plan_indicators.target`; nothing in this task writes template data. The same indicator for two donors stays two rows. A target is a single total (D-50a: no per-gender targets; achievement is shown disaggregated next to it).
- **Detach:** only without `plan_indicators`; otherwise refused with the count (`trans_choice`, Arabic plural ranges).
- **Grid:**
  - rows = instances in this proposal's framework; columns = linked projects, labelled with **HR center name + city** (fallback: project name); cell = value + period;
  - once a target has reports, its indicator and source are locked; value and period stay editable;
  - validation: `value` nullable, numeric, min:0, max:9999999999.99 (`decimal(12,2)`) — «القيمة لا تكون سالبة» / "Value cannot be negative"; `period` required with a value, `Rule::enum(Period::class)`;
  - empty = no target, `0` = zero target; percentage ≤ 100 (0–100, never 0–1) — «النسبة لا تتجاوز 100» / "A percentage cannot exceed 100"; average uncapped (library unit shown);
  - percentage cells show beneficiaries and the derived figure («80% × 180 = 144»), with the badge «أدخل عدد المستفيدين في المقترح» when `target_beneficiaries` is missing;
  - every cell passes `chainIssuesFor()` (reject only the issues the save introduces);
  - clearing a saved cell deletes it only when it has no reports and the user holds `targets.delete`, otherwise the batch is refused;
  - suggestions (last year's achievement on renewal (T10), the framework default from T32 (`copied_from_id`)) are shown in a distinct style and saved only when MEAL confirms;
  - D-37 symbols: `-` → tracking-only (no row, value without %); `**` → required before `submitted` (warning only at `concept note`).
- **Center total** beside an indicator repeated across donors on the same center: `split` → sum, `shared` → highest (display only).
- **Status:** editable in every non-terminal status from `concept note`; read-only for `rejected`/`completed`.
- **Authorization:** attach `indicators.create`; detach `indicators.delete`; grid `targets.create/update/delete` per cell (MEAL only, D-23). `proposals.update` alone grants nothing; GM, Managers and program managers see read-only (buttons hidden **and** 403).
- **BOLA:** results via `Result::where('proposal_id', $p->id)->whereKey()`, projects via `$proposal->projects()->whereKey($ids)`, targets via `source_type='proposal'` + `source_id`. Any foreign id rejects the whole batch.
- **Concurrency:** one transaction; lock the proposal row; compare each cell's loaded `updated_at` (`version`) with the stored one. Any stale cell → **reject the whole batch** and flag the stale cells «عُدّلت هذه القيمة من مستخدم آخر» / "Another user changed this value; reload." A double submit writes nothing new.
- **Writes** go through Eloquent (`firstOrNew` + `save`), never `DB::table()->upsert()`. One digest event `proposal.targets_saved` per save (register in T21's catalog). Default: keep the per-row activities (`Indicator`/`PlanIndicator` already track activity); raise in plan mode whether the volume calls for a quiet batch (`Activity::withoutRecording`) with only the summary event.
- Achievement only via `achievedValue()`/`percentAchieved()` with `reports` + `indicator` eager-loaded. No money in the tab.
- Project unlinked after targets: the rows stay, flagged inconsistent.
