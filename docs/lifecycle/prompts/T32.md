## Rules
- **Pillar mapping (D-35a),** matched by **HR program id**, never by name text. Missing programs are listed in the command report and stay "No pillar":
  - Pillar 1: Micro, Relief Programs, Family to Family, Wells, Alternative Energy;
  - Pillar 2: Study Zone, LEAP, Entrepreneurship project, DISC (Development Impact and Support Center);
  - Pillar 3: Children University, PSS & Case Management, Parenting.
- Hope Center, Earthquake Assistance, School to School, Homework Room, Sha8er and CYG stay unassigned. Before assigning, call `Program::syncFromHr()` if a program is missing locally.
- **Import → codes (D-10):** every indicator becomes a library entry **of that program** with `level_ref` from the node type + number (`G`, `OC`, `OP`, `AC`, `CC`) and a code from `IndicatorCode::next()`. Both Micro tracks share program code `002`. Serials continue within the level, so codes never collide. The same indicator in both tracks (same name + measure) is **one** entry. **No hand-made prefixes** like `MIC-U.`.
- **Idempotent by code:** re-import updates an entry unless it was edited by hand after the last import (`updated_at > imported_at`). In that case, report a conflict and leave it.
- **Default targets (D-37)** → stored on the program framework's `indicators.target`:

  | Source | Becomes |
  |---|---|
  | `0.8` | `80`, measure `percentage` |
  | `-` | target NULL, `is_tracking_only = true` |
  | `**` | target NULL (set per proposal) |
  | `زيادة 20%` | `20`, `percentage`, note "change from baseline" (`indicators.baseline` is set by MEAL) |
- **Structure:**
  - Goal = an `impact` root per track. The activities column is split on `+` into `activity` results under the matching output (`activity_kind` continuous), with no indicators.
  - The agricultural sheet's cross-cutting rows → a `cross-cutting` root with CC1, CC2, CC4.
  - Placeholder Micro results already in dev data (results 3, 4, 29–31) are neither touched nor deleted; list them.
- `name_en` is left empty; MEAL completes it in the library.
- **CopyResultTree:**
  - copies the subtree and its indicators (never `plan_indicators` or reports) into the proposal framework, remapping parents (parents before children, old→new map);
  - sets `copied_from_id` on every result and indicator; points the new root's `contributes_to_result_id` at the source root (not for cross-cutting);
  - allowed only before `submitted`; the same root twice into one proposal → «هذا الإطار مستورد مسبقًا في المقترح» / "This framework was already imported into the proposal.";
  - one transaction, batched inserts, a query count independent of node count; lock the proposal row and re-check the "already imported" rule inside the transaction.
- **Authorization:**
  - pillar CRUD and assignment: `Gate::authorize` on `strategies.update`; view on `strategies.view`;
  - copy: `results.create` + proposal visibility. Re-check that `sourceResultId` is a **program-framework root** (`proposal_id IS NULL`, `parent_id IS NULL`) of a program of the proposal's projects; any other id is rejected (BOLA) with «اختر إطارًا من برامج مشاريع هذا المقترح» / "Choose a framework from the programs of this proposal's projects.";
  - a multi-program proposal can copy one root per program;
  - commands are console-only.
- Each import runs in one transaction per file, under `Activity::withoutRecording`, and prints created / updated / conflicts.
- Validation: `name_ar` required max:255; `name_en` null max:255; goals max:2000; `code` required max:20, unique per strategy; the pillar is from another strategy → «المحور من استراتيجية أخرى» / "The pillar belongs to another strategy."
