# T31 · Proposal as planning container: milestones and department tasks · B3 · days 4–6 · 2 slices

## Goal
From the first draft (`concept note`), a proposal holds its **milestones** and the main **Media and Finance department tasks** on a **Plan** tab. Each department sees its tasks on a no-money **Department Tasks** page. On donor approval, the plan's planned dates shift once to the real grant period. Media deliverables (old T20) are `tasks.kind = media_deliverable`: there's no separate table and no `media-deliverables.*` permission.
- **Slice 1 (days 4–5):** schema, enums, actions, visibility, the rebase listener.
- **Slice 2 (day 6):** Plan tab, Department Tasks page, Gantt, alerts.

## Rules
- **Editing windows:** add/edit from `concept note` until `submitted` with plan rights (`proposals.update` or `milestones.create`/`tasks.create` + proposal visibility). After approval, normal execution rights (`milestones.update`/`tasks.update`).
- **The Plan tab replaces** the proposal page's existing `tasks` tab: one tab, grouped Milestones / Media / Finance / Other. Keep `?tab=tasks` deep links working with a redirect to `plan`.
- **Department first (D-33):**
  - `department_id` is required (an existing HR department);
  - a person is optional (set by the department head or a `tasks.update` holder); due within 7 working days and no person → alert;
  - department removed in HR → «قسم غير متاح» and alerts go to the proposal owner.
- **Media deliverables:**
  - `requested → delivered` needs `delivered_on` ≤ today plus, per `media_kinds`, a file / link (video = link only) / text;
  - `delivered → accepted | returned` (reason required); `returned → delivered` again;
  - tasks of a rejected proposal stop alerting.
- **Financial tasks:** Finance only; titles carry no amounts.
- **Final report (D-02):** the **Final Report** milestone template in **Add Milestone** (with a PR task) is the only way to create an `is_final_report` milestone; one per proposal. T04's completion gate reads it.
- **Rebase on approval:** a queued, idempotent listener `RebaseProposalPlanOnApproval` on `ProposalStatusChanged` with `to = approved`. It reloads the proposal and its approval status note, locks the proposal, and checks the `proposal_plan_shifts` ledger (unique `approval_note_id`). It shifts milestones' and tasks' planned dates by delta, clips them to `actual_date_end` (notifying the proposal owner with the clipped list), and skips rows whose `planned_dates_edited_at` is set. Activity Log entry with the system actor. A failure never touches the approval.
- **Visibility (§12.2):** extend `TaskVisibilityScope::constrain()` **and** `allows()` identically. Prove that nobody else gains visibility.
- **Media sees** proposal name, description, its tasks and milestones only: no money, no `proposals.view` shortcut (D-16). **Department Tasks** never queries budget, agreements, transfers or currency, and links to `proposals.show` only for users who can view it.
- **BOLA:** load via `$proposal->milestones()->whereKey($id)` and the scoped task query; a foreign id → 403/404 with no write.
- **Files:** `SecureUpload`, 5 MB, `FileType`, `UploadName`, `StoredFiles` (T22's encrypted write if merged); downloads through an authorized route with `throttle:files`.
- **Alerts:** on create (department head + members), due-soon in working days (`NotificationSettings`, default 5), overdue; `DeadlineCatalog` entries with ledger keys including `due_date`. Event keys `department_task.created|due|overdue|delivered|returned` in T21's catalog (direct: department, assignee, requester; MEAL + GM on overdue only).
- **Gantt (D-05):** a per-proposal Gantt on the Plan tab; an overall Gantt on the Project page with an "all proposals / one proposal" filter and a colour per proposal, reusing `x-ui.gantt`. Activity rows are coloured by their status, with weeks when `activity_schedules.weeks` is set (T12).
- **Draft deletion:** `DeleteProposal` (T12) removes the draft's milestones and tasks in its transaction. Provide `App\Actions\Proposals\DeleteProposalPlan::handle(Proposal $proposal): void` for it to call.
