## Rules
- **Read only:** no migrations, writes, observers, routes or events.
- **One builder:** `App\Support\ResultsChain::build(…)` returns node arrays for all three pages. Components render no queries. Load once per page (results of the scope; indicators with library entries; plan indicators with `reports` + `indicator`; projects; milestones with `result_id`; proposal/donor names for contributions), then shape in PHP. **Flat query count** independent of node count. Lineage comes from eager-loaded `parentRecursive` or the in-memory parent map; never `ancestors()` per node.
- **Achievement** only via `achievedValue()`/`percentAchieved()` (approved reports only). Percentages are never summed across centers or donors; totals are per target.
- **Weighted milestone progress:** the existing formula (reached weight ÷ weight of non-cancelled milestones).
- **Pages:**
  - proposal Logical Framework tab: its framework;
  - program page: the program framework, with proposal contributions under the result each proposal root contributes to (proposal and donor names as text; a multi-program proposal appears under each program);
  - annual plan page: the plan's targets + the program framework's activities whose linked milestones' planned dates fall in the plan year (no T24 table).
- **Filters** (`#[Url]`): indicator, center (project), donor. Values are validated against the loaded sets (`Rule::in`); unknown values reset to "All". A node whose parent is filtered out is promoted with its hidden lineage as context.
- **Cross-cutting** roots render in their own group below the tree, with their indicators and targets (no parent, no children, no contributes-to). Every `ResultType` match has an explicit arm.
- An inactive library entry still shows on existing frameworks; an indicator scoped to a project that left the proposal shows the existing chain-issue flag. After T12/T13 writes on the same page, call that page's `forget…()` helper so figures refresh.
- **Gap markers:** result without indicators · indicator without target · activity without milestone · milestone without activity. Milestones flagged by `activityLinkIssues()` are shown with the flag, never hidden.
- **Security:** follows the host page's permission. Proposal/donor **links** render only for `proposals.view` / `donors.view` holders (names always as text). No money: don't load agreements, budgets or transfers. Department tasks follow T31 visibility (financial tasks only for permitted viewers); titles, department, status and due date only.
- **UI:**
  - the component's heading id/title becomes configurable (today it's hard-wired to `programs.results_logframe` / `program-results-heading`); keep the shared ResultType mark/accent mapping and the `data-tree-depth` / `data-result-type` attributes;
  - logical spacing, `rtl:rotate-180` for directional icons, `tabular-nums`, `dir="auto"` for mixed names;
  - `x-ui.panel`, `x-ui.empty-state` (+ **Start Logical Framework** for `results.create` holders), `x-ui.enum-badge`, `x-ui.progress-bar`, `x-ui.header-filter-select`; stable `data-<name>` tour hooks (see `config/tour.php`) for T26.
- Lang in `lang/{en,ar}/results_framework.php` (never a group named `results`).
