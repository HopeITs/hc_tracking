## Rules
- English; exact names; placeholders `<db>`, `<app-path>`, `<backup-dir>`. Counts and ids only: no host, user, key, name, email, amount, account number or file name.
- SQL is `SELECT` only (incl. `information_schema`), no `INTO OUTFILE`/procedures, MariaDB + MySQL. Each check: id, purpose, owner, blocking/informational, expected result. Recommend a read-only DB user.
- Each step: command, expected output, measured duration, backup point, invariant, on-failure action. Every `--dry-run` command runs dry → real → **again** (zero changes). All outputs go into the report.
- **Blocking PRE** (non-zero stops until management decides): `donor_proposal` duplicates per `proposal_id`; proposals without an agreement (T03 aborts on both); duplicate `plan_indicators` (`source_type`, `source_id`, `indicator_id`, `project_id`) (T13 aborts); draft projects with dates; > 1 open project per (`center_id`, `program_id`) without a recorded decision; a duplicated HR `programs.code` on a program with indicators (D-10a).
- **Pass = end to end with no manual intervention.** A manual fix fails the rehearsal.
- Never, on the copy as on production: `RolesAndPermissionsSeeder`, `db:seed`, `migrate:fresh`/`refresh`/`--graceful`, `key:generate`.
- **Safe rehearsal `.env`** (names only; the operator sets it): `MAIL_MAILER=log`, `BROADCAST_CONNECTION=log`; no queue worker or scheduler (copied `jobs` never run; record `jobs`/`notifications` counts incl. `monthly_reports.generated`, `report_template.pending`); `HR_DB_*` → HR snapshot or read-only replica; `APP_ENV=production`, `APP_DEBUG=false`; a **throwaway** `FILE_ENCRYPTION_KEY` made on the rehearsal host and destroyed with the copy. APP_KEY columns (`users.two_factor_*`; `accounts.account_number`, `iban`, `swift_code`, `authorized_person`): keep the production APP_KEY on the closed host only, or rehearse without it and list what can't be checked; record the choice.
- Migrations need ALTER, INDEX, REFERENCES, CREATE: the operator confirms the production user has them, else names a separate migration account. No credentials in documents.
- **Backups** before each step: `mysqldump`/`mariadb-dump --single-transaction --routines --triggers`, archive of `storage/app/private`, `.env` in secure storage. A backup counts only after one restore into a scratch schema with matching counts.
- **Rollback proof:** `migrate --force --step` (one batch each); on the copy `migrate:rollback --step=<n>` to the baseline, then forward again. Flag lossy/failing `down()`s: T04, T05 (documented no-ops), T03 `donor_id` backfill, T31 `milestones.project_id`, T22 (throws once `encryption_key_id` is set), `transfers_tracking` (fails once NULL received amounts exist). `migrate:rollback` doesn't undo `permissions:sync` or fill commands. On production, rollback = restore.
- **Encryption:** free disk ≥ 1.5× `storage/app/private`. If it exceeds the window, run it after `up` (legacy rows stay readable while `encryption_key_id IS NULL`; avoid the 03:00 `files:prune`). Record Dev 1's and management's choice.
- **Superseded, do not build:** `report-templates:seed-existing` and `donor_attribution_confirmed_at` (replaced by `report-templates:prefill-active` and T13's setting); importing the Syria Cross / Children University workbooks (D-54).

## Part C: rollback
- **Triggers:** a migration failure; systematic decryption errors; the approval path (`ApproveProposal`) breaks. Each with a threshold; decision owner Dev 1 with management.
- **Steps:** `down` → restore DB **and** storage **together** (rows carry `encryption_key_id`; old code would serve ciphertext) → previous release → composer/npm → `optimize` → restart → `up` → verify (PRE counts, a download, a login).
- Data-loss window (writes after the final backup) and the message: en "We restored the system to its state before the update. Changes made after <time> need to be re-entered." / ar «أعدنا النظام إلى حالته قبل التحديث. يلزم إعادة إدخال التغييرات التي تمت بعد <time>.»

## Stop and escalate to Dev 1

## Do not
Run or ask to run anything on production or the copy. Skip a `--dry-run`. Run role-resetting seeders or `migrate:fresh`. Point the suite at the copy (`RefreshDatabase` wipes it). Write DML/DDL for a shared DB. Put secrets, personal data or amounts anywhere. Call a manual fix "passed".
