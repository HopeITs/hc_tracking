# T35 · Page scroll trapped by cards · Team B · Phase A (meeting 23 Oct) · 0.5 day · 1 slice

## Goal
Scrolling the mouse wheel anywhere on a page scrolls the **page**, unless the pointer is over an element that genuinely has its own overflow (a long dropdown list, the Gantt scroller). Today, on the dashboard and other pages, the wheel over a card scrolls the card (or nothing) and the user has to move to an empty area to continue. Find the trap, fix it once in the shared component or CSS, and guard it with a test.

## Scope
**In:** the root cause and its fix (one of: a `wheel` listener that calls `preventDefault()` outside its own scroller; a `.chart` / ApexCharts option that captures the wheel; a container with `overflow-hidden`/`overflow-auto` + fixed height where it should grow; `overscroll-contain` on an element that does not scroll); a regression test; the same fix applied to any other page that uses the same component.
**Out:** redesigning cards, changing card content, dashboard panel configuration (T52), the Gantt scroller behaviour (it must keep its own scroll).

## Rules
- Fix at the **component or CSS level**, never per page. If the trap is in `x-ui.chart`, every chart gets the fix.
- Elements that legitimately scroll keep `overflow-y-auto overscroll-contain` with a **max height**, and only when their content can exceed it (dropdown lists, the notification bell, the Gantt). A card whose content fits the viewport never has its own scroll container.
- No `wheel` listener with `preventDefault()` outside a scroller whose `scrollHeight > clientHeight`. If `notifications.js` is the cause, scope its listener to the bell panel.
- No `@php(...)`; logical Tailwind classes only.
