# Handoff · Y-14 · MEAL coverage moves to places

Branch: `wave4/Y-14-coverage-to-places` · Date: 2026-11-23 · ClickUp: https://app.clickup.com/t/123jdbatgd1

## Delivered contracts

- `MealCoverage::responsibleForPlace(ReportPlace): ?int`, `responsibleForLocation(ProposalLocation): array`, `covers(int, ReportPlace): bool`, and `scopeCoveredBy(Builder, int): Builder`. The scope uses a correlated query with active officer IDs from the HR connection.
- Coverage writes use `city` and `place`. The stored scope key separates governorate and place assignments. `AssignMealCoverage::handle` validates the city, program, center and officer before writing. City ID alone remains supported for existing governorate callers.
- Cities builds its place inventory from report templates and proposal locations. Direct assignments override governorate coverage. Place assignment activity uses `meal_coverage.place_assigned`. The old event remains readable.
- Report validation and return, confirmation and placement queues, and monthly matrix extraction use the template or target place. Preparers still come from proposal location responsibilities. Annual-plan and notification callers with a legacy project ID resolve its linked proposal location rows and deduplicate officers.

## Migrations and local data

The additive migration adds program, HR center, field-work flag and scope key. The second migration previews the mapping, refuses conflicting officers before adding the unique scope key, and backfills the distinct places. Legacy rows are retained for rollback and ignored by the place-based authority checks. The unique city and project indexes are replaced by the scope key, with a supporting index retained for the legacy project foreign key. Existing migration and seed files were kept.

Local development dry run after the migrations:

```json
{"project_scopes":2,"written":0,"already_covered":2,"unset_rows":[],"conflicts":[]}
```

Both start and finish mirror checks reported that every location row matches its project (31 projects checked). Local test location 15 and report template 1 were aligned as field work before backfill, preserving the direct officer.

## Legacy boundaries

- `MealCoverage::responsibleFor(Project)` and `projectsCoveredBy()` removed.
- `PlaceBridge::mealOfficerFor()` and `placesOfProjects()` removed. `placeOfProject()` still translates existing matrix URL links until Y-17.
- `MealCoverage::cityIdOf()` remains for legacy annual-plan and execution callers until the Y-15/Y-16 row conversion. The temporary `officersForLegacyProject()` adapter uses the Y-11 mapper rather than reading coverage from projects.
- Annual-plan follow-ups retain the existing task source and assign each distinct location officer to the generated task. Proposal and report notifications retain their existing event routing where only the recipient lookup changed.
- `meal_coverages.project_id` and the legacy enum value remain readable for old data and backfill. New place assignment writes do not set it.
