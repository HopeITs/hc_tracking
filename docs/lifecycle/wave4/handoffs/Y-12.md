### `App\Support\Locations\TaskRowBackfill` (final)
```php
public function run(bool $apply): array
// array{tasks: int, moved: int, by_date: int, by_most_recent: int,
//       subtasks_followed: int, unmapped: list<int>, projects_without_row: list<int>}
```
Roots first, then children, so a subtask is already on its parent's row when its turn comes. A root goes to `ProjectSuccessor::rowFor($projectId, due_date ?? created_at)`; **a subtask takes its parent's row whatever its own date**, so a task tree is never split — the same rule `MoveTask` already applies by hand. A task whose project no row carries keeps its `project` source and is listed (D-80).

### `App\Support\Locations\ScheduleRowBackfill` (final)
```php
public function run(bool $apply): array
// array{dependencies, dependencies_moved, dependencies_deleted: list<int>,
//       dependencies_unresolved: list<int>, baselines, baselines_moved,
//       baselines_by_date, baselines_by_most_recent, baseline_items_dropped,
//       baselines_unmapped: list<int>}
```
- **A dependency takes the row of its successor.** Both ends must be on the same row, so one whose ends land on **different rows is deleted and its id listed** — it cannot be honoured. An end that is not a task (the dead `milestone` type) makes it unresolvable: listed and **left alone**, never guessed.
- **A baseline takes the row its own `created_at` picks** (D-94), and an item whose task is on another row is dropped from the baseline and counted.

Both dry runs do the real work inside a rolled-back transaction, so their counts are exact.

### Commands
`tasks:row-backfill {--dry-run} {--apply}` (`BackfillTaskRows`) and `schedule:row-backfill {--dry-run} {--apply}` (`BackfillScheduleRows`). Lang `tasks.console.row_backfill_*` and `tasks.console.schedule_*` in **en and ar**.

> `schedule:row-backfill --apply` **deletes** dependencies. Run the dry run and read the deleted-ids list first.

### Code
- `Task::sourceLocationId(): ?int` — the row id, or null for any other source; reads the column, no query.
- `Task::activityProgramId()` — a `proposal_location` source resolves through `ProposalLocation::programIdFor()`.
- `Task::isPaused()` — a row-sourced task asks the row (`ProposalLocation::isPaused()`, Y-11); the `project` arm stays for unmapped tasks.
- `Task::notPaused` scope — now excludes both a paused project **and** a row with a deactivated centre of its own (a city-wide row is never paused).
- `TaskVisibilityScope::constrain()` — a new arm: `source_type = 'proposal_location'` and `source_id` in `User::ownedLocationIds()` (Y-11). `allows()` reuses `constrain()`, so single-task checks follow automatically. The `project` arm stays until Y-18.
- `MoveTask` — `resolveTarget()` accepts `location:ID` (same program only) and returns `['type' => 'proposal_location', ...]`; `targetFor()` renders `location:ID`; `programIdOfSource()` resolves a row. `project:ID` still accepted for unmapped legacy tasks.
- `CreateTask` — already passed its `$sourceType` through unvalidated, so only its docblock changed.
- `ScheduleDependency` / `ScheduleBaseline` — `proposal_location_id` fillable, cast, and a `location()` relation beside `project()`.
