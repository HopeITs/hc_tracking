### Fields a change request may touch
These are exactly the fields `SaveProposal::update()` let through on an approved proposal before this task:
- `name`, `plannedDateBegin`, `plannedDateEnd`, `notes`, `conceptNote`
- `requestedBudget` and `requestedCurrency` (money holders only)
- `beneficiaries` (linked projects)
- `narrative` (payroll only)
- `locations[]`, without the fill-only limit

`donorId` stays refused after the concept note, and `kind` never changes.

### Refusals
- Direct `SaveProposal` on an approved proposal, any difference except the D-83 fill: `changeRequest` / `change_request_required`.
- Request: reason under 10 (`reason`), not approved (403 from the policy, and `status` inside the lock), stale `expectedUpdatedAt`, one already pending, empty difference.
- Request (locations): a dropped or moved row that still carries a `project_id` (`location_row_has_project`); a center that already reports (`location_center_reports`), checked at request and again at approve.
- Review: not the slot holder (403), bad verdict, remarks note under 10, request already decided.
- Approve: wrong or decided status, proposal no longer approved, a review still waiting (vacant slots are skipped first), stale `from` (`change_request_stale`, which names the fields).
- Reject: note under 10, request already decided.

**Requester** (`RequestsProposalChange`, proposals/show):

**Review, decide, withdraw** (`DecidesProposalChange`, proposals/show):

- What the viewer gets:
  - a slot holder: **No objection** / **I have remarks** (note required);
  - a decider: **Approve**, behind a confirm, disabled with "Approve opens once both reviews are in: Waiting for …" while a review waits; and **Reject** (note required);
  - the requester: **Withdraw**, behind a confirm;
  - anyone else: a read-only line.
- Opening as a decider marks vacant slots `skipped` (`skipVacantReviews()` under the request's lock).
- A stale approve offers only Reject.
- The deep link `?change-request=1` opens the pending request once.
- The request is loaded through `$proposal->changeRequests()`, so an id from another proposal returns 404.
- Notice `data-test="change-pending-notice"` while a request is pending.
- Chapter `_show-change-requests` (`data-test="change-requests-chapter"`) sits in the Status tab after the reviewers, payroll included. Newest first, each with a status word (`ProposalChangeRequestStatus` now has a badge tone).
