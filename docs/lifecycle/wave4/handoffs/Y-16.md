## Deviations from contracts.md / the prompt

1. **`forProjectInWindow()` is kept, not deleted.** The prompt says the old methods go "when their last caller is gone", and its last caller is a test. But `contracts.md §12.1` still documents it as the way to read a project's targets in a period, and removing a method the frozen contract names is an escalation (`AGENT.md §6`), not a prompt call. Added the twin, left the old one. **Dev 1: delete the method and strike the §12.1 line, or keep both until Y-18?**
2. **An annual-plan target picks a location row, not a place.** The prompt says "a location row or a place". A row was chosen because `chainIssuesForRow()`'s "a row carrying an annual-plan target must sit in the plan's program" is then the exact twin of the project rule, and one place rule (`placeColumnsForRow`) serves every target. Consequence: a **new** annual-plan target gets `project_id = null` (it is `$row?->project_id`, and a row may have no project), where before it got the chosen project. Existing rows keep their stored place and project. §12.1 allows a null `project_id` ("A target with no `project_id` has no place"), and the row supplies the place instead. **Dev 1 to confirm**, since Y-08 deviation 1 placed annual-plan targets through their project.
3. **The targets directory's place filter is renamed `project` → `location`.** Keeping the name while changing its meaning would answer an old `?project=12` link with row 12 — a silently wrong list. Instead `mount()` translates a legacy `?project=<id>` to its successor row and `?project=none` to `none`, the courtesy Y-05 gave the matrix's `?center=`. The prompt's "filters keep their URL names" rule is about the **projects** directory (slice 2), which is untouched here.
4. **`ProposalRenewalCloneTest` keeps its project-and-pivot fixture.** `wave4/AGENT.md §8.6` asks a touched test to build a row instead. Doing it in the shared `renewalSource()` helper broke 15 tests: the helper's centre belongs to a different city than its project ("Every center must stand in the row's city"), and another test in the file builds the renewal's rows itself and then hit the `proposal_locations_proposal_city_program_unique` index. Only the one test that covers D-30 was changed, by placing its two targets explicitly at the one place they share. **Converting that helper belongs with slice 2.**
5. **`ResultsChain`, `BuildsMatrixActivities` and `ProposalFramework::programIds()` are listed by Y-15 as "for Y-17", but Y-17's prompt does not list them.** `ResultsChain` and `BuildsMatrixActivities` are in Y-16 slice 1's code list, so they belong here (not started, see below). `ProposalFramework::programIds()` is in **neither** prompt's code list, and the Y-17 Start state stops if anything outside its list still names `Project`. **Dev 1: add it to Y-16 slice 1.**
