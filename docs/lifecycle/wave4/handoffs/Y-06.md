## Delivered contracts (exactly as on the branch)
- `ReportTemplateReader::calendarFor(ReportTemplate): array{months: list<array{key: 'Y-m', label: string}>, groups: list<array{proposal: Proposal, rows: list<array{id: int, statement: string, adjusted: bool, cells: array<'Y-m', array{weeks: list<int>|null, label: string}>}>}>, multiple: bool}`. Months = union of the template proposals' `ProposalFramework::scheduleWindow()`; a row shows only months inside its own proposal's window. Four queries whatever the number of activities; no money.
- `ReportTemplateReader::weeksText(list<int>): string` ("1–2, 4").
- `ManagesReportTemplate::templateCalendar()` (`#[Computed]`): the reader output plus `editUrl` per group, set only when the user passes `ActivitySchedulePolicy::update` **and** `view` on the proposal (MEAL edits calendars without `proposals.view`, T12 deviation 10, so it gets the sentence without a link).
- `MonthlyReportActivities::for()` rows gain `proposal_name: string|null` (set only when more than one proposal feeds the report). The proposals are those of all templates of the report's project (`PlaceBridge::templateIdsOfProject()`, `proposal_report_template`), donor-approved only; a project with no template keeps its linked proposals. A scheduled month outside the activity's proposal window is not listed (carried-over and already-entered activities are unaffected).
- Page: read-only "Activity calendar" panel on the template tab (`data-activity-calendar`, real `<table>` with `scope` headers, sticky first column, scrolls inside its panel, check icon + sr-only label "Scheduled, weeks 1–2"); `data-calendar-group` rows when more than one proposal; badge "Adjusted for this center" / "Adjusted for field work" (city-wide template). The monthly report page shows the proposal name under the activity (`data-activity-proposal`).
- Lang: `report_templates.calendar.*` (en, ar). No table, column, contract or write path changed.
