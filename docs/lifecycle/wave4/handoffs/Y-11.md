## Deviations from contracts.md / the prompt

1. **`assignmentFields()` returns `[]` until Y-17** — needs Dev 1's nod. The prompt says the row gains `HasAssignments`, and the contract says the owner's acknowledgement is an `assignments` row on the row. But `HasAssignments` boots on `created`/`updated` and *asks* the person to acknowledge. With `['responsible_employee_id']` returned, every existing `SaveProposal` write would notify the responsible employee a second time for one appointment, while the project already asked them — against the Goal ("nothing a user sees changes") and §8.2 (the row is a mirror, `projects` is the writer). The trait is still used, so every reader works and the backfill/mirror write the rows explicitly. **Y-17 returns `['responsible_employee_id']` here** when the row becomes the writer.
2. **Files are mirrored, not moved** (decided with the developer, 20 Nov). The prompt's "files … not copied" is read as "not duplicated across the project's several rows" (what D-94 is about), not "taken off the project". Each file gets a second `media` row on the one row its date picks; the project's own row is untouched, so the project Files tab keeps working until Y-16 (§8.3). Moving them would have emptied 18 real files from the project pages today. Both rows point at the same stored object; nothing is written to disk.
3. **`ProjectSuccessorTest` lives in `tests/Feature`, not `tests/Unit`.** `tests/Pest.php` binds `TestCase`, `RefreshDatabase` and `createHrSchema()` only `->in('Feature')`, so a DB-touching test in `tests/Unit` has no application at all. Same choice Y-02 made for `PlaceBridgeTest`. The query-count test for `label()` lives in that file too.
4. **No commits.** `AGENT.md §7` lists commit/push/merge under Never, and a prompt may tighten a rule, never loosen it — so the `[contract]` change is **staged** rather than committed, although the DoD calls it "first commit". Suggested message is in the session scratchpad; the developer makes it.

# Slice 2 · the mirror, its call sites and the verify command (2026-11-20)

## Delivered contracts

### `App\Support\Locations\ProjectLocationMirror` (final)
```php
public function sync(Project $project): void                  // contracts.md §7 — the project's own columns onto every row
public function syncSectors(Project $project): void           // called by SyncProjectSectors, the only project_sector writer
public function syncAcknowledgement(Project $project): void   // called by Project::assignmentResponded()
public function attachFile(Project $project, Media $file): void
public function detachFile(Project $project, Media $file): void
public function apply(Project $project): array                // everything at once, with counts; the backfill and a newly linked row
public function differences(Project $project): array          // list<string> in words, for locations:verify-mirror
```

**This class now holds the only definition of what a row copies.** `LocationBackfill` owns no rule any more: it decides which projects to run over, calls `apply()` and tallies. The slice 1 helpers (`statusFor`, `periodFor`, `copySectors`, `copyAcknowledgement`, `mirrorFiles`, `uniqueSlug`) moved here, as the slice 1 handoff said they must.

**`complete()`**: the mirror re-reads the project when the caller passed a model loaded with a narrower select, so no writer has to know which columns the mirror needs. A full model costs no extra query. This was a real bug — W-34a's own `ProposalLocationBackfill` selects six columns and `Model::shouldBeStrict` raised `MissingAttributeException` on `status`.

### Why `sync()` is the columns only
The quality bar allows the mirror **at most 3 queries on a project write**. A full faithful sync costs 7–9 (rows, proposals, beneficiaries, the update, two for sectors, two for assignments, one for files), so `sync()` does the project's own columns — **exactly 3** for a project with one row (the rows, their proposals, one update) — and each other facet is synced by the writer that changes it. That is how the prompt lists the call sites: `SyncProjectSectors`, the assignment path and `SaveProjectFile`/`DeleteProjectFile` are named separately from the status writers. `locations:verify-mirror` still checks **every** facet, so a writer that skips its own is caught rather than trusted. Asserted by "the mirror adds at most three queries to a project write".

### Call sites (all ten actions, plus the rest of the prompt's list)
| Writer | Call |
|---|---|
| `SaveProject`, `CloseProject`, `ArchiveProject`, `RestoreProject`, `ReopenProjectAsDraft`, `ActivateProject`, `ApproveProjectFromProposal` | `sync($locked)` at the end of the transaction |
| `SyncProjectSectors` | `syncSectors($locked)` |
| `SaveProjectFile` / `DeleteProjectFile` | `attachFile()` / `detachFile()` |
| `ProjectPeriods::widen` | `sync($project)` — **inside widen**, so both callers (`ApproveProjectFromProposal`, `ExtendProposal`) are covered and a future one cannot be missed |
| `ProposalLocationRows::attachProject` (all three branches) | `apply($project)` — a row that has just taken a project needs the whole mirror, not only the columns |
| `Project::assignmentResponded()` | `syncAcknowledgement($this)` |

`detachProject` needs no call: the row is deleted, and its sectors go by FK cascade, its files and assignments by observer (below).

The mirror is **constructor-injected** (`private ProjectLocationMirror $mirror`) into the seven actions; nothing instantiates them with `new`, so the container resolves it. `ArchiveProject` gained a `DB::transaction` so its mirror write rides with the status change.

### New generic hook: `assignmentResponded()`
`Assignment::respond()` now calls `assignmentResponded($field)` on the assignable when it defines it — the twin of the existing `assignmentAcknowledged()`, which only fires on an **accept**. A project has to follow a **reject** too (the row carries a copy of the decision), and this keeps that knowledge in `Project` rather than teaching the generic model about projects. `Project::assignmentResponded()` calls `syncAcknowledgement()`.

### New: `App\Observers\ProposalLocationObserver`
Deletes a row's mirrored owner assignments on `deleting`. `assignments.assignable_id` carries no foreign key, exactly like `media.mediable_id` (`MediaOwnerObserver`). It never mattered while only projects held assignments — a project is archived, never deleted — but a **location row is** deleted (`ProposalLocationRows::replace`, `detachProject`), so from Y-11 these rows would outlive it. `ProposalLocation` is now `#[ObservedBy([MediaOwnerObserver::class, ProposalLocationObserver::class])]`.

### `App\Console\Commands\VerifyLocationMirror`
`locations:verify-mirror {--project=}`. Compares every mirrored column, the period, the calendar, the sector set, the slug and the owner's acknowledgement; prints each difference in words (`project 14, row 50: target_men should be empty but is 4242`) and **exits 1** when any exists. Read-only — it never repairs, because a difference means a writer reached `projects` without the mirror, and `--apply` on the backfill would only hide it. Lang `projects.console.verify_mirror_*` in en and ar.

**It is the Start-state check of Y-12…Y-17: run it before and after, and paste both.**

### `User::ownedLocationIds(): list<int>`
Rows whose responsible is the user's HR employee, plus rows of programs they manage. The twin of `ownedProjectIds()`, memoized with `once()` the same way. Nothing reads it yet — Y-16's pages do.
