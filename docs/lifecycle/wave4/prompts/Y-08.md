## Goal
A per-center target (`plan_indicators`) names its **place** (city + program + center, D-75) on its own row, so reporting no longer resolves it through `projects` (D-85, ruled against the recommendation: targets move within wave 4). Nothing a user sees changes: the targets grid, the target form and every page that reads targets show the same data. `project_id` stays and is still written (D-74).

- **Slice 1:** schema, the backfill with its dry run, `PlanIndicator::place()` and the `atPlace` scope, `PlaceBridge::placeOfTarget()` reads the new columns.
- **Slice 2:** every writer of a target writes its place; factory and seeders follow.

Runs right after Y-02 and before Y-03: Y-03 builds the monthly report on template lines, and those lines must match targets by place without reading `projects`.

Reporting reads a target's place only through these, never through `project_id`.

And in `§12.4`, change the `PlaceBridge` bullet's `placeOfTarget` to:

> `placeOfTarget(PlanIndicator): ?ReportPlace` returns `$target->place()` and `targetCoversPlace(PlanIndicator, ReportPlace): bool` returns `$target->coversPlace($place)` (Y-08); neither reads `projects` any more.

## Rules
- **Slice 1, migrations** (`wave4/AGENT.md §4`, additive first):
  1. add `city_id`, `program_id`, `center_id`, all nullable, and `city_wide` default false, after `project_id`;
  2. backfill each target with a `project_id`: `city_id` and `program_id` from its project; `center_id` from the project's `center_id`, else, for a `proposal` target, from the proposal's location row with that `project_id` (`proposal_locations.proposal_id` = the target's `source_id`, `proposal_locations.project_id` = the target's project) when that row has **exactly one** center; `city_wide` true when that row is `city_wide` (D-88); `all_centers` true when that row has **several** centers (D-90); otherwise null, not city-wide, not shared. This read of `projects` and `proposal_locations` lives in the migration, not in app code;
  3. second migration: add `plan_indicators_place_index`. The columns stay nullable (targets without a project have no place).
- A target whose row has several centers becomes a **shared target** (`all_centers`), never assigned to one of them (D-80, D-90); the dry run lists them with their centers. A target with no center is listed, not blocked (D-82).
- Command `targets:place-backfill {--dry-run}` prints: targets, with a place, with a center, without a center, row with several centers (ids), without a project. The dry run writes nothing and prints the counts the migration writes.
- `PlanIndicator::place()` builds a `ReportPlace` from the three columns. Equality is `ReportPlace::equals()` (Y-02): a city-wide target matches the city-wide template of its city and program (D-88); a target whose center is **not set** matches nothing, not even an unset template (D-82). Say in the handoff how many targets that leaves unmatched on local data.
- `PlaceBridge::placeOfTarget()` delegates to `PlanIndicator::place()`. Update its PHPDoc: no `projects` read left in it.
- **Slice 2, writers.** Every writer that sets `project_id` also sets the place, in the same write: `SaveProposalTargetsGrid` (one place per project column) and `ManagesTargetForm::saveTarget` (proposal and annual-plan targets). The place for a new target comes from one method, `PlaceBridge::placeForTarget(Model $source, ?int $projectId): ?ReportPlace`, using the backfill's rule; PHPDoc names the task that replaces its project branch: Y-10 (targets keyed by location row, D-91).
- Changing a target's `project_id` rewrites its place in the same save. Changing a project's center or a row's centers does **not** rewrite targets in this task: list it in the handoff.
- In this task the targets grid keeps its project columns and the form keeps its project select (Y-10 moves both to location rows right after); `forProjectInWindow`, `chainIssuesFor` and `previousYearReference` keep reading `project_id`. Moving those is not this task.
- `ReportTemplatePrefiller` keeps matching lines through `PlaceBridge::targetCoversPlace()` (Y-02); its behaviour must not change on data where project and row agree.
- `PlanIndicatorFactory` fills the place from its project; seeders that create targets do the same.
- `WaveFourProjectsGuardTest`: `PlanIndicator::place()` and the `atPlace` scope never name `Project`.
