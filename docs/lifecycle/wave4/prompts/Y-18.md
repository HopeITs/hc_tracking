## Rules
- **Slice 1, no schema change.** Every test, factory and seeder that builds a `Project` builds a `ProposalLocation` (with its proposal) instead. 167 test files held `Project::factory` on 16 Nov; the earlier Stage B tasks moved the ones they touched. Do the rest here, in commits of one folder at a time, running each folder's tests before the next. A test that only asserted project behaviour which no longer exists is **listed for Dev 1 and deleted only with approval in the PR** (`CLAUDE.md`: tests are part of the application).
- `ProjectFactory` is deleted last in this slice; `ProposalLocationFactory` has every state the tests need (`approved`, `active`, `closed`, `archived`, `withCenters(n)`, `fieldWork()`, `ownerRejected()`).
- Seeders: `RealProjectsSeeder` becomes rows of the real proposals; `ProposalLocationSeeder` absorbs it. The showcase seeders build proposals with rows. `php artisan migrate:fresh --seed` must run clean (paste it).
- **Slice 2, one migration per table**, each: assert the audit count for that table is zero (throw otherwise, before any DDL) → drop the foreign key by **name** → drop indexes and uniques that include the column → drop the column. The names are in the Stage B inventory: e.g. `milestones_project_id_foreign`, `risks_project_id_foreign`, `meal_coverages_project_id_foreign`, `activity_schedules_project_id_foreign` + `activity_schedules_project_id_index`, `project_activity_statuses_project_foreign`, `plan_updates_project_id_foreign`, `apfut_project_id_foreign`, `schedule_dependencies_project_id_foreign`, `schedule_baselines_project_id_foreign`, `proposal_locations_project_id_foreign`, `report_templates_project_id_foreign`, `monthly_reports_project_id_foreign`.
- `plan_indicators`: add `place_key` and the new unique **before** dropping the old unique and the column; a duplicate under the new key is listed and stops the migration.
- `down()` of each slice 2 migration re-adds the column nullable with its index, **empty**. Say in its PHPDoc that the data does not come back and name the backup that holds it.
- Remove `'project' => Project::class` from `enforceMorphMap` in the same commit as the last morph audit reaching zero; `MorphMapTest` follows.
- **Slice 3, in this order:** fill `project_redirects` → drop `project_sector` → drop `project_proposal` → drop `projects`. Then delete `Project`, `ProjectPolicy`, `ProjectSuccessor`, the legacy methods of `PlaceBridge`, `projects:retire-audit`, and every now-unused import.
- **Names that still say "project"** and stay, on purpose: the route names `projects.*`, the permission keys `projects.*`, the notification keys `project.*`, `ProjectStatus`, `lang/*/projects.php`, the screen's title. Names this slice **does** change, because they name the dropped thing: the traits under `app/Livewire/Concerns/Projects/` move to `Concerns/Locations/` with `Location` in their names; `project_activity_statuses` and `ProjectActivityStatus` are renamed `location_activity_statuses` / `LocationActivityStatus` only if Dev 1 says so in the PR (a table rename on a table that holds report data buys clarity and costs a migration: ask, do not assume).
- **Production run** (Dev 1, not the agent): backup → `projects:retire-audit` (all zero) → deploy → migrate → smoke test (open the directory, one row, one monthly report, approve a test proposal on staging). Write these steps into the handoff as a checklist; do not run them.
