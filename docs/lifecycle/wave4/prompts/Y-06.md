## Rules
- **On the template** (the template tab, under the indicators): a read-only **Activity calendar** panel. Rows = the activities of the template's proposals, grouped by proposal when there is more than one; columns = the months of the template's window; a cell is marked when the activity is scheduled, with the weeks when they are set. One line of help says where it is edited, with a link to the proposal's calendar tab for those who may edit it (`ActivitySchedulePolicy`).
- The panel never edits. The proposal's calendar tab stays the one place a calendar is written (`SaveActivitySchedule`).
- **Which calendar applies (D-49):** the proposal calendar (`project_id` null), unless the place has an override. An override is still stored by project today: reach it through `PlaceBridge::legacyProjectIdFor($template)` and nowhere else (D-74). Mark an overridden activity with the word "Adjusted for this center".
- **In the report:** `MonthlyReportActivities::for()` already lists activities scheduled in the month or continuing. Make it read the **template's** proposals, so a joined template's report lists the activities of every proposal it covers, each labelled with its proposal when there is more than one.
- An activity scheduled in a month the template's window does not cover is not shown and not asked.
- Empty state: "No activity is scheduled yet. The calendar is set on the proposal." with the link when the user may edit.
- No colour-only cells: a scheduled cell carries a mark and an accessible label ("Scheduled, weeks 1–2").
