## Rules
- **Row (slice 1):** city* · program (or "new program" → the two name fields, which open a `program_requests` row) · responsible · centers (multi-select, only centers of the row's city, inactive ones shown disabled with a badge) · remove. "Add location" appends a row. One row per city + program (`proposals.location_city_duplicate` already guards it).
- Bind an Alpine repeater to `locations`; the server stays the only validator. Errors arrive as `locations` (the set) and `locations.{i}.{field}`; the summary at the top names the first invalid row and focuses its field.
- `projectIds` leaves the form, `ManagesProposalForm` and the form tests. `SaveProposal` keeps accepting it (other callers); do not remove it from the action.
- A payroll proposal shows no Locations section (W-32), as today.
- **Locations chapter:** rows with city, program, responsible, centers, and one status word each: Complete / Missing center / Missing responsible / Waiting for program. Never colour alone.
- **Approve preview:** "will create N projects, link M, wait for K" from `MaterialiseProposalLocations::preview()`; warning key `location_linked_existing`.
- **Slice 2:** the same rows component, opened from the Locations chapter with a required reason. City and program render as locked chips. The reason field is required only when the proposal is approved.
- **Slice 3:** a register at `proposals` behind a status button "Missing a center" (`setFocus()`, like the other registers): every non-rejected, non-payroll proposal with at least one row that has no center. Row shows the proposal, its donor, the rows missing a center, and one "Add centers" action that opens the slice 2 editor. The count on the button equals the list.
- HR is read-only: center and city names come from `HrCenter` / `HrCity::remembered()`, never copied into a tracking table.
- D-74: add no read of `projects` here. The chapter may still show a row's linked project name, read through `ProposalLocation::project()` as it does today.
