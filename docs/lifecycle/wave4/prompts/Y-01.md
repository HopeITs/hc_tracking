## Goal
A center can be entered on a proposal. Today it cannot: the form still chooses projects (`projectIds`), `proposal_location_centers` is empty and no project carries a center, locally or in production. Every later task in this wave names a place as city + program + center (D-75), so nothing can start until this ships and the team has entered the centers. A program may also work **in the field** in a city, with no center: such a row is marked **city-wide** (D-88, shown as "Field work, no center") and needs no center.

- **Slice 1 (Dev 2):** the location rows replace the project picker in the proposal form, each row with centers or city-wide; the Locations chapter on the proposal page; the approve preview. **[contract]**
- **Slice 2 (Dev 1):** on an approved or active proposal, a row that has no center and is not city-wide can be filled once (centers, or city-wide); nothing else changes. **[contract]**
- **Slice 3 (Dev 2):** the "Proposals without a center" list.

## Rules
- **Row (slice 1):** city* · program (or "new program" → the two name fields, which open a `program_requests` row) · responsible · centers (multi-select, only centers of the row's city, inactive ones shown disabled with a badge) **or** the checkbox "Field work, no center" (D-88) · remove. Ticking the checkbox clears and disables the centers picker; the two never hold together. "Add location" appends a row. One row per city + program (`proposals.location_city_duplicate` already guards it).
- Bind an Alpine repeater to `locations`; the server stays the only validator. Errors arrive as `locations` (the set) and `locations.{i}.{field}`; the summary at the top names the first invalid row and focuses its field.
- `projectIds` leaves the form, `ManagesProposalForm` and the form tests. `SaveProposal` keeps accepting it (other callers); do not remove it from the action.
- A payroll proposal shows no Locations section (W-32), as today.
- **Locations chapter:** rows with city, program, responsible, centers, and one status word each: Complete / Missing center / Missing responsible / Waiting for program. A city-wide row shows "Field work" in the centers cell and is Complete, never "Missing center". Never colour alone.
- **Approve preview:** "will create N projects, link M, wait for K" from `MaterialiseProposalLocations::preview()`; warning key `location_linked_existing`.
- **Slice 2:** the same rows component, opened from the Locations chapter. On an approved proposal every row renders locked (city, program, responsible and existing centers as chips); only a row with no center that is not city-wide shows the centers picker and the "Field work, no center" checkbox. No reason field. The action is hidden when no row is missing a center. A filled row cannot be undone here (that is a change request, Y-09): the dialog says so before saving.
- **Slice 3:** a register at `proposals` behind a status button "Missing a center" (`setFocus()`, like the other registers): every non-rejected, non-payroll proposal with at least one row that has no center and is not city-wide. Row shows the proposal, its donor, the rows missing a center, and one "Add centers" action that opens the slice 2 editor. The count on the button equals the list.
- `ProposalLocationRows::incompleteRowIds()` reads `city_wide` (the one definition of `locations_complete`). `MaterialiseProposalLocations` is **not** changed: a city-wide row already yields one project with no center, as a center-less row does today.
- HR is read-only: center and city names come from `HrCenter` / `HrCity::remembered()`, never copied into a tracking table.
- D-74: add no read of `projects` here. The chapter may still show a row's linked project name, read through `ProposalLocation::project()` as it does today.
