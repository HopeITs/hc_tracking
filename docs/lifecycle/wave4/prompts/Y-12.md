## Rules
- **Slice 1, migrations** (`AGENT.md §4`): add `proposal_location_id` nullable → backfill → no tightening (proposal-only milestones stay row-less).
- **Backfill (D-94):** roots first. A root milestone with a `project_id` goes to `ProjectSuccessor::rowFor($projectId, planned start ?? due date ?? created_at)`. Every descendant takes its root's row, whatever its own dates. `proposal_id` is filled from the row when null. A milestone whose project has no row is listed and left.
- Command `milestones:row-backfill {--dry-run}`: milestones, moved per row, decided by date / by "most recent", descendants that followed, unmapped (ids).
- `MilestoneObserver`: the cross-parent guard, `canNestUnder` and `assignSequence` key on `proposal_location_id` (then on proposal for row-less ones); `InvalidParentException::crossProject` becomes `crossLocation`. `MilestoneFactory::childOf()` copies the parent's row. Remember that raw writes bypass the observer: the backfill sets sequences itself.
- `SaveProposalMilestone`: input `location_id` (a row of this proposal) replaces `project_id`; error key `nested_milestones_in_other_centers` keeps its name. `SaveMilestone`: `proposal_location_id` in `$fields`. Both still write `project_id` from the row.
- `Milestone::allowedActivitiesFor(?int $locationId, ?int $proposalId)`: a row has exactly one proposal, so no pivot read is left in it.
- `MilestonePolicy::create(User, ?int $locationId)` and `update`: `milestones.*` or the row in `ownedLocationIds()`.
- `CloneProposalForRenewal::copyMilestones`: maps each milestone to the new proposal's row with the same city and program; a milestone whose row has no twin stays proposal-only and is named in the result.
- **Slice 2, tasks:** backfill `source_type = 'project'` → `'proposal_location'` with `ProjectSuccessor::rowFor($projectId, due date ?? created_at)`; milestone-sourced tasks need no change (they follow the milestone). `Task::sourceLocationId()`, `isPaused()` and `notPaused` read the row (`ProposalLocation::isPaused()`); `activityProgramId()` handles the new source. `TaskVisibilityScope` reads `ownedLocationIds()`.
- **Schedule:** a dependency goes to the row of its **successor** item; one whose two ends land on different rows is deleted and listed (it cannot be honoured). A baseline goes to `rowFor($projectId, its created_at)`; items of that baseline that are no longer on the row are dropped from it and counted.
- Delete the dead code the inventory found, in its own commit: `projectGanttPayload`, `autoSchedule`, `linkWouldCycle` (no callers). If one has a caller after all, keep it and say so.
- **Slice 3:** `milestones/⚡index`: the `project` URL filter becomes `location`, the groups are rows (label from `ProposalLocation::label()`), the create form picks a row. `milestones/⚡show`, `tasks/⚡show` ("milestone · place" link, the move dialog's tree is program → proposal → row → milestone). `BuildsPortfolioGantt` groups by row; `BuildsProposalPlanGantt` is unchanged. Calendar: `ManagesCalendarMilestones`, `BuildsCalendarGrid`, `ManagesCalendarTasks`.
- Notifications: `MilestoneRecipients`, `DeadlineCatalog` and `WorkingCalendar` read the row's owner and calendar (`WorkingCalendar::forLocation`); keys and wording unchanged.
- The user-facing word stays "Project" (`AGENT.md §8`): labels do not change in this task.
