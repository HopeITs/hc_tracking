## Goal
A report template belongs to a **place** (city + program + center, D-75) and to **one or more proposals** (D-76), not to a project. Two templates may exist at the same place. Nothing a user sees changes in this task: it moves the template onto its new keys, migrates what exists, and gives every later task one way to name a place.

- **Slice 1:** schema, the `ReportPlace` value object, `PlaceBridge`, the backfill with its dry run, the guard test.
- **Slice 2:** prefill, confirm, save-line, retire, the queue and the template tab read the new keys.

## Rules
- **Slice 1, migrations** (`wave4/AGENT.md §4`, additive first):
  1. add `city_id`, `program_id`, `center_id` nullable, create `proposal_report_template`;
  2. backfill each existing template: `city_id` and `program_id` from its project; `center_id` from the project's `center_id`, else from the location row that carries that project (`proposal_locations.project_id`) when the row has **exactly one** center; `city_wide` true when that row is `city_wide` (D-88); otherwise both stay empty ("center not set"). When a project's rows disagree (two proposals, different answers) the template stays unset and is listed. Then link every proposal of that project (`project_proposal`) with `joined_at` = the template's `created_at`; this one read of `projects` lives in the migration, not in app code;
  3. second migration: `city_id` and `program_id` not null, drop the unique on `project_id`, make it nullable, add the place index.
- A template that ends with no center and not city-wide migrates as "center not set" (D-82). It is listed by the dry run, not blocked. The human step after Y-01 should leave few of these: say how many in the handoff.
- Command `report-templates:place-backfill {--dry-run}` prints: templates, with center, city-wide, center not set, rows that disagree, proposals linked, templates with no proposal (must be 0; otherwise the migration stops before DDL).
- `ReportPlace::equals()`: same city and program, and either the same non-null center or **both city-wide** (D-88). An **unset** place equals nothing, not even another unset one (D-82), so nothing can be joined to it by accident. A city-wide place never equals a centered one.
- **Self-funding (D-87).** A proposal whose donor `is_internal` is pre-filled like any other: location rows, template, lines. Add no branch that skips it and no template without a proposal; the existing skips for donor reports and expected transfers are untouched.
- **Slice 2:** `ReportTemplatePrefiller::prefillForProposal()` works per place, never per project. A line is created for each library-linked target of the proposal that covers the template's place (`PlaceBridge::targetCoversPlace`). A **shared target** (D-90: one target on a row with several centers) therefore gets one line in **each** center's template; the unique (`report_template_id`, `plan_indicator_id`) already allows it.
- In this task an approval **always creates its own template** at each place when the proposal has none there. It never joins an existing one: joining is MEAL's choice and arrives with Y-04. Until Y-04 ships, a second proposal at an occupied place therefore gets a second pending template. Say so in the handoff.
- `ConfirmReportTemplate` keeps activating the approved project: resolve it with `PlaceBridge::legacyProjectIdFor()` and call `ActivateProject` as today. Activation moving off projects is not this task.
- `ReportTemplatePolicy::manage` keeps its rule; where it reads the project for MEAL coverage, route that one read through `PlaceBridge` (D-74).
- **Targets (D-85).** A target's place is read only through `PlaceBridge::placeOfTarget()`, which in this task still reads the target's project **and its location row**, by the same rule as the template backfill above (no project carries a center today, so reading the project alone would match no template); its PHPDoc says Y-08 replaces that read. A target whose row has several centers is **shared** (D-90): it has no single place and is matched through `targetCoversPlace()`, never assigned to one center. List the shared targets in the handoff, with their centers. Do not touch `plan_indicators`: Y-08 moves targets to places right after this task.
- The template tab on `projects/show` and `report-templates/index` show the same data as before; rows may now be two per place, each naming its proposals.
- `tests/Unit/WaveFourProjectsGuardTest.php`: scans the files this wave creates or lists (start with `app/Support/Reporting/**`, `ReportTemplatePrefiller`, `ReportTemplateReader`, `ReportTemplateQueue`, `app/Actions/ReportTemplates/**`) and fails when one names `App\Models\Project` outside `PlaceBridge`.
