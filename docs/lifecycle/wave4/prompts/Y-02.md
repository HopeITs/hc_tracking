## Goal
A report template belongs to a **place** (city + program + center, D-75) and to **one or more proposals** (D-76), not to a project. Two templates may exist at the same place. Nothing a user sees changes in this task: it moves the template onto its new keys, migrates what exists, and gives every later task one way to name a place.

- **Slice 1:** schema, the `ReportPlace` value object, `PlaceBridge`, the backfill with its dry run, the guard test.
- **Slice 2:** prefill, confirm, save-line, retire, the queue and the template tab read the new keys.

## Rules
- **Slice 1, migrations** (`wave4/AGENT.md §4`, additive first):
  1. add `city_id`, `program_id`, `center_id` nullable, create `proposal_report_template`;
  2. backfill each existing template from its project's `city_id` / `program_id` / `center_id` and link every proposal of that project (`project_proposal`) with `joined_at` = the template's `created_at`; this one read of `projects` lives in the migration, not in app code;
  3. second migration: `city_id` and `program_id` not null, drop the unique on `project_id`, make it nullable, add the place index.
- A template whose project has no center migrates with `center_id` null (D-82). It is listed by the dry run, not blocked.
- Command `report-templates:place-backfill {--dry-run}` prints: templates, with center, without center, proposals linked, templates with no proposal (must be 0; otherwise the migration stops before DDL).
- `ReportPlace::equals()` treats two null centers as **not** equal: an unset center never matches another (D-82), so nothing can be joined to it by accident.
- **Slice 2:** `ReportTemplatePrefiller::prefillForProposal()` works per place, never per project. A line is created for each library-linked target of the proposal whose place (`PlaceBridge::placeOfTarget`) equals the template's.
- In this task an approval **always creates its own template** at each place when the proposal has none there. It never joins an existing one: joining is MEAL's choice and arrives with Y-04. Until Y-04 ships, a second proposal at an occupied place therefore gets a second pending template. Say so in the handoff.
- `ConfirmReportTemplate` keeps activating the approved project: resolve it with `PlaceBridge::legacyProjectIdFor()` and call `ActivateProject` as today. Activation moving off projects is not this task.
- `ReportTemplatePolicy::manage` keeps its rule; where it reads the project for MEAL coverage, route that one read through `PlaceBridge` (D-85).
- The template tab on `projects/show` and `report-templates/index` show the same data as before; rows may now be two per place, each naming its proposals.
- `tests/Unit/WaveFourProjectsGuardTest.php`: scans the files this wave creates or lists (start with `app/Support/Reporting/**`, `ReportTemplatePrefiller`, `ReportTemplateReader`, `ReportTemplateQueue`, `app/Actions/ReportTemplates/**`) and fails when one names `App\Models\Project` outside `PlaceBridge`.
