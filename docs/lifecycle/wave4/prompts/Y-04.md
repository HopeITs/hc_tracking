## Goal
When a proposal is approved at a place that already has a template, **MEAL decides** how it is reported (D-77):

- **Join** the proposal to that template and pick which of its indicators are added. The center manager keeps entering **one** report.
- **New template** for the proposal. The center manager enters **two** reports that month.

Before this task an approval always creates its own template (Y-02). After it, an approval at an occupied place waits for MEAL's choice.

- **Slice 1 (Dev 1):** the pending-choice state, the two actions, events and notifications. **[contract]**
- **Slice 2 (Dev 2):** the choice on the "Templates to confirm" page and the template tab.

## [contract] (D-77, D-86)
Add to `contracts.md §12.4`:

> - **Placement choice (Y-04, D-77).** `report_template_placements`: `proposal_id` FK cascade, `city_id`, `program_id`, `center_id` null, `city_wide` boolean default false (the place, D-88), `status` (`TemplatePlacementStatus`: `pending`, `joined`, `created`), `report_template_id` FK null nullOnDelete (set when decided), `decided_at`, `decided_by` FK users null nullOnDelete, timestamps. Unique (`proposal_id`, `city_id`, `program_id`, `center_id`, `city_wide`). A place whose center is not set gets no placement choice: its template is created as before (D-82).
> - **Pre-fill** now branches per place of the approved proposal: no confirmed or pending template of **another** proposal there → create the template as before and write the placement as `created`; otherwise write a `pending` placement, create nothing, and notify MEAL (`report_template.placement_pending`).
> - `JoinReportTemplate::handle(Proposal $proposal, ReportTemplate $template, list<int> $planIndicatorIds, string $expectedStatus = 'pending'): ReportTemplate`: the template must sit at one of the proposal's places and the placement must be `pending`. Links the proposal (`proposal_report_template`), adds one **pending** line per chosen target (targets of this proposal at this place, library-linked, not already a line), marks the placement `joined`. Targets left out get no line and are listed on the template as "not reported".
> - `CreateReportTemplateForProposal::handle(Proposal $proposal, ReportPlace $place, string $expectedStatus = 'pending'): ReportTemplate`: creates the proposal's own template at the place exactly as the pre-fill does, marks the placement `created`.
> - Both run in one transaction under the placement lock, authorize `report-templates.manage` (the §12.4 "Who" rule), and are refused on a place whose center is not set (D-82).
> - A joined proposal's lines follow the usual path: `pending` until `ConfirmReportTemplate`; once confirmed they reach **draft** reports only through `RefreshMonthlyReportLines` (D-41). The template lives while any linked proposal is active; leaving a template is not offered (D-86).
> - **Overlapping lines (D-86).** An indicator required by more than one of the template's proposals is **one shared line**: one `monthly_report_lines` row per library indicator per month, with one share per covering target (§13.1 item 1). Joining never duplicates it: the new proposal's target gets its own `report_template_lines` row (unique per target, carrying its own window and fixed denominator) and becomes a **share** of the existing report line. When a proposal ends, only what that proposal alone required stops: its targets' template lines end at its last month (`effective_to`, set at pre-fill or join, or by `RetireReportTemplateLine`, month-exact), so from the month after the end its shares are no longer built; a report line that still has a share of an active proposal stays. A line required by the ended proposal alone is not built from the month after it ends.

Add to `§15.2`: key `report_template.placement_pending` (direct: the responsible MEAL officer of the place, else the MEAL Manager slot; importance as `report_template.pending`).

## Rules
- A place with a null center never offers Join (`ReportPlace::equals`). The page says "Set the center first" and links to the Y-01 editor.
- When several templates exist at the place, MEAL picks which one to join; each option names its proposals and its number of confirmed lines.
- Join pre-selects every eligible target; MEAL unticks what should not be reported. Zero selected is allowed only when the template already reports that library indicator for another proposal (the new proposal then shares the line): otherwise the action refuses with `report_templates.join_needs_one_line`.
- An indicator the template already reports gains a **share** for the new proposal's target, not a second line (§13.1 item 1). Show this in the picker: "already in this report · adds your target".
- The project of a proposal waiting on a placement stays `approved`, not `active`, exactly like one waiting for a confirmation. Joining does not activate it; confirming at least one of its lines does (`ConfirmReportTemplate`, unchanged).
- **Overlapping lines (D-86):** joining a proposal whose indicator is already on the template adds a share to the existing line, never a second line for that library indicator. When a proposal ends, a line stops only if no other active proposal of the template requires it; a line still required by another proposal keeps running, minus the ended proposal's share. Stopping is from the month after the end (`effective_to` = its last month; `RetireReportTemplateLine` never moves an earlier `effective_to` later).
- Leaving a template after joining is out of scope (D-86): no action, no button.
- Nothing is retroactive: submitted and validated reports keep what they were built with.
- **Slice 2:** "Templates to confirm" gains a third status button, **Choose a report** (pending placements), beside *New templates* and *Lines added*; disjoint, exhaustive, counts equal the list. A row offers two actions: **Add to an existing report** (opens the picker) and **Create a separate report** (confirm dialog that states the consequence: "The center will fill two reports each month").
- Both dialogs name the proposal and the place. The primary action is the one the meeting expects most often: Add to an existing report.
- Guard test: add `app/Actions/ReportTemplates/**` new files to `WaveFourProjectsGuardTest`.
