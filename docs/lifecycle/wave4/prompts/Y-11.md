## Goal
First step of Stage B (`wave4/README.md §2`). A location row (`proposal_locations`: one proposal × city × program) holds everything a project holds today: status, period, working days, owner and their acknowledgement, target beneficiaries, sectors, files, activity log. ## [contract] (D-92, D-93, D-94)
Add to `contracts.md §7`, under **`proposal_locations`**:

> **What the row carries (Y-11, D-93).** `slug` varchar unique null, `status` varchar(50) default `draft` indexed (`ProjectStatus` values; the enum keeps its name), `start_date` date null, `end_date` date null, `schedule_weekend` varchar(10) default `sat-sun`, `working_days` json null, `description` text null, `target_beneficiaries`, `target_men`, `target_women`, `target_boys`, `target_girls` unsigned int null. The row's owner is its `responsible_employee_id`; the owner's acknowledgement is an `assignments` row with `assignable_type = 'proposal_location'`, `field = 'responsible_employee_id'`. Sectors: `proposal_location_sector` (`proposal_location_id` FK cascade, `sector_id` FK restrict, unique pair). Files: `media.mediable_type = 'proposal_location'`. Morph key `proposal_location` is registered in `enforceMorphMap`.
>
> **Until Y-17 the row is a mirror.** `projects` stays the writer; `ProjectLocationMirror::sync(Project $project): void` copies status, period, calendar, targets, sectors and the owner's acknowledgement to every row that carries the project, in the writer's transaction. `target_beneficiaries` comes from `project_proposal.target_beneficiaries` of the row's own proposal, else the project's.
>
> **Successor (D-94).** `App\Support\Locations\ProjectSuccessor::rowFor(int $projectId, ?CarbonInterface $date = null): ?ProposalLocation`: the row carrying the project whose proposal period (`actual_date_begin` … `effectiveDateEnd()`, else planned dates) covers `$date`; when none or several cover it, or `$date` is null, the row of the most recent proposal (latest begin, then highest id). Null only when no row carries the project. `rowsFor(int $projectId): Collection`. Every Stage B backfill maps a project through this class and nothing else; Y-18 deletes it.

## Rules
- **Slice 1, migrations** (`AGENT.md §4`, additive first): add the columns nullable or defaulted → create `proposal_location_sector` → backfill → second migration: unique on `slug`.
- **Backfill, per row that carries a project:**
  - `status`: the project's status when the row's proposal is the project's most recent one; rows of **earlier** proposals of the same project get `closed` when that proposal's period has ended, else the project's status. Archived stays archived on every row.
  - `start_date` / `end_date`: the row's proposal period clipped to the project's dates; the project's dates when the proposal has none.
  - calendar, description, the five targets, sectors: copied to **every** row of the project (they describe the place, not a moment).
  - files and the owner's acknowledgement: **not copied**. A file goes to `ProjectSuccessor::rowFor($project, $file->created_at)`; the acknowledgement goes to the row of the most recent proposal, and earlier rows are written as acknowledged at the same time when the project was. (D-94: nothing is duplicated that has a date.)
  - `slug`: from the proposal's number, the city and the program, unique with a numeric suffix.
- **A project with no row** (2 locally: no proposal at all) is listed and blocks the second migration. It needs a proposal first (D-84), an internal-donor one when self-funded (D-87): that is a human step, never a row invented by the migration.
- A row with **no project yet** (waiting for its program, or before approval) keeps `status = draft` and null dates.
- Command `locations:backfill-from-projects {--dry-run}` prints: rows filled, rows per status, projects on several rows (ids), projects with no row (ids), files moved per row, sectors copied.
- **Slice 2, mirror.** One class, `ProjectLocationMirror`, called at the end of the transaction of: the ten actions in `app/Actions/Projects`, `ProjectPeriods::widen`, `ProposalLocationRows::attachProject` / `detachProject`, `SyncProjectSectors`, the assignment acknowledge / reject path (`Project::assignmentAcknowledged`), `SaveProjectFile` / `DeleteProjectFile` (new files are also attached to the successor row). No other class writes the mirrored columns before Y-17.
- `ProposalLocation` gains the readers the later tasks need, each a twin of the project's: `label()` (program · city · centers, "Field work" for a city-wide row), `isOpen()`, `isPaused()` (a center deactivated in HR), `ownerEmployeeId()`, `sectors()`, `media()`, `ownerAssignment()`, static `programIdFor(int $id)`, static `ownerEmployeeIdFor(int $id)`. Traits: `HasSlug`, `HasAssignments`; activity context unchanged (`activityParent()` stays the proposal).
- `User::ownedLocationIds(): list<int>`: rows the user's employee is responsible for, plus rows of programs they manage. Twin of `ownedProjectIds()`, cached the same way.
- Command `locations:verify-mirror`: compares every mirrored column, sector set and acknowledgement between each project and its rows; prints the differences; exit code 1 when any exists. It is the Start-state check of Y-12…Y-17.
- `MorphMapTest` covers `proposal_location`. `ProposalLocationFactory` gains states `approved()`, `active()`, `closed()` and fills the new columns.
- D-74 still holds: this task adds **no** new reader of `projects` outside the mirror, `ProjectSuccessor` and the backfill.
