# M-05 · Plain error messages instead of 500, and the role beside the name · S

ClickUp: https://app.clickup.com/t/123jdbau1qn

## Goal
- A failed action shows a short, clear message in the user's language instead of a bare 500 page.
- The user's role shows next to their name in the account menu.

## Start state

## Rules
- Do not swallow errors: every exception is still reported (`report()`/log). Only the response changes.
- Livewire requests (`X-Livewire`): a failed action returns a toast with a plain sentence ("That did not save. Try again, and tell IT if it keeps happening.") in EN and AR, never a stack trace; add a reference id the user can quote, written to the log with the exception.
- Normal page requests keep `errors/500`, with the same plain wording and the reference id. Local (`APP_DEBUG`) still shows details; production never does.
- Known recoverable cases found in Start state (stale record, deleted parent, missing relation) get their own specific messages at the source, not a generic handler.
- Role: show the user's primary role label beside the name in the top-bar menu and, if the sidebar shows the user, there. Use the translated role label; a user with several roles shows the highest one (state the rule in the plan). No new query per page: use the already loaded relation.

## Stop and escalate
A cause of 500 that hides data loss, or a role model that does not say which role is "main".

## Do not
Hide errors from the log, change the 403 audit, or show exception text to users.
