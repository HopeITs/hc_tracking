# M-01 Unified indicator form and MEAL logframe

[ClickUp task](https://app.clickup.com/t/123jdbau1qh)

## Entry points

- The Indicators directory and its Desk quick action open Form B through the quick form. Result and project deep links preselect their context.
- The standalone MEAL page and proposal Logical Framework tab mount the same Livewire table. Adding an indicator from either opens Form B pinned to the row.
- The Indicator Library uses Form B for standalone catalogue creation and editing.
- Proposal Targets still attaches existing entries through its picker. Its new-indicator button opens Form B with the proposal and library group preselected.
- The old Results route redirects to the MEAL logframe. The MEAL sidebar links directly to the new page.

## Permissions

The MEAL Manager slot holder with the MEAL role, General Manager, and Super Admin can add indicators under the default grants. Preserve these grants and evaluate each permission independently. Keep the existing MEAL Manager slot and bypass checks.

In a result context, `indicators.create` continues to authorize picking an existing entry and creating an indicator with a new name. The current flow already creates the corresponding library entry as part of the indicator write. Form B should keep that behavior scoped to the result. Standalone catalogue creation continues to require `indicator-library.create`. Catalogue edits require `indicator-library.update`. Instance edits require `indicators.update`.

## Stored fields

- An `Indicator` instance requires a result and a single name. Measure and frequency are required in the existing form and have defaults in storage. Project, unit, baseline, target, and library link can be absent. Keep Arabic as the stored instance name when attaching a library entry, consistent with the existing action. Display the linked entry in the current locale with the other language as fallback, then the instance name for legacy rows.
- A `LibraryIndicator` stores the Arabic name, optional English name, placement, measure, unit, and collection frequency. Arabic name, level reference, measure, collector, and frequency are required in Form B. Program is required for a non-institutional entry. Follow-up months are required only for follow-up frequency. The action generates the code. Baseline, target, and project belong to the instance.

## Implementation

The shared entry modal contains the bilingual name search, duplicate feedback, placement and measurement fields, and a collapsed More options section. A result-scoped save writes the new library entry and its attachment in one transaction. Linked indicator measurements and catalogue fields use their corresponding permissions. The row editor keeps project, baseline, and target, and supports legacy indicators that lack a library entry.

The same table renders levels, descriptions, localized indicators, baseline, target, means of verification, and assumptions and risks on both pages. Its reads eager-load indicator and project data. Add row below preselects the current row's level and parent and saves the new sibling immediately after it. Apply the migration that adds `results.logframe_position` before opening the updated logframe pages. Pre-existing results use their IDs as their initial order.
