## What changed
- `bootstrap/app.php`: an exception the handler reports (`shouldReport()`; so not 403/404/419/validation/auth) is answered with a plain response when `APP_DEBUG` is off: JSON `{message, reference}` plus header `X-Error-Reference` for Livewire / JSON requests, the `errors/500` page with the reference otherwise. `$exceptions->context()` writes the same `error_reference` into the log line. Reporting is untouched; the 403 audit callback is unchanged.
- `App\Support\ErrorReference::for(Throwable)`: one 8-character id per exception object (log and response agree).
- `resources/js/request-errors.js` (imported in `app.js`): `Livewire.interceptRequest`; a 5xx calls `preventDefault()` (no Livewire error dialog) and shows a Flux danger toast with the sentence and the reference; a network failure shows the sentence alone. Wording is read from `<body data-request-failed / data-request-reference>` in `layouts/app/sidebar.blade.php`.
- `errors/500` and `x-errors.page` show "Reference: …" when given one. New strings `errors.request_failed`, `errors.reference` (EN/AR).
- Role: `User::primaryRole()` (the active role while held, else the highest by `config('access-control.role_display_order')`, unlisted roles last by name; reads the loaded `roles` relation, no query), `Role::label()` (translated built-in name, stored name for custom roles), `lang/{en,ar}/roles.php` → `names.*`, shown as `<small data-user-role>` under the name in the account menu (`desk/top-bar.blade.php`).
