## 2026-10-13: pack v1 (replaces the per-task prompts of plan rev 9)

- Each prompt is flattened into one current body; the stacked "Revision N wins" blocks are gone.
- References to the missing `docs/superpowers/plans/…ar.md` plan and the `.docx` decision files are removed. `contracts.md` + `decisions.md` are now the source of truth.
- The phantom skills `laravel-security` and `database-migrations` are replaced by the real skills.
- Session rules move into `AGENT.md` (start-state ritual, TDD, stop conditions, the `handoffs/` files).
- Large tasks are split into slices of one session each (T04, T06, T09, T11, T12, T13, T16, T17A, T17B, T18, T19, T21, T22, T31, T32, T33).
- Prompts were written for T33 and T34 (the plan had none). T01 now means pack sign-off plus the CP1 contract stubs.
- T14, T24 and T25 move to `prompts/later/`.

## 2026-11-04: W-14 (D-65) department task scope by HR job level
- `contracts.md`: §10 gains `EmployeeProfile::isDepartmentManager(int $employeeId): bool` and the rule under it. No schema, no new permission, nothing stored locally. D-65 (29 Oct) replaces the 23 Oct `direct_manager_id` idea: a department manager is an employee whose current position's HR job level matches `config('access-control.department_manager_job_level')` (default «Department Manager – Grade 5»), compared on a normalised string (dash variants, spacing, case) against `job_levels.name_en` **or** `name_ar`, so the answer never depends on the interface language. `User::canSeeDepartmentTasks()` delegates to it and is the one gate of the desk Tasks panel's `department` scope and the `department-tasks` page (`TaskPolicy::viewDepartmentQueue`); administrator roles bypass it and `Managers`/GM qualify only when their job level matches. The `deliverables` desk panel, whose register is `department-tasks.index`, follows the same rule (developer instruction, 4 Nov) so the desk cannot show what the page refuses. `mine` and `team` are unchanged. W-14's prompt carried no `[contract]` section, so the §10 line was added with the task on the developer's instruction — Dev 1 to confirm the wording.
