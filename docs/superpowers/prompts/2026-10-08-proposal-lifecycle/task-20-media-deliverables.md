# Task 20 — Media deliverables (merged into Task 31)

> **المهمة:** مخرجات الإعلام ومواعيدها — **مدمجة في Task 31**، ولا يُشغَّل لها برومبت.
> **المطوّر:** — · **الفريق:** — · **الأيام:** — · **الجهد:** 0 (العمل كله ضمن Task 31) · **يعتمد على:** —
> **متى تستخدمه:** لا تستخدمه. استخدم بدلًا منه [`task-31-proposal-plan-department-tasks.md`](task-31-proposal-plan-department-tasks.md) (B3، الفريق B، الأيام 4–6).
> **طريقة الاستخدام:** لا يوجد برومبت لهذه المهمة. هذا الملف إشعار فقط، يبقى ليحافظ على ترقيم المهام وروابط الخطة.

**ما الذي تغيّر (المراجعة 2، 2026-10-08):** مخرجات الإعلام صارت **مهامًا رئيسية لقسم الإعلام داخل المقترح** منذ إنشائه (`tasks.kind = media_deliverable`، مسندة إلى القسم من HR عبر `tasks.department_id`)، بأنواعها (فيديو، صور، ملف، نص)، ومواعيدها الثلاثة (الطلب، الموعد النهائي، التسليم الفعلي)، ومسار التسليم والقبول والإعادة، وتنبيهاتها قبل الموعد وعند التأخر. كل ذلك في **Task 31**. صفحة **Media Workspace** استُبدلت بصفحة **Department Tasks** العامة لكل الأقسام.

**ما الذي لا يُبنى:** لا جدول `media_deliverables`، ولا صلاحيات `media-deliverables.*`، ولا نموذج أو سياسة أو Actions خاصة بمخرجات الإعلام، ولا صفحة **Media Workspace**. أي برومبت أو فرع قديم لهذه المهمة يُهمَل.

**لماذا:** توضيح الإدارة (2026-10-08) يجعل المهام الرئيسية لفريقي الإعلام والمالية جزءًا من المقترح منذ إنشائه ومسندة حسب القسم. وجدولان منفصلان للمهام يكرران منطق الرؤية والتنبيهات والملفات. لذلك تُوسَّع `tasks` القائمة بدل إنشاء جدول جديد (انظر `### Task 20` و`### Task 31` في `docs/superpowers/plans/2026-10-08-proposal-lifecycle-correction.ar.md`).

**أثره على المهام الأخرى:** Task 21 تستعمل أحداث `department_task.*` (لا `media_deliverable.*`) في كتالوج الإشعارات والملخص الشهري؛ Task 26 تكتب جولة **Department Tasks** بدل **Media Workspace**؛ Task 10 تنسخ مهام الأقسام بلا تسليمات عند التجديد.
