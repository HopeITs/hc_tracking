02What the website is, exactly

An internal operations platform for Christian Hope Center that tracks the full life of humanitarian programme work, from strategy down to individual tasks, alongside the money that funds it.

Delivery chain

  • Strategies → Programs → Annual plans → Projects
  • Milestones and Tasks (with Gantt, dependencies, baselines)
  • Results, Indicators, Targets, Indicator progress
  • Reports with draft → review → approval flow
  • Risks, Calendar, Timeline, Executive summary

Funding chain

  • Proposals and their pipeline phases
  • Donors and Funding agreements
  • Tranches (instalments) and Transfers tracking
  • Bank accounts with per-account money roll-ups
  • Donor reports

How it works underneath

  • Sign-in: staff use their HR database password (hr_db, read-only). Managers, finance and admins must enable two-factor (TOTP, email codes or passkeys).
  • Session safety: each request re-checks HR (cached 60 s). If HR deactivates a person or changes their password, every open session ends.
  • Live updates: notifications pushed over private websocket channels (Reverb / Pusher), with digests and alert scanners on a schedule.
  • Stack: PHP 8.5, Laravel 13, Livewire 4 single-file pages, Flux UI, Tailwind 4, Vite, MySQL, Spatie Permission; served by Apache.

Every page will look fast at this size. The real question is what happens at 10k–100k rows.

Many users

  • Cache, sessions, rate-limit counters and the queue all live in MySQL, so every request writes to the database.
  • Per-request HR check (cached 60 s per user) and HR program sync (once a minute, during a visitor's request) tie page speed to the HR database.
  • Realistic today: dozens of people at once. For hundreds: Redis plus a CDN first.

Much data

  • whereYear('scheduled_date', …) and year(coalesce(…)) = ? wrap the column, so MySQL cannot use its index and scans the whole table (executive summary, finance registers).
  • Totals built in PHP after ->get() on whole result sets: calendar (18 loads), dashboard (12), admin users (12), proposal page (10), executive summary (8).
  • 35 paginated lists: good. The risk is in dashboards and summaries, not in lists.

High 5

02
No CDN, WAF or DDoS protection
Where
Infrastructure: Apache on public IP 195.42.143.64.
Risk
A modest flood takes the site offline; the origin IP can be hit directly.
Fix
Put Cloudflare in front; set TRUSTED_PROXIES=cloudflare and TRUSTED_PROXIES_REQUIRED=true (already supported in code); firewall the server to Cloudflare ranges; fill TURNSTILE_SITE_KEY/TURNSTILE_SECRET_KEY.
Effort
Half a day.
03
Cache, sessions, rate limits and queue all on MySQL
Where
.env: CACHE_STORE, SESSION_DRIVER, QUEUE_CONNECTION.
Risk
Each request writes to the database; under load or attack the database is the first thing to fall over.
Fix
Move cache, sessions and rate limiting to Redis; run a real queue worker.
Effort
1 day including server setup.
04
Queries that will slow down as data grows
Where
executive-summary/⚡index, dashboard/⚡index, calendar/⚡index, finance registers.
Risk
Full table scans and large PHP memory use; summary pages get seconds-slow at tens of thousands of rows.
Fix
Replace whereYear()/YEAR(col) with whereBetween(col, [start, end]); compute sums and counts in SQL; add composite indexes on date + status columns; seed ≈100k rows and measure.
Effort
2–3 days.
05
Oversized page components
Where
proposals/⚡show 3,243 lines; calendar 2,270; indicators 2,211; projects/⚡index 1,933; 24 pages over 750.
Risk
Hard to review, easy to introduce bugs, heavier Livewire state on every interaction.
Fix
Split into child components or islands; move writes to Action classes; move queries to model scopes.
Effort
Ongoing; start with the top five.
06
HSTS lasts only one day
Where
HSTS_MAX_AGE=86400.
Risk
Browsers forget to force HTTPS after a day, leaving a downgrade window on hostile networks.
Fix
Set 31536000 and add includeSubDomains once all subdomains are HTTPS.
Effort
Minutes.

10Concept, originality & mission fit

  • Innovative workflow?
    Yes. It joins delivery (logframe → targets → reports) with funding (proposals → agreements → tranches → transfers) in one system. Most NGOs run these in separate spreadsheets.
  • Not a template / AI-generated CRM?
    Yes in structure: HR-linked identity, password-fingerprint session kill, Gantt baselines and dependencies, per-account money roll-ups and bilingual AR/EN are bespoke. Visual originality will be judged in Round 2.
  • Delivers the mission?
    Yes for tracking programme delivery and donor money in one place with audit trails and alerts.
