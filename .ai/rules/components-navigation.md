# Components Navigation

## Desktop sidebar collapse toggle: dispatch flux-sidebar-toggle, don't hand-roll ui-sidebar-toggle
The first attempt at a desktop collapse-arrow toggle hand-replicated Flux's `<ui-sidebar-toggle data-flux-sidebar-collapse>` markup with a negative-offset absolute position — it didn't render reliably and didn't visibly toggle. Root cause understood by reading `vendor/livewire/flux/dist/flux-lite.min.js` (the free-tier bundle actually served, confirmed via `AssetManager::fluxMinJs()` since `livewire/flux-pro` isn't installed): the sidebar's collapse/expand state machine listens for a plain `document.addEventListener('flux-sidebar-toggle', ...)` DOM CustomEvent and picks mobile-drawer vs desktop-collapse automatically based on current viewport (`this.state.viewportDesktop`) — no custom-element wiring needed. The fix: a plain `x-data` element with `x-on:click="$dispatch('flux-sidebar-toggle')"`, positioned inline in the sidebar header (not negative-offset/absolute, to avoid any ancestor-overflow clipping) — the exact same event this file's own `x-on:keydown.escape.window` mobile-close handler already dispatches. Reuse this event for any future sidebar open/close control; don't reintroduce the `<ui-sidebar-toggle>`/`data-flux-sidebar-collapse` markup by hand.

## Desktop sidebar collapse: bracket-syntax width override + force groups visible
Two more things needed beyond dispatching `flux-sidebar-toggle` (see the earlier rule in this file) to make the desktop icon-only collapse actually render: (1) Flux's own `data-flux-sidebar-collapsed-desktop:w-14` utility on `<flux:sidebar>` (sidebar/index.blade.php) never made it into our compiled CSS — Tailwind's bare `data-{long-hyphenated-name}:` shorthand didn't generate a rule here even though the "in-" ancestor form of the exact same attribute compiled fine. Worked around by using explicit bracket syntax instead: `data-[flux-sidebar-collapsed-desktop]:lg:w-[4.5rem]! data-[flux-sidebar-collapsed-desktop]:px-2!` on the sidebar's own class list — confirmed via an isolated fixture that this computes to 72px correctly. (2) Flux's `<flux:sidebar.group>` (group.blade.php) hides the ENTIRE group — icons included, not just the heading — when collapsed (`in-data-flux-sidebar-collapsed-desktop:hidden` on the group root) unless the group is `expandable` (a hover-dropdown variant we don't use). Since every group here has a heading and none are `expandable`, collapsing made the whole nav disappear. Fixed by adding `in-data-flux-sidebar-collapsed-desktop:flex!` (keep the group itself visible) and `in-data-flux-sidebar-collapsed-desktop:[&>div:first-child]:hidden!` (hide only the heading wrapper) to `$navigationGroupClasses`. Verified end-to-end (click → attribute set → 72px width → icon-only rows with the active item as a solid red square, matching the reference) via a page served through `public/build`'s actual compiled assets — this machine also has a stale/orphaned local Vite dev server (`public/hot` pointing at `http://[::1]:5173`) that serves outdated CSS; don't trust visual checks against it, verify against a fresh `npm run build` instead.

## Desktop collapse toggle floats on the sidebar edge, not inline in the header
Supersedes the "positioned inline in the header" version of the earlier rule in this file. The toggle must visually straddle the sidebar/content border (absolute, `end-[-14px] top-[1.35rem]`, `hidden lg:flex`) to match the reference design — placing it inline inside `<flux:sidebar.header>` was a needless retreat from an earlier (wrongly diagnosed) visibility bug; the real bugs were the event mechanism and the missing collapsed-width CSS, both already fixed, not overflow clipping. Because of this, `<flux:sidebar>` must NOT get `overflow-x-hidden` (or any overflow-hidden) on its root — that would clip this negative-offset child. Verified via bounding-rect checks that the button straddles the border symmetrically in both expanded (259px sidebar) and collapsed (72px) states, in a page served through `public/build`'s real compiled assets (see this file's other rule for why that matters on this machine).

## Desktop collapse toggle must stay fully inside the sidebar's own box
Supersedes the "floats on the sidebar edge with a negative offset" version of the earlier rule in this file — that positioning (`end-[-14px]`) got silently clipped in production. Root cause, confirmed with `document.elementFromPoint()` at the button's own edges: `<flux:sidebar sticky>` makes Flux auto-add `overflow-y-auto` to the sidebar root (see `sidebar/index.blade.php`'s `if ($sticky)` block) — and per the CSS2.1 rule, setting overflow-y to anything but visible forces the browser's *computed* overflow-x to `auto` too, even though we never wrote `overflow-x` ourselves. Raising the sidebar's own z-index above the header's did not help (confirmed the header, not overflow, was not the cause once this was isolated) — the overflowing half of the button was genuinely being clipped by the sidebar's own box, not painted-over by a sibling. Fix: keep the toggle fully within the sidebar's padding box (`end-1`, not a negative offset) so it can never depend on overflow behavior at all. It no longer visually straddles the border pixel-for-pixel like the reference screenshot, but it is guaranteed visible in every state — verified with `elementFromPoint` at the button's left/center/right edges in expanded (259px), collapsed (72px), and RTL, all resolving to the button itself.
